# LogDock 에이전트 시제품

측정 M7(에이전트의 CPU·메모리와 회전 시나리오)에 쓰려고 만드는 Go 시제품이다. 제품 구현 승인이 아니며, 범위와 진행 기록은 `docs/agent`의 agent-prototype 작업 파일에 있다. 지키는 규약은 [API 계약 초안](../docs/specs/api-contract-v0.1.md) 2절, 수집 정책은 [수집·에이전트 명세](../docs/specs/collection-agent-v0.1.md)다.

## 실행 환경

- Go 1.27 계열([버전 고정](../docs/research/d17-tech-evidence-2026-11-03.md#8-버전-고정)). 표준 라이브러리만 쓴다.
- 대상은 Linux다. 지금 시험은 개발 PC(macOS)에서 돌렸으므로 Linux 전용 동작(journald 등)과 자원 측정은 Linux에서 다시 확인한다.
- journald 연결은 PATH의 `journalctl`을 띄운다. 실행 계정은 시스템 journal을 읽을 수 있어야 한다(root나 `systemd-journal` 그룹). journald 시험은 가짜 journal과 export 형식 합성 데이터로만 돌렸다.

## 시험

저장소 루트에서 실행한다.

```sh
go -C agent test -race ./...
```

## 구성

| 패키지 | 하는 일 |
| --- | --- |
| `internal/tail` | 로그 파일을 stat 확인으로 따라 읽는다. `Follower`는 경로 하나, `Watcher`는 폴더 하나에서 파일명 규칙에 맞는 파일 모두를 따른다. 장치·inode로 파일을 구분해 이름 바꾸기 회전, copytruncate, 지워진 파일, 재시작 뒤 이어 읽기를 처리하고, 빠뜨린 구간은 경계로 알린다. `Watcher`는 다 읽고 조용한 파일을 닫아 두었다가 바뀌면 다시 열고, 처음 보는 파일의 시작 위치를 D02대로 가른다(계약 2.3절) |
| `internal/assemble` | 읽은 바이트를 이벤트·거부·경계 기록으로 묶는다. 한 줄·JSON·여러 줄 형식, 최초 연결의 시작 경계(D02), 이벤트 크기 상한(D03), 파일이 바뀌면 이벤트를 끊는 규칙(AG-08)을 지킨다 |
| `internal/queue` | 연결 하나·세대 하나의 디스크 대기. 기록에 순번을 붙여 세그먼트 파일에 쓰고 디스크에 확정한다. 기록마다 길이와 CRC를 달아 쓰다 멈춘 끝을 잘라 내고, 수신 확인된 순번까지 지운다. 형식 버전이 다르거나 확인된 기록이 사라졌으면 지우지 않고 멈춘다. 파일명 규칙 연결은 파일별 읽기 위치 스냅샷을 대기 폴더에 함께 두고, 스냅샷 뒤 기록은 수신 확인돼도 지우지 않는다 |
| `internal/record` | 대기에 저장하는 기록과 수신 서버로 보내는 기록(계약 2.3절)의 형식. 잘못된 UTF-8은 base64와 `encoding_error`로, 모르는 유실량은 0이 아닌 미확인으로 보낸다 |
| `internal/collect` | 연결 하나의 읽기 흐름. 읽기 위치를 기록마다 대기에 함께 확정해, 재시작하면 마지막으로 확정된 기록 다음부터 다시 읽는다(AG-12). 대기가 차면 읽기만 멈추고(D01, 수신 확인되지 않은 바이트로 판단), 디스크에 쓰지 못하면 기록을 버리지 않고 멈추며(D05), 재시작 위치를 잃었으면 처음부터 시작하지 않고 복구 보류로 둔다(D02). 파일명 규칙(`PatternReader`)은 파일마다 따로 이벤트를 묶고(AG-08), 조용한 파일의 위치가 든 기록이 수신 확인 뒤 지워질 수 있어 모든 파일의 위치를 스냅샷으로 함께 확정한다. 재시작하면 스냅샷과 그 뒤 기록으로 위치를 되살린다. journald(`JournalReader`)는 시작 전에 journal 읽기 권한을 확인하고, 대기가 차면 journalctl을 끝냈다가 확정한 위치에서 다시 띄우며, 저장한 항목이 지워졌으면 복구 보류로 둔다 |
| `internal/journal` | journald 입력. `journalctl --output=export`를 하위 프로세스로 읽어 항목으로 만들고, Docker·systemd가 나눈 긴 줄의 조각을 잇고, 형식대로 이벤트로 묶는다. 커서 문자열은 비교할 수 없어 항목 식별값(부팅 ID·두 시각·필드 요약)으로 재시작 위치를 확인한다. journald 속도 제한 알림은 원본 소실 경계(`source_dropped`)로 낸다 |
| `internal/journaltest` | 시험용 가짜 journal. 조건·`--cursor`·`--lines=1`·`--follow`와 보관 한도로 지워진 항목, journalctl 비정상 종료를 흉내 낸다 |
| `internal/ship` | 대기의 기록을 gzip JSON 묶음으로 HTTPS 수신 서버에 보낸다. 저장 끝 응답(`acked_through`)까지만 대기에서 지우고, 계약 2.4절 표대로 재시도(지수 백오프와 지터, `Retry-After`)·보류(키·보관·중복 대상 등)·묶음 나누기(413)를 한다. 세대 번호는 수신 서버에서 받고, 설정 버전이 바뀌는 곳에서 묶음을 끊는다. 키 보류 중 키 파일이 바뀌면 같은 순번부터 바로 다시 보낸다 |
| `internal/config` | 에이전트 전체 설정과 연결 설정(TOML)을 읽고 계약 2.8절 입력 규칙을 검사한다. 쓰는 TOML 문법만 엄격히 읽고 나머지·모르는 키는 오류로 알린다. 키 파일은 실행 계정만 읽을 수 있어야 한다(SC-03). 인증서 검증을 끄는 설정은 없다 |
| `internal/rules` | 수집 대상과 형식의 입력 규칙(계약 2.8절). 설정 파일 검사와 조회·관리 API의 등록·사전 검사가 같은 함수를 쓰도록 따로 두었고, 문제마다 사유 코드를 준다. 네트워크·파일 패키지에 기대지 않는다 |
| `cmd/logdock-rules` | `internal/rules`를 WebAssembly(`GOOS=js GOARCH=wasm`)로 내보낸다. API가 `npm run build:wasm`으로 빌드해 불러 쓴다. 다른 환경에서 빌드하면 안내만 하고 끝난다 |
| `internal/status` | 연결마다 상태 보고(계약 2.7절)를 정기적으로, 상태가 바뀌면 빈도 제한 안에서 바로 보낸다. 대기에 쌓지 않는 최선 노력 전송이고, 모르는 값은 null로 보낸다 |
| `internal/agent` | 실행기. 연결마다 읽기·보내기·상태 보고를 따로 돌려 읽기가 보내기를 기다리지 않는다. 잘못된 연결은 건너뛰고 나머지는 돌리며, 중지 신호에는 남은 전송을 기다리지 않고 바로 멈춘다(Q05-02). 인스턴스 ID·설정 적용 시각·로컬 상태 파일을 상태 폴더에 둔다 |
| `internal/ingesttest` | 시험용 가짜 수신 서버(TLS). 묶음 수신·세대 발급·순번 중복 판정·상태 보고를 흉내 내고 장애(응답 잃기, 키 폐기, 보관, 크기 초과, 혼잡, 순번 기록 잃기)를 끼워 넣는다. 실제 수신 서버가 아니다 |
| `cmd/logdock-agent` | 실행 파일. `run`(수집), `check`(설정·키 권한·대상을 검사만 하고 보내지 않음. 파일명 규칙은 지금 맞는 파일 수와 압축 파일이 섞였는지, journald는 journalctl·읽기 권한과 journal이 메모리에만 보관되는지 알림), `status`(연결별 읽기·보내기·대기 상태), `version` |

## 실행

설정 예시는 [examples](examples/)에 있다(합성 값). `c_example1`은 파일 하나, `c_example2`는 파일명 규칙, `c_example3`은 journald 컨테이너 연결이다. 연결 설정은 중앙이 만들어 내려주고, 키 파일은 같은 폴더에 `<connection_id>.key`로 두고 실행 계정만 읽게 한다.

```sh
go -C agent build -o logdock-agent ./cmd/logdock-agent
./agent/logdock-agent check -config /etc/logdock-agent/agent.toml
./agent/logdock-agent run -config /etc/logdock-agent/agent.toml
```

다음은 journald를 실제 Linux journal에서 확인하는 것, Q06 다시 수집 명령, 자원 강제 제한(systemd)이다.

## 시제품 기본값

Poll 한 번 읽기 1MiB(파일명 규칙은 모든 파일 합계), 회전 유예 2초, 지워진 파일 보유 5분, 이벤트 상한 1MiB, 여러 줄 이벤트 대기 5초, 대기 세그먼트 4MiB, 대기 한도 256MiB(한도에서 멈춘 뒤 90% 아래로 내려가면 재개), 묶음 1MiB·1,000건, 요청 제한 시간 30초, 재시도 1초~1분(±20%), 보류 중 재확인 1분, 전송 창 1, 읽기 주기 250ms, 상태 보고 30초(상태가 바뀌면 1초 간격 안에서 바로)는 측정 전에 둔 임시 값이다. 파일명 규칙은 폴더 탐색 1초, 조용한 파일 닫기 1분, 동시에 여는 파일 32개, 따라가는 파일 1,024개, 위치 스냅샷 1초 간격이다. journald는 나뉜 메시지의 다음 조각 대기 5초, 재시작 위치 뒤에 기억하는 처리한 항목 256개, 한 번에 처리하는 항목 4,096개·본문 1MiB, 읽어 두는 항목 1,024개, journalctl 다시 띄우기 1초~30초다. 대기는 한 번 읽은 만큼 한도를 넘을 수 있다. 제품 수치는 측정(M7)과 Q15 협의 뒤 정한다.

## 알려진 한계

- 파일 하나: 멈춘 사이 회전이 두 번 이상 일어나면 중간 파일을 알 수 없어 순서 미확인으로만 표시한다. 줄바꿈 없이 멈춘 마지막 줄은 파일이 바뀔 때까지 붙잡는다.
- 파일명 규칙: copytruncate로 만든 복사본이 규칙에 들면 새 파일로 보고 처음부터 읽어 중복된다. 규칙은 회전된 파일과 겹치지 않게 잡는다(`check`가 압축 파일이 섞이면 알린다).
- 파일명 규칙: 닫아 둔 조용한 파일에 마지막으로 쓰인 줄이 다음 탐색(1초) 전에 파일과 함께 지워지면 잃고 알리지 못한다. 규칙 밖으로 나가 다 읽고 놓은 파일(조용한 지 1분 뒤)이 다시 규칙에 들어오면 새 파일로 처음부터 읽는다.
- 파일명 규칙: 동시에 쓰이는 파일이 동시에 여는 파일 수보다 많으면 나머지는 기다린다(`file_limit`). 조용한 파일을 닫아 자리를 내므로 날짜별 파일처럼 하나씩만 쓰이는 경우는 해당하지 않는다.
- journald: 실제 journalctl·journald·Docker와 돌려 보지 않았다. 연결마다 journalctl 프로세스가 하나씩 돈다(비용은 M7에서 잰다).
- journald: 저장한 항목이 지워졌는지는 다시 띄울 때만 확인한다. 따라 읽는 동안 journal 파일이 지워질 때의 동작은 Linux에서 확인한다.
- journald: 컨테이너 로그의 속도 제한 알림은 Docker 데몬 unit 전체의 수라 이 컨테이너의 몫을 모른다. 조각 ID가 없는 예전 Docker 형식은 시작 경계 바로 뒤의 마지막 조각을 보통 줄과 가르지 못할 수 있다.
- journald: 여러 줄 형식은 stdout과 stderr를 journal 순서대로 한 흐름으로 묶는다. 두 출력이 같은 순간에 섞여 쓰이면 이벤트가 섞일 수 있다.

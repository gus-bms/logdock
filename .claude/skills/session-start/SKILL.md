# 세션 시작 보고

대상: `$ARGUMENTS` (비어 있으면 작업 폴더에서 고른다)

세션이 바뀌어도 작업이 이어지게 하는 것이 목적이다. 사용자는 지난 상황을 다시 설명하지 않아도 되고, 에이전트는 다른 세션이 하던 일을 모른 채 새 일을 벌이거나 같은 일을 두 번 하지 않는다. 폴더와 작업 파일의 규칙은 [docs/agent/README.md](../../../docs/agent/README.md)가 기준이며 이 파일에 복사하지 않는다.

## 1. 읽기

- `AGENTS.md`. 루트 `CLAUDE.md`로 이미 읽혔으면 다시 읽지 않는다.
- `docs/agent/README.md`의 `현재 단계`와 `작업 규칙`.
- 작업 보드. SessionStart hook이 붙여 준 보드가 있으면 그것을 쓰고, 없으면 아래 명령을 그대로 단독으로 실행한다. 사전 승인된 형태라 다른 명령을 붙이면 권한 확인이 뜬다.

  ```sh
  sh .claude/skills/session-start/scripts/board.sh
  ```

- `progress/`의 작업 파일은 진행 기록과 다음 할 일까지 모두 읽는다. 이어갈 맥락이 거기 있다. `todo/`와 `hold/`는 보드의 머리말로 고르고, 추천할 작업만 본문을 읽는다. `done/`은 선행 작업이 끝났는지 확인할 때 말고는 열지 않는다.
- `git status -sb`로 브랜치, 커밋하지 않은 변경, 원격과의 차이를 본다. `docs/agent/`가 없거나 브랜치가 원본보다 뒤처진 작업 폴더라면 문서가 최신이 아닐 수 있으므로 보고에 적는다.

## 2. 고르기

- **진행 중인 작업이 있으면 이어가기를 먼저 권한다.** 다른 에이전트가 지금 맡고 있을 수 있으니 담당과 마지막 갱신을 함께 보여 준다. 마지막 갱신이 오래됐다는 이유만으로 버려진 작업이라고 단정하지 않는다.
- **없으면 `todo/`에서 고른다.** `선행`이 모두 `done/`에 있는 작업 가운데 우선순위 숫자가 가장 작은 것을 추천한다. 같으면 다른 작업의 `선행`에 이름이 올라 있는 작업, 즉 다른 일을 막고 있는 작업을 먼저 둔다.
- **`hold/`는 풀리는 조건만 본다.** 사용자가 풀 수 있는 조건(서버 준비, 구현 시작 요청 등)은 확인할 것으로 적고, 다른 작업이 끝나야 풀리는 것은 적지 않는다.
- 추천한 작업이 사용자 판단이 필요한 기획 안건이면 `plan-decide`로 진행한다고 적는다.

## 3. 보고

새 세션의 첫 보고는 아래 형식을 따른다. 내용이 없는 줄은 뺀다. 예시의 작업 이름과 날짜는 형식을 보여 주기 위한 것이다.

```text
세션 시작 보고 (docs/agent 기준)
진행 중: wireframe-search — 담당 Claude Code 2026-11-05, 다음 할 일: UI-03 상태 그리기
추천 시작: wireframe-common — 다른 와이어프레임 묶음 4개의 선행 작업이다
다른 후보: api-contract-draft, version-pinning
확인할 보류: measurement-m1-m8 — 16GB 중앙 서버가 준비됐으면 알려 주세요
저장소: docs/planning-wrapup, 커밋하지 않은 변경 없음
```

마지막에 추천한 작업으로 시작할지 한 줄로 묻고 답을 기다린다. 승인 전에는 작업 파일을 옮기거나 고치지 않는다. 사용자가 다른 작업을 고르면 그 작업으로 시작한다.

첫 메시지가 구체적인 요청이면 보고를 두세 줄(진행 중인 작업과 겹치는지, 관련된 보류)로 줄이고 그 요청을 진행한다. 보드에 없는 큰 작업이면 작업 파일을 만들어 진행 상황을 남기고, 질문에 답하거나 몇 줄 고치는 정도의 일은 만들지 않는다.

## 4. 시작한 뒤

작업을 잡고, 진행 기록을 남기고, 끝내거나 멈추는 방법은 `docs/agent/README.md`의 `작업 규칙`을 따른다. 커밋은 사용자가 요청할 때만 하고, 커밋하지 않은 변경이 남으면 마지막 보고에 적는다.

# LogDock 관리와 운영 상세 기획 v0.1

최종 갱신: 2026-11-02. 상태: 최신 합의에 맞춰 통합한 검토 초안. 한 운영팀용 자체 설치형의 F01/F02/F06/F08/F09/F10과 중앙 전달·설치·복구·출시를 다룬다. 기존 [수집·에이전트 명세](collection-agent-v0.1.md)의 합의·자원 보호·AT-01~AT-18을 유지한다.

사용자 합의는 [결정 기록](../decisions.md), 남은 선택은 [협의 목록 Q01~Q16](../planning/user-decisions-v0.1.md), 범위·완료 기준은 [잔여 기획](../planning/remaining-plan-v0.1.md)을 따른다. D01~D05·D06 중복 방지·Q04 중앙 프로그램 재시작 보존·D09·서비스 분류와 Q01의 초기 포함/후속 구분은 합의된 전제로 유지한다. Q01에서 오류 알림은 첫 출시 포함으로 합의했으며 건수 기준으로 시작하고 평소 대비 급증은 후속으로 합의했다. 초기 채널은 이메일로 합의했으며 조건 수치·메일 연결 설정·수신 주소 검증/한도·세부 정책은 미정이다. Q01에서 연결/수집·상태/원인 확인·기본 접근/키 관리·주요 관리 이력·기본 보존/사용량/용량 관리와 제품 완료 기준의 초기 범위도 합의했다. 역할 분리·보존 상세·수명·구체 지원/보장/수치는 검토안이다. 문서 통합은 기능 채택이나 실제 운영 설정·DB 작업·배포를 실행하는 지시가 아니다.

서비스는 로그 분류·검색/필터·집계 기준이다. 아래 source scope·역할 표는 Q10의 접근 통제 검토안이며 서비스마다 tenant나 권한 경계를 만드는 요구가 아니다. 민감정보 처리는 앱 책임이며 LogDock은 앱 출력 본문을 마스킹·민감 내용에 따른 제외·격리 없이 중앙화한다.

외부 자료의 확인일은 원본 초안의 조사 기록이다. 초안 통합 때는 외부 자료를 재검증하지 않았다. 이후 2026-11-01 Q05·Q07·Q10 요청으로 [공식 자료 15건](../research/q05-q07-q10-evidence-2026-11-01.md)을 확인하고 [전용 기획안](../planning/q05-q07-q10-plan-v0.1.md)을 작성했다. 조사 자체는 정책 채택·기술 선정·실행 검증이 아니며 이후 사용자가 선택한 범위는 결정표와 각 절의 상태를 따른다.

## 1 F01 출처와 수집원 수명

Q07-08 합의: 사람이 입력하는 운영/개발 환경 태그와 서버 표시명은 선택이다. 실제 서버/agent/입력의 연결 식별 및 현재 허용 등록 확인과 구분하며 서비스/입력 종류/대상의 기존 필수 흐름을 유지한다. 미입력/관측 불가를 구분하고 가짜 값으로 채우지 않는다. 표시 fallback·instance 판정·필드/schema는 후속 설계이며 선택 메타데이터를 권한/동일 서버 판정 근거로 사용하지 않는다.

Q08-06·Q08-07 합의(2026-11-02): 수집 연결 등록에 선택 입력 `로그 시간대`와 `추출 규칙`을 둔다. 미입력만으로 등록을 막지 않는다. 시간대를 입력하지 않으면 에이전트 서버 시간대로 해석해 `시간대 추정`을 표시하고, 규칙이 없으면 내장 패턴으로 읽으며 실패는 미확인으로 남긴다. 잘못된 규칙은 등록 때 오류로 알리고 규칙 변경은 이후 로그에만 적용한다. 규칙 문법과 실행 위치는 후속 설계다.

Q07-05 합의: 다른 서버나 전혀 다른 로그를 수집하게 되면 새 연결로 등록해 기존 대상/이력과 구분한다. 별칭 수정·정상 rotation·재시작은 기존 연결/복구를 유지한다. 기존 대기는 원래 연결/식별로 보존·처리하고 새 등록은 D02 시작 기준을 따른다. 동일 입력의 설정 수정/판정·종료/새 등록·기존 서버 대기/제거 절차와 agent 관계/키 교체 정합성은 후속 설계이며 자동 이전·대기 복사·무중단 보장은 추가하지 않는다.

서비스 이름은 표시용 별칭이며 실제 연결/인증 식별과 구분한다. 사용자가 서버와 agent의 연결을 강조함에 따라 이름 중복 금지 질문은 필수 협의에서 제외하고 Q07-02/T02/T05의 설계로 인계했다. 동일 서버의 다른 입력은 별도 수집 연결일 수 있으며 한 agent의 여러 서비스 수집을 유지한다. 별칭 중복 허용/차단이나 서버 판별 방식·agent 수를 이 정리로 채택하지 않는다. 키 범위/개수는 Q10-07의 연결별 키·평상시 1개/교체 중 2개 합의를 따른다. Q07-06에서 같은 서버의 같은 로그 연결이 이미 등록됐다고 확인되면 기존 연결을 안내하고 추가 등록을 막는 원칙을 합의했다. 같은 서버의 다른 입력과 불확실한 겹침은 구분하고 실제 판정/검사 시점·동시 등록/복제는 후속 설계다. 원격 파일 탐색을 새로 추가하거나 기존 연결/데이터를 자동 병합·삭제하지 않는다.

Q07-01에서 수집 연결 등록 화면의 기존 서비스 선택/새 분류 이름 등록을 합의했다. 등록·이름·입력/서버 교체·중복·보관/재활성/삭제·메타데이터의 선택 기록과 남은 추천/대안은 [Q07-01~08](../planning/q05-q07-q10-plan-v0.1.md#q07)에 모았다. Q07-04 직접 분류 이동은 후속으로 유예했다. 초기에는 기존 연결 종료/잔여 처리 후 새 분류에 새 연결로 등록하며 D02 수집 공백 가능성과 기존 로그/대기 원래 분류를 유지한다. 종료/중복 차단·미확인 정합성은 후속 설계다. Q07-07에서 보관/재활성화 초기 제공·연결 등록 완전 삭제 후속도 합의했다. 보관은 운영자의 명시적 사용 중단 선택이며 무로그·agent 단절만으로 자동 판정하지 않는다. 관리 상태와 실제 agent 관측 상태를 분리하며 새 등록의 D02 시작 경계·누락 가능성과 기존 대기의 원래 출처를 함께 다룬다. 아래 객체/수명 표를 승인된 schema나 확정 수명으로 읽지 않는다.

| 객체 | 책임과 관계 | 생성·변경·종료 제안 |
| --- | --- | --- |
| service | 앱의 논리 식별과 분류·조회 기준. 여러 environment/instance/source 연결 | 수집 연결의 서비스 지정·등록 확정 후 키 발급, 중앙 등록정보로 서비스 판별. 미분류 보관/재분류는 제거. 키의 권한은 Q10-07의 해당 등록 연결에 한정. ID/UI·등록/입력 묶음·이름/수명은 후속 설계/검토. tenant/권한 경계가 아님 |
| environment | 운영/검증 등 배포 환경의 논리 식별 | 이름을 권한 근거로 쓰지 않음. 환경을 바꾸면 새 이벤트 적용 경계 기록 |
| instance | 호스트·컨테이너·실행 단위의 발생 식별 | 재생성 시 새 identity. hostname 재사용만으로 같은 실행으로 합치지 않음 |
| source | 입력·parser/이벤트 경계 규칙·전송 자격·진단의 관리 단위 후보 | 한 service=한 파일을 가정하지 않음. 여러 instance 연결은 명시적 정책으로 허용 |
| agent | 제한된 자원으로 source를 읽는 실행 주체 | agent/instance/source 상태를 구별. 같은 상태 디렉터리 이중 실행 충돌 처리 |
| 설정 version | 입력 경로·출처 매핑·규칙·한도·destination 참조 | 검증→적용→관측 version 구별. secret 원문을 저장/감사 이력에 넣지 않음 |

source 수명은 `작성 → 연결 대기 → 사용 중 → 신규 수집 중단 → 보관 → 폐기`를 후보로 둔다. ‘사용 중’ 같은 관리 상태와 ‘pause/전송 장애/미관측’ 같은 런타임 상태는 별도다.

- 등록은 입력·소속·중복·자격·예산을 검증한 뒤 설정을 발급하는 흐름이다. 발급 성공을 설치/수신 성공으로 표시하지 않는다.
- Q07-03 합의: 서비스 별칭을 나중에 바꿔도 서버/agent/수집 연결·기존 로그/출처와 본문은 유지하고 화면의 서비스 이름을 현재 별칭으로 표시한다. 이름 규칙·이전 이름/변경 이력 표시·동시 수정·서비스/연결 참조의 구체 계약은 후속 설계다. 다른 서비스 분류로의 이동·소속/전송 권한 변경과 queue 원래 scope(D08)는 별도 처리한다.
- 과거 이벤트는 원래 source ID에 연결하고 현재 사용자의 그 source 조회 권한으로 검사하는 안이다. 소속 변경으로 과거 데이터를 새 scope에 자동 공개하지 않으며, 과거 데이터 접근 범위를 바꾸려면 영향 범위가 명시된 별도 정책 변경으로 처리한다.
- 수집 중단 시 신규 읽기 중단과 기존 queue 전송의 허용 여부를 구분한다. 보안 폐기 때문에 전송을 중단한 queue는 자동 drain하지 않는다.
- Q07-07 보관은 운영자가 더 쓰지 않을 연결에 명시적으로 선택한다. 로그 0건·미보고/단절·인증/네트워크 오류는 런타임 상태로 구분하고 자동 보관 사유로 삼지 않는다. 중앙 새 수신 차단·과거 로그의 보존 정책 유지와 로컬 중단 적용/관측을 구분한다. 재활성화는 원래 서버/입력·현재 자격/설정·위치 확인 후 진행하며 Q06 보류/복구를 유지한다. 등록 완전 삭제는 후속이며 키·참조·대기·보존 로그를 일괄 삭제하지 않는다.
- source 삭제 버튼으로 중앙 로그·agent spool·원본 파일을 한 번에 지우지 않는다. 원본 파일은 LogDock의 자동 삭제 대상에 넣지 않는다.

## 2 F02 지원 범위와 연결 절차

| 지원 항목 | 합의/확인과 초기 제안 | 확정·검증할 조건 |
| --- | --- | --- |
| OS와 실행 | 에이전트 설치 대상 Linux는 사용자 확인. 명시적 서비스 실행은 검토안 | 배포판/버전·kernel·architecture·filesystem·자원 제한 수단·사용 계정·실행 방식. 중앙 OS는 미정 |
| 입력 | 일반 파일/journald 입력·일반 텍스트/JSON/여러 줄 형식·UTF-8 초기 지원 합의 | 파일 identity·rotation·경로 한도, journal 대상/최초 경계/진행 위치·권한·분할 메시지·원본 기록 삭제·전체 자원 검증 |
| 컨테이너 | 기존 파일 또는 journald에 기록된 출력을 해당 입력으로 수집 | stream/이벤트 경계·재배포 identity·권한·중복 경로. 모든 Docker driver나 Docker 제어 권한을 기본 요구하지 않음 |
| 초기 유예 제안 | Windows/macOS agent, network syslog, 앱 SDK, 자동 전체 디렉터리 탐색 | journald는 초기 채택으로 이동. 나머지는 필요 범위 선택과 자원/손실 시험·지원표로 검증 |
| 합의된 제외 | 최초 수집 경계 이전 로그의 별도 가져오기. 압축 backfill도 포함 | 후속 출시 후보로 남기지 않음. 정상 장애 후 밀린 로그 재개와는 구분 |
| 설정 방식 | 중앙에서 단일 파일/파일명 규칙 입력→키 발급과 주소/키/경로 설정 제공→사용자 복사 적용은 합의 | 경로/파일/읽기 권한은 해당 에이전트가 확인. 중앙 원격 탐색/권한 변경·자동 설치 없음. 문법/한도·OS/형식/설치 명령·TLS/키 세부는 후속 설계 |

합의한 초기 연결은 중앙 수집 연결 화면에서 기존 서비스 선택 또는 새 분류 이름 등록과 로그 서버 경로 입력→서비스/수집 등록 확정→키 발급과 중앙 주소/키/경로 설정 제공→사용자가 에이전트에 복사/적용이다. 파일 존재/읽기 권한은 로그 서버의 에이전트가 로컬에서 확인한다. 이후 합성 이벤트 관측·중앙 수신/검색 확인과 실제 설치/명령/형식은 후속 설계다. 중앙 원격 파일 읽기나 업무 API/DB 테스트를 정상 확인 수단으로 요구하지 않는다. 무로그 상태 보고만으로 전체 성공을 추정하지 않는다.

경로 없음·권한 부족·지원하지 않는 파일·이벤트 경계 판별 불가·복구 근거 없음·parser 오류·크기 상한 초과·디스크 사용 불가·네트워크/TLS·인증·부분 거부·검색 지연을 서로 다른 사유로 표시한다. 안내는 필요한 최소 권한과 영향 범위를 설명하며 자동 chmod·방화벽 변경·서비스 재시작으로 해결하지 않는다.

일반 텍스트·JSON·명시한 시작 규칙의 여러 줄 로그는 Q02-03 초기 지원 합의다. UTF-8은 Q02-04 초기 지원 합의이며 EUC-KR/CP949 등은 필요 확인 시 후속 추가한다. 구체 parser/내장 규칙·필드 추출·JSON 구조/여러 줄 JSON·BOM/줄 구분·부분/잘못된 문자·지원 외 인코딩 처리와 한도는 후속 설계다. 고유 vendor 형식 자동 추정은 별도 채택 대상이다. 입력 지원 여부와 parser 성공률은 별도이며, Q02-05에서 지원 조건/이벤트 경계가 유효한 일반 파싱 실패의 본문 보존 전송·해석 실패 표시·확인 불가 항목 미확인·다음 로그 계속 수집을 합의했다. 세부 표시/필드·검색/진단과 검증은 [수집 명세](collection-agent-v0.1.md#일반-파싱-실패-q02-05)를 따르며 인코딩/경계/크기 오류와 구분한다. D04는 LogDock의 민감정보 처리 실패 차단을 정의하지 않는다.

Q02-06 일반 파일 탐색은 지정 폴더 안에서만 수행하고 필요한 하위 폴더는 별도로 지정한다. 제공 설정·로컬 검사/오류 안내에서도 같은 범위를 유지하고 문법/경로·symlink·중복 일치·자원/검증은 [수집 명세](collection-agent-v0.1.md#파일-탐색-범위-q02-06)로 연결한다.

Q02-02에서 journald를 초기 입력으로 채택했다. 파일 경로 기반 등록/설정 제공 원칙에 더해 journal 허용 대상·서비스 연결·읽기 권한·제공/적용 설정과 상태 표시를 설계한다. 파일 존재 검사와 journal 접근/대상 검사를 구분하며 구체 UI/필드·호스트 보관/권한 설정 변경은 자동 채택하지 않는다. 기존 앱/driver를 유지하고 별도 파일 복제 없이 읽는 방향을 검토한다. 신규 경계·위치 복원·분할 이벤트와 미실행 검증은 [수집 명세](collection-agent-v0.1.md#journald-입력-q02-02)를 따른다. 실제 서버의 journal 영구 보관은 미확인이고 LogDock 디스크 대기와 별개다.

D02의 파일별 최초 EOF·쓰던 이벤트 제외·신규 생성 확인/불확실한 미등록 파일의 구분·복구 근거 없을 때 자동 읽기 보류는 합의된 전제다. 경계 규칙이 없거나 잘못돼 판별할 수 없으면 해당 파일을 설정 확인 필요 대기 상태로 둔다. D03은 상한 초과 이벤트 전체 본문을 거부하고 확인 가능한 사유·시각·건수·상한을 본문 없이 표시한 뒤 다음 경계를 확인해 정상 수집을 이어간다. D05는 제한된 디스크 버퍼를 기본으로 하고 사용 불가 시 자동 메모리 대체 없이 해당 수집을 대기/오류로 처리한다. 기존 버퍼를 보존하고 필수 전송 완료/위치 상태도 기록할 수 없으면 해당 전송을 안전 정지하며, 정상 확인 후 기존 위치부터 예산 안에서 재개한다. 상세 계약은 수집 명세를 따른다.

## 3 D06 중앙 전달과 실패 계약

Q05-01은 키 오류 중 정상 디스크/필수 상태·명시 중지 없음 조건에서 로컬 대기 한도 내 새 읽기 지속으로 합의했다. 포화는 D01 보존/읽기 중단, 상태/쓰기 오류는 D05 안전 정지이며 기존 앱 기록은 계속된다. Q16-09/Q05-02 정상 중지는 잔여 전송/ACK 대기 없이 종료하고 기록/대기를 보존하는 합의다. Q05-02 사고 대응은 중앙 대상 키 폐기 우선 시도·서버 운영자의 해당 연결 로컬 읽기 중지·중앙 실패가 로컬 중지를 지연시키지 않음·대기 보존으로 합의했다. 중앙/로컬 완료와 연결/전체 agent 영향을 구분하고 실제 적용/실패는 설계로 남긴다. Q05-03 전용 대기 폐기는 후속으로 유예했고 [전용 기획안](../planning/q05-q07-q10-plan-v0.1.md#q05)을 따른다. 폐기 효력은 Q10-11 합의, 장기 대기/중복 판정 수명은 T08/D06의 설계다. 중앙 차단과 agent의 실제 읽기 중단/관측은 구분한다.

D06/Q04의 합의는 동일 이벤트 재전송의 중앙 저장·검색·집계 한 건, 프로그램 재시작 후 보존할 기록 확정 뒤 수신 완료 응답, 응답 전 한도 내 후속 전송과 미확인 버퍼 유지다. 중앙 서버/디스크 고장 대비 별도 복제·자동 장애조치·로그 백업/복구 보장은 제외한다. 에이전트는 중앙의 전송 응답만 처리하고 이후 저장·색인·검색·보존은 중앙 책임이다. 기록 확정 수단·ACK/버퍼 정리 순서·판정 유지 기간·실제 한도·검색 지연 목표는 후속 설계/검증이다.

| 계약 | 제안 의미 | 설계에서 확인할 것 |
| --- | --- | --- |
| 전송 인증 | 서비스가 확정된 수집 등록정보에 연결된 키로 중앙이 허용 수집원과 서비스를 판별 | 서비스 없는 등록에는 키를 발급하지 않음. 요청 필드로 인증 범위/서비스를 임의 확장하지 않음. 키/등록정보 확인 불가 시 완료 응답하지 않고 오류 표시·미확인 대기 보존 |
| 중앙 ACK | 프로그램 재시작 후 보존할 기록 확정 뒤 수신 완료 응답. 메모리 수신만으로 완료 응답하지 않음 | 기록 확정과 승인/부분 거부·ACK/버퍼 정리 순서를 설계/검증. 중앙 서버/디스크 고장 대비 별도 보호/복구는 제외. 검색 지연 목표는 미정 |
| 후속 전송 | 앞선 응답 전에도 한도 안에서 다음 로그를 전송. 미확인 데이터는 버퍼 유지·같은 식별 재시도 | 미확인 전송 건수/bytes·in-flight 상한과 D01 버퍼 포화를 구분. 전자는 새 전송 대기, 후자는 추가 읽기 pause. 에이전트가 중앙 저장소/검색을 직접 검사하지 않음 |
| 부분 결과 | 승인·영구 거부·재시도 대상을 안정적으로 구별 | 개별 식별/상태가 없는 프로토콜이면 제한과 batch 중복 위험 기록 |
| 재전송 식별 | source/stream identity·원본 구간/sequence·변환 version 등으로 동일 전송 재시도를 식별 | 본문이 같은 별개의 이벤트를 dedup하지 않음. 식별 수명·cache 상한·재시작 보존·충돌 계약 |
| dedup | 동일 이벤트 재전송의 중앙 중복 저장·검색·집계 방지 | 판정 상태의 유지/복원·동시 재전송·보존 만료·오래된 재시도의 처리 계약 필요. 판정 근거가 사라진 뒤 도착한 로그는 Q13-04대로 같은 식별로 저장하며 새 ID를 만들지 않음 |
| 위치 기록 | 원본 복구 위치·queue commit·중앙 완료 위치를 분리 | 기록 순서와 crash 원자성. 필수 기록 실패면 위치 확정/dequeue 중단 |
| 영구 거부 | D03 크기 상한 초과와 향후 채택한 형식/범위 정책에 따른 사유·확인된 개수. D04 민감 내용 거부는 제외 | 일반 timeout/장기 retry를 영구 거부로 바꾸지 않음. 정상 이벤트는 경계 확인 후 진행 가능 |
| 전송 혼잡 | 429·5xx·단절은 bounded retry/backoff/jitter | 송신률·연결·in-flight·retry budget·진단 비용 모두 예산에 포함 |
| 인증/권한 변경 | Q05 합의: 키 사용 불가 시 원래 수집원의 디스크 대기 파일 보존·전송 보류, 새 유효 키의 전송 권한 확인 후 같은 식별 재개 | 실제 등록/권한 모델·조치 협조는 설계이며 전용 강제 대기 폐기는 Q05-03 후속 유예 합의. 포화 시 D01, 실제 폴더/형식/용량·기록/정리 순서는 후속 설계. 본문 재마스킹 제외 |
| 검색 준비 | 중앙이 관측·제공하는 별도 단계/수신 지표 | 에이전트가 저장소/검색을 직접 검사하지 않음. 알 수 없으면 ‘수신 확인, 검색 가능 미확인’으로 표시 |

중앙 수신 시각은 고유 이벤트의 최초 수신 기준을 유지하는 검토안이다. 같은 이벤트 재전송으로 보존 만료나 알림 평가 창이 매번 연장되지 않도록 설계한다. Q12 알림 집계는 중앙 수신 시각으로 합의했으며 기준의 기록 확정·복원과 중앙 보존 기준은 Q04/Q13 및 D06에서 설계/협의하며, 판정 근거가 남아 있는 재시도를 새 발생으로 취급해 중복을 만들지 않으며, 근거가 사라진 뒤 도착한 로그는 Q13-04를 따른다.

키 사용 불가 시 미전송 로그는 에이전트 서버의 원본과 별도 전용 디스크 대기 파일에 보관하고, 새 키의 유효 전송 권한을 확인하면 원래 수집원으로 같은 식별 재개하는 Q05 원칙을 따른다. 폴더/형식/용량·기록 확정/정리 순서는 후속 설계다. 소속/권한 변경 세부는 Q10과 연결해 검토한다. 본문 재마스킹은 제외하며 D01의 기존 queue 보존·포화 시 추가 읽기 pause와 D05 디스크 사용 불가 처리를 유지한다.

## 4 F06 수집 상태와 데이터 품질

상태는 관리 수명, agent 관측, 읽기/전송, queue, 중앙 수신/검색을 나누어 제공한다. 한 개의 초록색 ‘정상’으로 모든 단계를 대신하지 않는다.

에이전트 보고와 중앙 자체 관측을 합쳐 보여주는 검토안이며 agent가 중앙 검색까지 검증한다는 뜻이 아니다. Q14 기본 정책은 제한된 진단의 재시작 확인·rotation/새 기록·전체 한도에서 미전달 진단도 오래된 파일부터 정리·진단 저장만 실패/로그 대기와 필수 상태 정상 시 실제 수집/전송 계속과 진단 저장 오류/공백 표시다. 보고 불가 시 미관측·대기/필수 상태 실패 D05 안전 정지와 원본/대기·전체 예산/즉시 중지를 유지한다. 기본 사용자 협의는 정리했고 실제 수치/회전·정리/기록/복구·보고/신선도/정합성은 개발팀 검증이다.

| 관측 상태 | 의미와 안내 |
| --- | --- |
| 연결 대기 | 등록되었으나 agent/수신 증거 없음 |
| 관측됨·무로그 | 유효 상태 보고는 있으나 이벤트 없음. 읽기와 중앙 수신 성공을 자동 확정하지 않음 |
| 수집/전송 진행 | 마지막 읽기·ACK 등 확인된 단계와 시각 표시 |
| 읽기 pause | D01 포화/자원 보호 등 사유·시작 시각·queue·원본 보존 위험 표시 |
| 설정/복구 확인 필요 | D02 경계 불명 또는 복구 근거 없음 표시. 기록을 끝내 복원할 수 없을 때 누락 안내 후 Q06 ‘지금부터 다시 수집’ 선택 제공. 경계/파일/필수 새 기준 기록 확인 불가 시 보류 유지 |
| 디스크 사용 불가 | D05 권한/공간/쓰기 실패, 영향 범위·읽기/전송 중단 여부. 기존 버퍼 보존과 정상 확인 후 제한 재개 |
| 이벤트 거부 관측 | D03 수집원·사유·관측 시각·확인된 건수·적용 상한·이후 수집 상태. 본문은 진단에 포함하지 않음 |
| 전송 오류/보류 | 재시도 가능한 오류·인증 오류·현재 정책 재검사 구분 |
| 복구 중 | backlog와 제한된 회복 속도. 새 이벤트보다 오래된 이벤트만 보일 수 있음 |
| 관측 오래됨/미확인 | 마지막 보고와 현재 관측 불가. 마지막 정상값을 현재값처럼 표시하지 않음 |
| 시각 확인 필요 | 에이전트 보고 시각과 중앙 시각의 차이가 크거나 연결의 시각이 관측 시각과 일정하게 어긋남. 서버 시계 또는 `로그 시간대` 설정 확인을 안내하고 수집은 멈추지 않음(Q08 SD-05) |
| 중단/보관 | 관리자가 정한 수명 상태와 남은 queue 처리 표시 |

기본 화면은 source/agent별 마지막 보고·마지막 ACK·queue bytes/가장 오래된 항목·pause 사유·parse/거부·확인된 손실·누락 가능 구간을 보여주는 안이다. 검색 준비 여부는 capability가 있을 때만 제공한다.

count는 읽기 bytes·조립 이벤트·승인·영구 거부·재시도·중복·확인된 drop을 구별한다. 재시도 횟수를 고유 event 수로 세지 않으며 counter reset/측정 기간을 표시한다. 원본 삭제로 읽지 못한 개수가 모르면 미확인으로 남긴다. 진단 원문·고유 request ID를 metric label로 넣어 cardinality를 늘리지 않는다.

heartbeat 주기·오래됨 기준·계측 집계 창·진단 보존 기간은 D16에서 채운다. 이벤트 발생 시각은 source 시계 오차가 있으므로 중앙 관측 지연과 직접 동일시하지 않는다.

## 5 F09 인증과 권한과 키와 감사

Q10-01~14의 기본 사용자 정책은 [전용 표](../planning/q05-q07-q10-plan-v0.1.md#q10)의 채택/유예/설계 인계 결과를 따른다. 공용 계정·인증/자격/복구·관리 보호·세션·등록별 키와 인증/주요 관리 감사 범위는 합의했고 MFA는 후속이다. Q10-13/14는 감사 90일 목표/강제 예산 우선 정리와 감사 저장 단독 실패 시 정상 로그인/검색/수신 계속(인증/세션·필수 상태/로그 저장 정상 조건), 일반 민감 관리 변경 적용 전 보류·확정 가능한 긴급 권한 축소/인증된 호스트 로컬 자격 복구 예외·공백/실제 결과 표시를 합의했다. 키 90일 자동 만료나 교체 중 24시간/7일 자동 종료는 채택하지 않았고 감사 90일은 사용자 목표/용량 우선으로 최소 보장이나 법정 기간이 아니다. 실제 예산/권한/저장·기록/정리/부분 실패/복구·수치/정합성/구현/검증은 후속이다. 웹 세션과 agent 키/대기는 독립이며 아래 사람별 역할 표는 향후 계정 분리 검토안으로 유지한다.

### 인증 방향과 남은 운영 정책

Q10/Q11에서 초기 웹 로그인은 운영팀 공용 계정 하나, 검색 조건은 그 계정의 저장 목록을 함께 사용하는 것으로 합의했다. 개인/팀 목록과 사용자별 계정·역할 관리는 초기 범위에 추가하지 않는다. 향후 필요 시 계정 분리를 지원할 수 있도록 주체 식별·객체 귀속·권한 검사에 확장 지점을 둔다. 실제 계정이나 자격을 생성한 것은 아니며 웹 계정 수가 수집 키 수를 정하지 않는다.

2026-11-01 사용자는 웹 운영 범위를 ‘사내망·VPN 전용’, 인증 선호를 ‘자체 로그인’으로 답했다. 웹과 에이전트 전송에는 HTTPS를 기본 적용한다. Q16-04/E01에서 로그 서버와 중앙은 모두 private 서버이며 서로 연결 가능하다고 확인했으며 이 설치는 private 연결을 전제로 설계한다. HTTPS 인증서는 이미 관리 중이라고 사용자 확인했으며 관리 여부는 재질문하지 않는다. 실제 연결 시험은 미실행이고 인증서 구체 적용/신뢰 배포·갱신 연동·TLS 종료 뒤 구간·구체 네트워크 허용은 후속 설계/설치 확인이다. 기존 공용 1계정의 로컬 인증을 제공하며 MFA는 후속이다. 초기 자격 설정/변경·잠금 복구·로그아웃·세션 만료·동시 접속·허용 관리 작업은 관련 Q10 선택표를 따른다. 복수 사용자/역할과 기존 검색 조건/알림 이전은 향후 계정 분리 채택 시 정하며 채팅/공개 문서에 실제 자격을 기록하지 않는다.

기본 거부와 매 요청 권한 확인은 [OWASP Authorization Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)의 지침을 참고했다(2026-11-01 확인). 다음 역할과 scope 설계는 향후 계정 분리 시의 검토안이며 초기 공용 계정의 역할 표로 채택한 것이 아니다.

Q10-03 합의(2026-11-02): 설치 시 서버 운영자가 고유 초기 비밀번호를 안전하게 설정하고 웹 재인증 후 변경한다. 분실/잠금은 인증된 서버 운영자의 로컬 재설정이며 이메일 자동 복구는 초기 제외한다. 최소 15자/긴 문구 허용·흔한/알려진 유출 값 차단·로그인 시도 제한·정기 강제 변경 없음/유출 확인 시 변경을 따르고 기존 웹 세션 전체 종료와 수집 키/대기의 독립을 유지한다. 실제 최대 길이/문자 처리·저장/해시·로컬 권한/복구 경로·시도/잠금 수치/실패/동시성·라이브러리·구현/검증은 T04/E03 설계다. 실제 비밀번호/계정을 수집하거나 생성하지 않았다.

### 키와 session 수명

키 발급 전 수집 연결의 서비스 지정·등록정보를 확정하고 중앙은 키/등록정보로 서비스를 판별한다. 서비스 없는 등록에는 키를 발급하지 않으며 키 범위/개수는 Q10-07의 연결별 키·평상시 1개/교체 중 2개 합의를 따르며 실제 등록/입력 묶음·인증/요청 형식은 후속 설계다. 조회 자격과 수집 자격을 분리한다. Q10-08의 발급/교체 화면 원문 표시·이후 재조회 불가·메타데이터 조회·복사 실패/분실 시 새 키 교체를 따른다. 설정 재다운로드/응답 유실·동시 발급/폐기와 최대 2개 제한·저장/전달 방식은 후속 설계다. Q10-09에 따라 일반 키의 자동 만료는 없으며 웹 세션/인증서 수명과 구분한다. Q10-10의 새 키 수동 적용/수신 확인 뒤 기존 키 직접 폐기·자동 종료 기한 없음·최대 2개 제한을 따른다. 확인/폐기 실패·무로그/부분 적용·동시 조작과 완료 표시는 후속 설계다. Q10-11의 중앙 폐기 확정 전 저장 완료/늦은 응답 인정·미완료는 폐기된 키로 완료 금지·원래 연결의 유효 키/같은 식별로 대기 재전송을 따른다. 중앙 차단과 agent 읽기/관측은 별개이며 실제 인증 상태/기록·부분 요청/완료 응답·재시작/실패·효력 표시/지연 검증은 T03/PT-12에 남는다. 진단/감사에 secret을 기록하지 않는다.

계정/권한 회수 시 새 요청뿐 아니라 진행 중 live/export/알림 작업의 정책 재검사를 포함한다. 이미 외부로 반출된 내용의 회수는 보장하지 않는다. 비밀 공급 방식·보관·TLS·session cookie·CSRF·rate limit 등 구현 세부는 선택한 인증/배포 구조의 공식 자료와 위협 모델로 검증한다.

### 감사 범위

Q10-13/14 합의(2026-11-02): 감사 목표는 90일이며 별도 강제 디스크 예산이 우선한다. 만료 이력과 용량 초과 시 가장 오래된 이력부터 정리하고 90일 전 조기 정리/실제 조회 가능 범위를 표시한다. 감사 저장만 실패하면 인증/세션·필수 상태/로그 저장이 정상인 로그인/검색/수신은 계속한다. 새 키 발급·일반 등록/설정·웹 비밀번호 변경 등 채택된 일반 민감 변경은 적용 전 보류한다. 2026-11-05 후속 합의로 보류한 변경은 감사가 복구돼도 자동 적용하지 않고 사용자가 다시 실행한다. 키 폐기/전체 웹 세션 종료는 실제 인증 차단 상태를 확정 저장할 수 있을 때 허용하고 Q10-03의 인증된 호스트 운영자 로컬 복구도 새 자격/기존 세션 회수를 안전하게 확정할 수 있을 때 허용한다. 감사 공백과 실제 결과를 구분하며 인증/세션 상태까지 확정 불가를 성공 처리하지 않는다. 기존 키/세션·agent 대기/식별을 감사 장애만으로 자동 폐기하지 않고 실제 예산/기록/정리/부분 실패/복구·권한/정합성은 T04/T06/Q15 설계/검증이다.

초기 사람의 작업은 공용 계정을 주체로 기록하며 계정을 함께 쓰는 개인을 식별하는 이력은 전제하지 않는다. 계정 분리 이후에도 과거 공용 계정 기록을 특정 사람에게 임의 배정하지 않는다. 에이전트의 전송 키·수집 등록 참조는 웹 로그인 주체와 별개다.

Q10-12 합의(2026-11-02): 로그인 성공/실패·로그아웃·비밀번호 변경/복구·세션 종료와 채택한 연결/키/보관/주요 설정 변경의 시도/결과를 기록한다. 시각·공용 계정·동작·대상·결과를 남기고 비밀번호/키 원문·로그 본문/검색어 원문과 세션 쿠키/토큰 등 비밀값은 제외한다. 모든 검색/본문 조회 상세 추적과 IP/기기 정보 장기 보관은 초기 제외한다. 시도 제한용 임시 정보는 장기 감사와 구분한다. 대상/상관 참조·사유/설정 version·허용 필드/크기/주입 방어·폭주 집계/한도·조회 권한은 T06 설계이며 공용 주체로 실제 개인을 단정하지 않는다. 감사만을 위해 미채택 사용자/역할·삭제/폐기·export 기능을 추가하지 않는다.

[OWASP Logging Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html)는 인증/고위험 관리 사건 기록·비밀 직접 기록 회피/접근 제한과 로깅 장애/자원 고갈의 시험·가용성을 안내한다(2026-11-02 재확인). Q10-12의 최소 범위/IP·기기 장기 보관 제외와 Q10-13/14의 90일 목표/예산 우선·작업별 보류/예외는 사용자 채택 제품 정책이며 가이드가 그 숫자/알고리즘을 일률 요구한다는 뜻이 아니다. 실제 필드/저장·예산/정리/실패/복구·구현/검증은 T04/T06/Q15에 남긴다.

여기서 비밀값·본문을 남기지 않는 대상은 LogDock 자체의 진단·감사 기록이다. 앱이 출력한 수집 본문을 필터링하라는 의미가 아니며 D04의 책임 구분을 유지한다.

중앙 보존 만료와 agent 미전송 queue의 폐기는 서로 다르다. 중앙 기간 변경으로 agent queue를 지우지 않는다. 삭제/권한 변경된 source에 queue가 남으면 Q05/D08에 따라 전송 보류와 조치 필요를 표시하는 안이다. 중앙 하드웨어 고장용 로그 백업/복구를 제품 필수 동작으로 넣지 않으며, 제품 밖의 사본 관리 책임과 로그 보존/삭제를 구분한다.

사용량은 수집 전/후 bytes·중앙 승인/거부·논리 저장량·물리 디스크·조회 scan/실행 시간·내보내기·queue를 구별한다. 측정 시각·집계 기간·reset·추정 여부를 표시하며 서로 다른 기준의 bytes를 같은 수치로 맞추지 않는다. SaaS 청구액·플랜 화면은 초기 범위가 아니다. 저장량·남은 공간·조회 가능 시작일·조기 삭제 발생을 함께 표시한다.

Q13 설계 인계: 만료 시 검색 제외는 각 로그 기준으로 맞추되 실제 디스크 회수는 저장 분할 단위로 일어날 수 있다. 분할이 작으면 인덱스 수가 늘고 크면 물리 삭제가 늦어지므로 기술 선정 때 함께 정한다. 수신 시각으로 분할하면 재전송이 다른 분할로 들어갈 수 있어 6개월 범위의 중복 판정 방식을 함께 설계한다. 로그가 감사·메타데이터 공간을 잠식하지 않도록 조기 삭제 기준은 전체 디스크가 아니라 로그 전용 저장 상한으로 둔다. 삭제 표시만으로 공간이 바로 회수되지 않는 엔진 특성([Lucene 삭제 처리](https://www.elastic.co/blog/lucenes-handling-of-deleted-documents), [ClickHouse TTL](https://clickhouse.com/docs/knowledgebase/when_is_ttl_applied), 2026-11-02 확인)을 후보 평가에 반영한다.

## 7 F08 알림 정책

2026-11-02 Q12 세부 협의를 정리했다. 상태 전이·전달·실패 계약의 기준은 [Q12 기획안](../planning/q12-plan-v0.1.md)이다. 시간 구간·임계는 기본값 없이 직접 입력(1~1,440분, 1 이상). 해소 대기는 규칙별이며 비우면 시간 구간과 같은 길이. 조건 수정 시 상태 초기화. 대상 연결 전부가 끊겼을 때만 해소 계산 정지. 수집 끊김·평가 실패 10분 지속 시 설치 공통 운영 메일 1통. 크기 초과 거부는 화면 표시만. 전송 여부 불명은 같은 Message-ID로 재시도. 해소 뒤 대기 메일은 계속 전송하고 해소 사실 표시. 수신 주소는 규칙당 최대 10개, 형식 검사와 테스트 메일. 알림 이력은 로그 보관 기간과 동일. 기존에 쓰는 네이버 SMTP를 쓰고 메일 주소는 사용자가 입력한다. 아래 절의 미정·보류 표현 중 이 합의와 다른 부분은 재개 전 기록이다.

2026-11-01 사용자는 메일 세부 협의를 넘기고 잔여 항목 전체 보고를 요청했다. 아래 기존 합의는 유지하며 해소 후 대기 메일 A/B는 미결정·협의 보류다. 이 보류는 2026-11-02 Q12-11(계속 전송·해소 사실 표시) 합의로 닫았다. 실제값·실패 분기 등은 설계안으로 묶어 정리하고 추가 개별 질문을 자동 재개하지 않는다.

Q01에서 오류 알림을 첫 출시에 포함하고 Q12에서 건수 기준으로 시작하기로 합의했다. 평소 대비 급증 감지는 후속이다. 초기 수신 채널은 이메일이다. 집계는 중앙 수신 시각으로 합의했다. 시간 구간과 임계 건수는 규칙마다 설정하기로 합의했다. 실제 설정값/한도·필터 세부 계약·평가/해소 대기 시간·메일 연결 설정·수신 주소 검증/한도 등은 미정이다. 설명용 5분/10건을 기본값으로 채택하지 않는다. 아래 표는 건수 기준의 합의와 세부 검토안, 후속 급증 검토 항목을 구분하며 미합의 상세 동작을 확정하지 않는다. Issue 관리는 계속 보류다.

2026-11-01 Q12 반복 발송 합의(A): 오류 건수 조건을 처음 충족하면 메일을 한 번 보내고, 같은 조건이 계속 충족되는 동안에는 반복 발송하지 않는다. 조건 해소가 확인된 뒤 다시 충족하면 새 알림 메일을 보낸다. 지속 중 주기적 재발송과 매 평가 발송은 초기 방식에 포함하지 않는다. 첫 메일을 놓친 경우의 지속 알림은 제공하지 않는 선택이다.

2026-11-01 Q12 회복 메일 합의(B): 조건이 해소돼도 회복 메일은 보내지 않는다. 해소 확인 후 재발하면 새 오류 메일을 보내는 기존 합의는 유지한다. 회복 메일 생략이 내부 해소 판정 생략을 뜻하지 않는다. 해소 대기 기간의 실제값/평가 계약·데이터 없음/평가 실패 처리·평가 주기·조건 수치와 메일 재시도 실제값/실패 분류·전송 여부 불명/중복 제어·상태 기록/복원은 후속 협의/설계로 남긴다. 반복 발송 생략을 전송 실패 재시도 생략으로 해석하지 않는다. 실제 메일 설정·발송이나 구현/실행 검증은 하지 않았다.

2026-11-01 Q12 집계 시각 합의(A): 초기 건수 알림은 로그가 중앙에 도착한 수신 시각을 기준으로 집계한다. 10:00에 발생해 10:30에 도착한 로그는 알림에서 10:30 수신 구간의 대상이 된다. 일반 검색은 Q08 발생 시각 기준을 유지하며 중앙 보존 기준은 Q13 최초 중앙 수신 시각이다. 시각은 합성 예시이며 기본값이 아니다.

전송 지연 뒤 과거 오류가 도착해도 수신 시점의 조건을 충족하면 알림 대상이 될 수 있다. 기존 D06에 따라 동일 이벤트 재전송을 새 오류로 중복 집계하지 않도록 설계한다. 정확한 수신 경계/시각 기록·평가 지연/구간 경계·동일 이벤트 판정과 상태 복원·해소 대기 시간/세부 계약·필터 세부 계약·수신 목록의 검증/한도·실제 수치는 후속 협의/설계다. 실제 규칙 생성·메일 발송·구현/시험은 하지 않았다.

2026-11-01 Q12 규칙별 조건 합의(A): 알림 규칙마다 서로 다른 시간 구간과 임계 건수를 설정할 수 있게 한다. 예를 들어 서비스 A는 최근 5분 오류 10건 이상, 서비스 B는 최근 1분 오류 30건 이상을 각각 둘 수 있다. 서비스명·기간·건수는 합성 예시이며 기본값이 아니다. 모든 초기 규칙은 기존 중앙 수신 시각 집계·조건 지속 중 최초 한 번·해소 후 재발 시 새 발송·회복 메일 생략 합의를 따른다.

시간 구간/임계 건수의 허용값·기본값·입력 검증·평가 주기·필터 세부 계약·규칙 수/자원 한도·조건 수정 시 상태 처리·수신 목록의 검증/한도는 후속 협의/설계다. 규칙 생성·메일 설정/발송·구현/시험은 실행하지 않았다.

2026-11-01 Q12 수신자 합의(A): 알림 규칙마다 수신 주소를 하나 또는 여러 개 지정할 수 있게 한다. 규칙별로 다른 수신 목록을 사용하고 같은 주소를 여러 규칙에 지정할 수도 있다. 공용 로그인 1계정과 기존 규칙별 시간 구간/임계 건수·중앙 수신 시각 집계·최초 한 번/해소 후 재발 시 새 발송·회복 메일 생략 합의는 유지한다.

수신 목록의 최대 개수·주소 입력/검증·중복 처리·수신자 변경과 대기 발송의 관계·수신자별 실패 분류·재시도 실제값/중복 제어·메일 발송 방식/제공자·메시지 문구/추가 요약 항목은 후속 협의/설계다. 실제 주소나 자격을 기록하거나 규칙/메일 설정·시험 발송·구현/실행 검증을 수행하지 않았다.

2026-11-01 Q12 메일 구성 합의(A): 알림 메일은 규칙명·오류 건수·집계 시간 구간 등 요약과 로그인 후 여는 LogDock 조사 이동 링크로 구성한다. 원문 로그 본문은 메일 본문이나 첨부에 포함하지 않는다. 링크는 알림을 판단한 대상 조건과 중앙 수신 시각의 절대 평가 구간을 유지하고, 열 때 현재 로그인·권한·로그 보존을 적용한다.

F07 내부 공유 객체·파일 내보내기 후속과 결과 snapshot 장기 저장 제외는 유지한다. 메일 문구/추가 요약 항목·링크 식별/주소 구성·조건 수정 뒤 원래 평가 조건 유지·미인증/권한 변경/만료 표시·현재 결과와 당시 통계 차이·길이/자원 한도는 후속 설계/검증이다. 실제 메일 설정·발송이나 구현/실행 검증은 하지 않았다.

2026-11-01 Q12 알림 필터 합의(A): 일반 검색에서 채택한 서비스·서버·레벨·본문 조건과 정상적으로 해석한 구조화 필드의 값 일치·항목 존재·숫자 범위를 알림 집계 대상 선정에도 사용한다. 본문은 기존 Q08의 기본 대소문자 미구분·선택적 구분 옵션을 따르며 이 옵션을 필드 값/ID 비교에 자동 적용하지 않는다. 알림의 집계 시간 기준은 중앙 수신 시각을 유지한다.

서비스 A의 ERROR 중 본문에 timeout이 있는 로그만 세는 것은 합성 사용 예시다. 타입·문자열 비교·누락/해석 불가·조건 조합·구체 문법과 지원 한도·평가 예산은 Q08 상세 계약과 함께 설계/검증한다. 파싱 실패를 필드 없음으로 단정하지 않으며 추가 고급 연산·구체 엔진/코드/UI 채택을 확정하지 않는다. 실제 규칙 생성·평가/메일 발송·구현/시험은 실행하지 않았다.

2026-11-05 [Q08-09](../planning/q08-search-plan-v0.1.md#q08-09-같은-서버의-여러-로그를-어떻게-나눠-볼-것인가) 합의로 알림 규칙 조건에도 출처 `수집 대상`(등록된 수집 연결)이 생겼다. 보관된 연결은 규칙 대상에서 빠진다(Q12 TD-18).

2026-11-01 Q12 메일 재시도 합의(A): 전송에 실패한 수신자를 대상으로 간격을 두고 정한 횟수와 총 대기 시간의 상한 안에서 재시도한다. 전송 성공이 확인된 주소에는 다시 보내지 않는다. 상한까지 실패하면 최종 실패 상태를 표시한다. 조건 지속 중 최초 한 번의 알림 생성·해소 대기 후 재발 시 새 알림·회복 메일 생략은 유지하며, 메일 전송 작업의 한도는 D01 에이전트 로그 대기 보존과 별개다.

초기 알림 채널은 이메일로 합의했다. 규칙별 한 개 이상의 수신 주소 지정은 합의했다. 메일 발송 방식·제공자·연결/인증 설정·수신 주소의 검증/최대 개수·목록 변경·재시도 실제 한도/간격·실패 유형/중복 제어와 메시지 문구/추가 요약 항목·링크 식별은 후속 설계/협의한다. 공용 로그인 계정 하나를 단일 수신 주소나 로그인 주소 자동 발송으로 해석하지 않는다. 자격은 환경별 비밀 설정으로 다루며 공개 문서에 넣지 않는다. 실제 발송 설정·시험 메일 전송은 이번 문서 반영에 포함하지 않는다. 다른 채널은 후속 검토하며 webhook을 채택한다면 목적지·비밀 공급·본문·재시도 한도를 별도로 설계한다. 원문 본문 없는 요약도 정보 반출이므로 채널 관리 권한·source scope·수신자 범위를 함께 확인한다.

소유자 정지·권한 회수·source 보관·규칙 변경 때 평가 주체와 scope를 다시 검증하고 필요하면 비활성화하는 안이다. query 오류·예산 초과·외부 채널 장애는 관리 화면에서 확인한다. 알림 시스템 자체 장애를 같은 알림만으로 감시하지 않도록 운영 점검 경로를 둔다.

## 8 규모와 수치 기획

수치는 **사용자 목표 입력 → 제한값 설계 → 격리 측정 → 필요시 목표/지원 범위 조정 → 사용자 합의**로 채운다. 임의 기본값이나 특정 회사 서버 사양을 공통 보장으로 넣지 않는다. 아래 빈칸은 기획 잔여이며 미정 상태로 운영 출시를 승인하지 않는다.

### 대표 workload 입력표

Q15 초기 현황은 서비스 2개·서비스당 로그 서버 2대씩 총 4대이고 중앙은 별도다. 사용자는 서비스를 계속 늘릴 계획이라고 명시했다. 등록/설정으로 서비스와 서버를 추가할 수 있어야 하며 서비스당 서버 수와 수집원/키 수도 현재 값으로 고정하지 않는다. 실제 처리/저장 용량은 로그량·동시성·정상/폭주/복구·증가 workload와 자원 예산으로 설계/측정한다. 근거 없이 제안한 검색 가능 지연 5초는 철회했고 사용자 합의/제품 기본값/고정 대기 주기가 아니다. 운영 기대와 측정 기준을 바탕으로 지연/용량을 후속 제안하며 실시간 화면 갱신·ACK·query 응답과 구분한다.

| query | 시간 범위·page rows·scan/실행 deadline·동시성·응답 bytes·조건 수·필드 수/깊이/값 길이·미래 시각 허용 오차 | 부분/한도/오류와 계속 조회 가능 여부 |
| 조사 UI | 문맥 전후 건수/시간·live rows/bytes·재개 토큰 범위·최대 필드 표시 | 표시 생략·gap·고정 검색 연결 |
| 반출/알림/진단 | export rows/bytes/만료·평가/재알림/재시도·heartbeat/stale·audit 보존 | 상태 공개·반복 비용 제한·필요 작업 차단 |
| 서비스 품질 | query p95·수신→검색 지연·agent 복구 속도·가용성 목표·기존 서비스 지연/오류율/I/O 영향 | 목표 미달을 숨기지 않고 지원 범위 축소 또는 재설계 |

모든 값에 단위·측정 창·입력 규모·정상/폭주/단절/복구 조건·강제 제한 수단·실제 측정 결과를 붙인다. 메모리 queue 크기만으로 process RSS 상한을 입증하지 않는다. CPU 우선순위 설정만으로 강제 ceiling을 보장하지 않는다.

기획 계산식은 용량 가설을 비교하는 용도다. 예를 들어 `사용 가능한 queue payload 여유 bytes / 실제 enqueue bytes/s`는 전송이 중단된 상황에서 추가 읽기를 멈추기까지의 대략적 시간이며 parser/state overhead·파일 삭제·디스크 장애를 포함하는 무손실 시간 보장은 아니다. `복구 송신률 - 신규 유입률`이 양수일 때만 단순 backlog 해소 시간을 계산할 수 있다. 실제 값 없이 숫자 결과를 만들지 않는다.

### 지원과 사용성 표

Q16-01의 요구는 서버별 Linux 배포판/버전·CPU/메모리/디스크·Docker 사용 여부가 달라도 지원하는 것이다. 같은 배포판/버전이나 동일 사양으로의 통일을 전제하지 않고 설치/실행 경로와 서버별 자원 예산 적용을 설계한다. 실제 OS/architecture/filesystem/collector version·입력/TLS/auth/설치 조합의 최소 요구/지원표는 개발팀이 확인/검증하며 정확한 규격 제출은 현재 기획의 선행 조건이 아니다. 첫 출시 브라우저는 Q15-01에 따라 데스크톱 Chrome이다. 화면·언어·접근성도 검증 항목으로 유지한다. 지원 요구·문서 확인·격리 검증·운영 관찰을 구분하고 미검증 조합을 지원 완료로 표시하지 않는다.

## 9 설치와 운영과 복구

Q06의 복원 불가 파일 재개는 누락 안내 후 사용자 명시 선택으로만 제공한다. 적용 시 확인한 파일 끝 위치를 새 기준으로 기록하고 이후 새 이벤트부터 읽는다. 쓰던 이벤트는 D02대로 제외하며 기존 유효 대기 로그는 보존한다. 대상/경계/필수 기록을 안전하게 확인하지 못하면 보류를 유지한다. 정상 재시작/유효 복원에는 적용하지 않고 중앙 하드웨어 재해 복구·과거 가져오기·버퍼 삭제를 추가하지 않는다. UI·권한·동시 조작/재시작·파일 교체·진단/기록 순서는 후속 설계다.

Q16-07 양쪽 부팅 자동 시작·제한된 비정상 종료 재시작/반복 실패 중단·오류 표시와 Q16-08 에이전트 직접 업데이트/호환 버전 수동 되돌림을 유지한다. 각 호스트의 실행 관리 계층이 담당하며 agent 위치/식별·유효 대기·파일 보류와 중앙의 프로그램 재시작 수신 보존/ACK를 지킨다. Q16-04/E01에서 모든 로그 서버와 중앙은 private 서버이며 서로 연결 가능하다고 사용자 확인했다. HTTPS 인증서 기존 관리도 확인했고 Q16-05 설정 적용/재시작의 일시 수집 중단도 합의했고 중앙 업데이트는 개발팀 담당으로 정리했고 다양한 Linux 환경/사양 지원을 요구하고 세부 호환 확인은 개발팀 검증으로 넘겼으며 초기 서비스 2개·로그 서버 총 4대 입력을 확보했고 서비스/서버 증가를 전제로 Q15 운영 기대와 로그량/증가 workload를 확인하고 구체 성능/용량은 측정 후 제안한다. 실제 실행/설치·연결/인증서 설정·AT-18/OT-03/09/10은 미실행이다.

### 초기 설치 제안

Q16-09/Q05-02 정상 중지 합의(2026-11-02): 요청 시 새 읽기/새 전송·재시도를 멈추고 잔여 전송/중앙 ACK를 기다리지 않고 즉시 종료한다. 최소 로컬 정리와 기존 진행 기록/동일 식별·미전송/미확인 대기는 보존하며 다음 실행은 기존 복구/중복 방지 계약을 따른다. 중지 완료와 전송 완료·중앙 미관측을 구분하며 최소 정리/취소·실제 종료 한도·강제 종료/실패는 개발팀 설계/검증이다. 한 연결의 보관/키 폐기·보안 사고 차단과 전체 agent 중지는 별도다. 다음 Q16-10/Q14의 제한된 오류/거부 이력 영속 보관은 추천·미합의다.

Q16-05에서 수동으로 새 설정을 복사/적용한 뒤 진행 기록·동일 이벤트 식별·유효 대기를 보존한 에이전트 재시작과 일시 수집 중단을 허용하기로 합의했다. 앱은 계속 실행하며 실제 적용 version/검사·실패·변경 경계/중단 시간은 설계/검증이다. 중앙의 중단 목표나 원격 자동 변경을 함께 채택하지 않았다. Q16-08 중앙 업데이트는 개발팀 담당으로 사용자 직접/자동 선택 질문을 종료하며 실제 배포·호환/중단·복원은 개발팀 설계다. 자동 업데이트나 중앙 되돌림 기능을 채택한 답변으로 확대하지 않고 에이전트의 기존 수동 업데이트 합의는 유지한다. 다양한 Linux 환경/사양 지원을 요구하고 세부 호환 확인은 개발팀 검증으로 넘겼으며 초기 서비스 2개·로그 서버 총 4대 입력을 확보했고 서비스/서버 증가를 전제로 Q15 운영 기대와 로그량/증가 workload를 확인하고 구체 성능/용량은 측정 후 제안한다.

Q16-01~03 합의/환경 확인: 중앙은 별도 Linux 서버·Docker 사용 가능이고 에이전트는 Linux·Docker 가능/불가 혼재라 비컨테이너 실행 경로가 필요하다. 대상 로그 읽기와 전용 대기 폴더 쓰기 권한은 설정할 수 있다고 확인했다. 실제 계정/최소 권한·경로/volume·상태/진단 쓰기·디스크 여유·구체 패키지/실행·호환성/자원·실제 권한 적용은 후속 설계/검증이다. Q16-07에서 에이전트와 중앙 모두 부팅 자동 시작·비정상 종료의 제한된 자동 재시작·반복 실패 중단/오류 표시를 합의했다. 기존 위치 재개와 수신 완료 기록 보존 원칙을 유지하며 실제 호스트 설정은 실행하지 않았다.

설치 안내에는 필요한 포트/volume/권한·TLS 종료 위치·secret 참조·자원 예산·관리자 bootstrap·합성 이벤트 검증·중단/제거 절차를 포함한다. `.env`나 운영 자격을 공개 예시에 넣지 않는다. agent와 중앙은 독립적으로 중단 가능해야 하며 agent 제거가 원본 로그나 앱 실행을 종료하지 않게 한다.

## 11 후속 기술 설계의 산출물

설계 담당은 합의된 범위 안에서 논리 event schema·관리 객체 수명·ACK 상태표·error/capability·권한 평가·query/cursor·live/export 작업 계약을 작성한다. 상태 변경에는 재시도/중복 방지와 version 충돌 처리를 포함한다. 외부 공개 API는 첫 출시에 두지 않기로 2026-11-05 합의했다([결정 기록](../decisions.md)). 조회·관리 API는 함께 배포하는 웹 화면 전용이며 외부 client용 토큰과 호환 보장을 두지 않는다. 계약 초안은 [API 계약 초안](api-contract-v0.1.md)에 있다.

collector·저장/검색·metadata/queue·backend/auth·packaging별로 한 가지 채택안과 탈락 이유를 남긴다. Q04의 응답 전 후속 전송·미확인 버퍼 유지·프로그램 재시작 보존을 충족하되, 중앙 하드웨어 고장용 별도 복제·자동 장애조치·로그 백업 복구를 추가 요구로 넣지 않는다. 제품·버전·라이선스·보안·호환성은 선정 시 공식 자료로 다시 확인한다. 특정 엔진·프레임워크·수집기·인증 라이브러리는 아직 채택하지 않았다.

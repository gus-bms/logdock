# LogDock 검색과 조사 상세 기획 v0.1

최종 갱신: 2026-11-02. 상태: 최신 합의에 맞춰 통합한 검토 초안. 한 운영팀용 자체 설치형을 대상으로 F03/F04/F05/F07과 F08의 조사 연결을 구체화한다. 확정 상태는 [결정 기록](../decisions.md), 남은 사용자 선택은 [협의 목록 Q01~Q16](../planning/user-decisions-v0.1.md), 범위·완료 기준은 [잔여 기획](../planning/remaining-plan-v0.1.md)을 따른다.

Q01에서 기본 검색/발생량·상세/주변 로그·수집 문제 확인과 제품 완료 기준을 합의했고 검색 조건 저장·오류 알림의 첫 출시 포함과 실시간·내부 공유 링크·파일 내보내기·요청 ID 기반 연관 조회의 후속 구분을 합의했다. 초기 공용 로그인 1계정의 검색 저장 목록을 함께 쓰며 향후 계정 분리 확장을 고려한다. 첫 알림은 건수 기준·이메일, 급증은 후속으로 합의했고 조건 수치·메일 연결 설정·수신 주소 검증/한도는 미정이다. 아래 D11/D12/D14의 세부 동작은 이 출시 구분 아래 검토할 제안이다. 현재 구현은 health API와 연결 확인 화면이며, 이 문서의 화면·API 계약·검증 시나리오는 구현 결과가 아니다.

외부 자료의 확인일은 원본 초안의 조사 기록이다. 이번 통합에서는 외부 자료를 다시 검증하거나 기술 후보를 새로 조사하지 않았다.

2026-11-02 [Q08 기획안](../planning/q08-search-plan-v0.1.md)과 [공식 자료 조사](../research/q08-search-evidence-2026-11-02.md)로 F03을 전수 조사해 3절과 10절에 반영했다. 아래 `Q08-nn`은 2026-11-02 사용자가 모두 A안으로 합의한 결정이고 `SD-nn`은 기획안 5절의 설계 확정 항목이다.

서비스는 분류·검색/필터·집계 기준이며 서비스별 tenant나 권한 경계를 전제하지 않는다. D03의 큰 이벤트 전체 거부와 D04의 앱 출력 본문 중앙화는 합의된 전제다. 인증·권한의 필요 범위와 아래 역할/scope 관련 상세안은 Q10 검토 대상이며, 이 초안을 통합했다는 이유로 채택되지 않는다.

## 1 조사 대상과 공통 정보

목표 사용자는 여러 서비스·서버의 오류 위치와 주변 상황을 찾는 운영자와 개발자다. 오류 조사 중 필터·선택 이벤트·읽기 위치를 유지하고, 결과의 한계와 수집 문제를 구분한다.

| 논리 정보 | 의미와 제안 계약 |
| --- | --- |
| 이벤트 식별 | D06에 따라 동일 이벤트 재전송은 중앙 저장·검색·발생량 집계 한 건. 실제 별도 발생은 구분. 안정적인 조회 참조와 재전송 식별의 생성·검증·관계는 후속 설계이며 timestamp나 본문 hash만으로 유일성을 가정하지 않음 |
| 발생/관측/수신 시각 | 원본 발생, agent 관측, 중앙 수신을 분리. 검색 가능 시각은 실제 관측할 수 있을 때만 제공 |
| 기본 검색 시각 | Q08에서 로그의 발생 시각을 기본으로 합의. 누락/해석 불가는 기존 관측 시각 대체·표시 설계안을 유지하며 재질문하지 않는다. Q02-05에 따라 발생 시각은 미확인으로 두고 별도의 검색 기준 시각만 대체한다(SD-01, SD-02). Q08-05 합의: 관측 시각보다 허용 오차 이상 미래인 시각은 원본을 보존하고 검색 기준만 관측 시각으로 대체해 `시각 의심`을 표시한다. 과거 시각은 보정하지 않는다. Q08-06 합의: 시간대 없는 시각은 연결의 `로그 시간대`로 읽고 미입력이면 에이전트 서버 시간대로 읽어 `시간대 추정`을 표시한다 |
| 출처 | Q07 서비스 지정/수집 등록 후 키 발급, 중앙이 키와 등록정보로 판별한 서비스로 서비스별/통합 조회. 미분류 보관/재분류 안건 제거. 참조/당시 표시 정보·이름 변경 표현은 후속 설계/검토 |
| 로그 흐름 | 파일 identity·stream·instance 등 수집기 capability로 구분. 경로 이름만으로 회전 전후 연속성을 단정하지 않음 |
| 본문과 필드 | 앱 출력 본문과 별도의 typed fields·파싱 성공/일부 실패/실패 표시. 민감정보 처리는 앱 책임. D03 상한 초과 본문은 전체 거부하며 분할·잘림 전송하지 않음 |
| severity | 원본 값과 정규화 값을 구분. 정규화는 TRACE·DEBUG·INFO·WARN·ERROR·FATAL과 미확인. Q02-05에 따라 누락·알 수 없음을 INFO로 바꾸지 않는다(SD-09, SD-10) |
| 연관 ID | 실제 존재하는 request/trace/span ID만 사용. 다른 실행 흐름의 같은 문자열이 같은 요청임을 보장하지 않음 |
| 버전과 품질 | parser/rule/config/schema version, 추정·누락·거부 상태. 일부 상태를 모르면 미확인 |

발생 시각과 관측 시각의 구분은 [OpenTelemetry Logs Data Model](https://opentelemetry.io/docs/specs/otel/logs/data-model/)을 참고했다(2026-11-01 확인). 중앙 수신 시각·출처 snapshot·검색 상태는 LogDock의 추가 제안이며 OTel 채택을 확정하는 것은 아니다. 전송 timestamp의 실제 인코딩과 정밀도는 엔진 평가 후 정하며 브라우저 숫자 변환으로 정밀도가 줄지 않게 계약을 검증한다.

상세의 ‘원문’은 D04에 따라 중앙에 보관된 **앱 출력 본문**을 뜻한다. LogDock은 민감정보 판별·마스킹·내용에 따른 제외·별도 원문 격리 저장을 수행하지 않는다. 파싱·정규화 필드와 화면 접기·표시 생략은 본문과 구분하며 저장 본문을 바꾸지 않는다. 구체 형식·인코딩과 일반 파싱 실패 처리는 Q02 후속 검토 대상이다.

## 2 화면 구조와 이동

| 화면 | 주요 정보와 동작 | 진입과 복귀 |
| --- | --- | --- |
| 로그 탐색 | 시간·출처·severity·본문/필드 조건, 발생량, 목록, 결과 상태 | 기본 조사 진입. 새 검색 전 현재 조건 편집과 적용된 조건을 구분 |
| 이벤트 상세 | 출처·시각·본문·필드·stack trace·품질·주변/요청 연관 전환 | 행 선택. 닫으면 기존 조건·선택·스크롤로 복귀 |
| 실시간 | 필터·연결 상태·pause·새 이벤트 수·화면 한도·누락 가능 구간 | 명시적 시작. 고정 검색과 상태를 혼동하지 않음 |
| 저장 탐색 | 공용 계정 목록의 이름·조건·최근 수정·실행 가능 여부 | 저장 조건을 현재 권한으로 다시 실행 |
| 수집 상태 연결 | 해당 source 상태·마지막 보고·거부·queue·손실 가능성 | 검색/상세에서 권한 있는 진단으로 이동, 복귀 조건 유지 |

첫 출시는 Q15-01에 따라 데스크톱 Chrome을 기준으로 한다. 작은 화면의 패널 전환은 지원 확대 때 검토한다. 구체 breakpoint·컴포넌트·색상·타이포그래피는 기술/디자인 설계 산출물로 남긴다. 표의 상태를 먼저 확정하고 시안에 반영한다.

로그 본문은 실행 가능한 HTML로 해석하지 않는다. 긴 행 접기·줄바꿈·JSON 펼침은 표시 동작이며 저장된 본문을 수정하지 않는다. 본문 속 링크는 자동으로 활성화하지 않고 ANSI 표시는 Q08 설계를 따른다. Q09-04에 따라 상세에서 로그 한 건의 본문과 필드를 복사할 수 있으며 현재 사용자가 볼 수 있는 내용만 포함한다.

## 3 F03 통합 검색

### 조건과 실행

첫 출시는 시각적인 필터 입력만 제공한다. Q08-03 합의로 정규식·엔진 query/SQL 직접 입력은 후속이다. 검색창에서 지원하지 않는 문법을 조용히 부분 실행하지 않는다. 검색·저장 검색·알림은 구조화된 하나의 조건 형식을 쓰고 엔진 쿼리 문자열을 저장하지 않는다(SD-30).

| 조건 | 지원 범위 | 경계 |
| --- | --- | --- |
| 시간 | 기본 검색은 Q08 합의대로 로그의 발생 시각. Q08-04 합의: 검색 화면에서 발생 시각과 수신 시각을 고르고 저장 검색에도 저장하며 결과에 적용 기준을 표시. 범위는 시작 포함·끝 제외(SD-06). 표시 시간대는 배포 설정 하나(SD-07) | 검색 실행 시 상대시간을 고정된 절대 범위로 변환. 페이지 이동 중 범위를 이동시키지 않음. 알림 링크는 수신 시각으로 고정(SD-08) |
| 출처·레벨 | 같은 필드의 여러 선택은 OR, 서로 다른 필드는 AND(SD-13). 출처는 등록 참조로 저장(SD-11) | 권한 없는 값·건수를 후보 목록에 노출하지 않음. `미확인`·`미입력`·`보관됨`은 별도 표시(SD-09, SD-12). 로그 안의 `service`·`host` 값은 출처 분류를 바꾸지 못함 |
| 본문 | Q08 합의: 기본은 대소문자 미구분이며 필요할 때 구분 옵션 사용. Q08-01 합의: 입력을 공백 포함 한 덩어리로 보고 글자 그대로 부분 일치. Q08-02 합의: 본문 제외 제공. 여러 조건은 AND | 저장 본문 전체 비교(SD-14), 특수문자는 일반 문자(SD-15), JSON 이스케이프 문자열 디코드 값 포함(SD-16). Unicode·정규화는 SD-17로 검증. 엔진이 요구를 못 맞추면 합의를 조용히 완화하지 않고 영향을 다시 제시 |
| 구조화 필드 | Q08 초기 지원 합의: 정상 해석한 필드의 값 일치·항목 존재·숫자 범위. Q08-02 합의: 값 다름·항목 없음도 제공하며 정상 해석한 로그에만 적용 | 값 일치는 보이는 값 기준으로 숫자 500과 문자열 "500"이 함께 일치하고 문자열은 대소문자 구분(SD-20). 존재·범위는 SD-21. 일치·불일치·판정 불가의 세 값으로 판단하고 판정 불가는 결과에서 빼고 건수를 표시(SD-22). 타입 충돌로 거부하지 않음(SD-24) |
| 배열·중첩·날짜 | 중첩 객체는 점 경로로 지원. 배열은 항목 존재만, 값 비교와 날짜 범위 비교는 후속(SD-19) | 지원 범위를 화면에서 구분하고 미지원 연산은 비활성화 |
| 복합 조건 | 기본 AND와 필드 내 OR. 임의 괄호는 제공하지 않음 | 정규식은 후속(Q08-03). 등록 때 입력하는 추출 규칙(Q08-07)과 별개. 검색식 길이·조건 수 제한은 측정 후 제안하고 표시 |
| 요청 ID | 서비스 필터 없이 본문 일치·필드 값 일치로 전체 서비스에서 찾음(SD-23) | 결과는 일반 목록. 전용 연관 화면은 Q01 후속 유지 |

사용자는 조건 편집 후 실행한다. facet 선택으로 자동 실행을 제공한다면 요청 취소·동시성·입력 빈도 제한을 함께 적용한다. 조건 오류는 필드와 수정 이유를 표시하고 이전 성공 결과는 ‘이전 조건의 결과’로 표시한다. 오류 상태에서 기존 결과를 새 조건의 성공 결과로 보이지 않게 한다.

### 결과와 일관성

- 목록·histogram·분포는 같은 정규화 조건·권한·절대 시간 범위·조회 세대를 사용한다. 여러 요청을 사용하면 각 완료 상태와 수신 기준을 유지한다. Q08-08 합의: 시간별 발생량과 서비스·서버·레벨별 건수를 제공하고 임의 필드별 건수는 제공하지 않는다.
- 기본은 검색 기준 시각 내림차순과 안정적인 유일 보조 정렬키이고 오래된순으로 바꿀 수 있다. 같은 시각 다건을 timestamp만으로 페이지 이동하지 않는다. 같은 로그 흐름 안에서는 원본 순서를 유지한다(SD-26).
- 페이지는 커서 기반 `더 보기`다. 토큰은 조건·정렬·시간 기준·권한 범위·기준 시점에 묶는다. 권한이 줄거나 토큰이 만료되면 다시 검사하고 재검색을 안내한다(SD-27).
- 실행할 때 검색 가능이 확정된 수신 시점을 잡아 목록·발생량·분포·다음 페이지에 같은 상한을 적용하고 화면에 표시한다. 특정 엔진의 snapshot이나 장기 결과 저장에 의존하지 않는다(SD-28). 이 방식이 요구를 못 맞추면 영향을 다시 제시한다.
- 고정 검색 실행 후 들어온 새 로그와 late event는 재실행에서 반영한다. 당시 결과를 완전한 과거 사실로 보장하지 않으며 수집/검색 지연 정보를 함께 표시한다.
- histogram의 bucket 경계·간격·시간대를 응답에 포함한다. 집계는 표본 없이 정확히 세고 실행 예산을 넘으면 완료 구간만 부분 결과로 표시한다(SD-29). 제한된 목록 행 수를 총 발생량으로 쓰지 않는다.
- 조회 기간에 고정 상한을 두지 않고 실행 예산으로 제한하며 최신 구간부터 처리한다. 검색이 로그 수신과 저장을 밀어내지 않게 한다(SD-31).

조건 변경에는 새 조회 세대를 부여하고 늦게 온 이전 응답이 화면을 덮지 못하게 한다. 서버 취소가 지원되지 않더라도 서버 실행 deadline과 동시성 한도를 적용하는 안이다. 자동 무한 재시도는 하지 않는다.

## 4 F04 상세와 주변 로그

**출시 구분: 요청 ID 기반 여러 서비스 연관 조회는 Q01에서 후속으로 합의했다. 상세·같은 흐름 주변 조회는 Q01, 주변 조회의 레벨/본문 조건 해제·원래 검색/권한 유지는 Q09 합의다. Q09-01~04도 합의했고 순서 식별과 수치 한도는 후속 설계/검증이다.**

상세는 출처·선택 이벤트·조회 기준을 고정한 채 본문, 필드, stack trace를 읽는 흐름이다. 이벤트를 열 때와 추가 데이터를 요청할 때 현재 권한을 다시 적용한다. 보존 만료·권한 변경으로 가져올 수 없으면 목록에 남은 정보가 현재 조회 가능함을 보장하는 것처럼 표시하지 않는다.

| 조사 모드 | 범위 | 조건 전환과 경계 |
| --- | --- | --- |
| 같은 로그 흐름 | 선택 source/instance/stream identity의 앞뒤 이벤트 | Q09-01 합의: 주변 조회에서만 레벨·본문·필드·시간 조건을 풀고 해제 조건 표시. 원래 검색·선택·같은 흐름·현재 권한은 유지. Q09-02 합의: 정상 회전 경계를 넘어 이어 보여주고 경계 표시. 파일 순서를 확인할 수 있을 때만 이어 붙임 |
| 같은 요청 (후속) | 같은 허용 scope와 제한 시간 안의 request/trace ID | 같은 문자열은 상관 후보임을 표시. 시간/서비스 경계를 사용자가 확인할 수 있게 함 |
| 같은 서비스·서버의 근접 시간 | Q09-03 합의: 같은 서비스·서버의 다른 파일 로그를 시간순으로 함께 보는 전환. 일반 출력과 오류 파일이 나뉜 경우와 순서를 확인할 수 없는 경우에 사용 | ‘원본의 인접 행’ 대신 ‘시간상 근접 이벤트’로 표시 |

원본 순서를 제공할 수 있는 경우에만 해당 순서로 앞뒤를 정의한다. 다른 stream의 timestamp를 정렬했다고 원본 인접성을 주장하지 않는다. 추가 로딩은 각 방향의 경계 토큰으로 수행하고 선택 행과 읽기 위치를 유지한다.

주변 범위는 전후 건수와 최대 시간 폭을 함께 제한한다. 정확한 값은 D16에서 정한다. 원본을 수집하지 않았음·거부됨·보존 만료·조회 한도·현재 관측 불가를 관측 가능한 범위 안에서 구분한다. 요청 ID가 없으면 해당 모드를 비활성화하고 stream/시간 조사로 안내한다.

## 5 F05 실시간 조회

**출시 구분: Q01에서 후속으로 합의했다. 첫 버전은 고정 검색을 다시 실행하며, 아래 계약은 후속 검토 자료다.**

실시간은 현재 조건에 맞는 신규 수신 이벤트를 제한된 화면 버퍼로 보는 기능이다. 에이전트 수집·전송 pause와 화면 pause는 별도다. 과거 전체 결과와 라이브 표시를 동일한 완전성 보장으로 묶지 않는다.

| 상태와 전환 | 제안 동작 |
| --- | --- |
| 시작 | 조건·현재 권한을 확정하고 연결 시점/재개 토큰을 기록. 시작 전 이력은 고정 검색으로 조회 |
| 연결됨 | 수신 순으로 추가하고 각 이벤트 발생 시각 표시. 전역 event-time 순서나 원본 순서 보장으로 표현하지 않음 |
| 화면 일시정지 | 자동 스크롤·화면 추가를 멈춤. 수신을 계속하면 정해진 버퍼 안에서만 보유하고 한도와 대기 수 표시 |
| 한도 도달 | 오래된 화면 행을 내보낼 수 있지만 UI에서 제거한 행 수/범위를 표시. 중앙 저장 데이터 삭제와 구분 |
| 재개 | 토큰/cursor의 유효 범위 안에서 중복을 제거하고 복구. 범위를 넘으면 gap 표시와 고정 검색 연결 |
| 재연결 중 | 제한된 backoff로 연결, 마지막 확인 지점과 불확실 구간 표시. 조용한 상태와 연결 단절을 구분 |
| 조건 변경 | 기존 stream 종료 후 새 기준으로 시작. 섞인 결과를 같은 조건의 연속 결과로 표시하지 않음 |
| 권한 회수/로그아웃 | stream 중단, 현재 화면·클라이언트 캐시 정리, 재인증/재조회 안내 |
| 화면/탭 비활성 | 자동 일시정지 또는 연결 종료 정책을 정하고 복귀 시 재연결 경계 표시 |

late event는 발생 시각이 과거여도 신규 수신으로 나타날 수 있다. 이를 별도 표시하고 과거 위치로 자동 삽입해 읽는 행을 이동시키지 않는 안이다. 라이브 복구 토큰의 보존 범위와 최대 지연은 중앙 capability로 공개한다. 브라우저 장기 로컬 저장은 기본안에서 제외한다.

## 6 F07 탐색 저장과 공유와 내보내기

**출시 구분: 검색 조건 저장은 첫 출시 포함, 인증된 내부 공유 링크·파일 내보내기는 후속으로 합의했다. 공용 로그인 계정 하나의 저장 목록을 함께 사용하고 초기 개인/팀 목록 구분은 두지 않는다. 개인별/팀별 저장은 향후 계정 분리 시의 검토 후보로 남긴다.**

검색 조건 저장, 내부 링크, 결과 파일은 서로 다른 객체다. 조건을 저장했다고 해당 로그의 장기 보존이 생기지 않는다.

| 기능 | 제안 범위 | 실패·수명·권한 |
| --- | --- | --- |
| 공용 계정 저장 탐색 (첫 출시) | 공용 계정의 단일 목록에 검색 조건을 저장하고 다시 실행. Q11-01 이름·조건·시간 수정, Q11-02 확인 후 즉시 삭제, Q11-03 자동 삭제 없음·개수 상한 도달 시 저장 차단과 안내 | 같은 계정으로 로그인한 사용자가 목록을 함께 사용. 개인/팀 목록 구분은 없으며 현재 인증·허용 범위를 적용. 이름 중복 금지, 동시 수정 덮어쓰기 전 경고, 보관된 연결 참조는 실행 전 경고 |
| 개인별 저장 탐색 (향후 계정 분리 후보) | 이름·설명·필터·컬럼·시간 방식 저장 | 비밀 token/본문 원문을 이름·설명에 넣지 않도록 안내. 삭제된 필드·source는 실행 전 경고 |
| 팀 저장 탐색 (향후 계정 분리 후보) | 소유자·열람/편집 권한, 버전 충돌 처리 | 타인 변경을 조용히 덮지 않음. 소유자 퇴사/정지 시 이전 또는 보관 정책 필요 |
| 인증된 내부 조건 링크 (후속) | 공유 객체 ID로 조건 참조. 이벤트 ID 링크는 현재 권한 재검사 | 민감 query 본문을 URL에 직접 넣지 않는 안. 타인에게 자동 데이터 권한 부여 없음 |
| 시간 의미 | Q11 합의: 상대/고정 모두 지원하고 저장 시 선택 방식 유지. 상대는 열 때 현재 기준 재계산, 고정은 저장 날짜/시간 그대로 실행 | ‘동일 조건’과 ‘동일 결과’가 다름을 표시. 조사 공유는 고정 범위를 권장 |
| export (후속) | 선택한 고정 조건·시간·현재 권한의 앱 출력 본문과 필드, 한도 있는 다운로드 | 생성/다운로드 시 재검사, 만료·회수·건수/bytes/시간 제한. 결과의 부분 여부·시간 기준·기준 시점 포함. LogDock이 본문을 재마스킹하지 않음 |

공용 목록도 로그인 주체와 귀속 관계를 표현할 수 있도록 후속 설계하며 초기 계정 수를 영구적인 단일 사용자 구조로 고정하지 않는다. 향후 계정을 분리할 때 기존 조건을 공용으로 유지할지, 복사/이전할지와 편집 권한을 별도로 정한다. 공용 1계정이 동시 접속 1개라는 뜻은 아니며 동시 세션 지원과 변경 충돌 처리는 Q10/Q11/Q15에서 구체화한다.

export 형식은 초기 JSON Lines를 우선 검토하고 CSV는 수식 해석 등 반출 위험과 타입 손실을 검토한 뒤 추가하는 안이다. 파일 생성이 비동기면 대기/처리/완료/부분/실패/취소/만료를 구분한다. 한도 초과를 조용히 성공으로 처리하지 않는다. 이미 내려받은 파일은 서버 권한 회수로 회수할 수 없다는 경계를 안내한다.

익명 공개 링크, 결과 snapshot의 장기 저장, 외부 조직 공유, 무제한 다운로드는 별도 채택 전까지 유예한다. Q09-04 한 건 복사는 현재 조회가 허용된 앱 출력 본문과 필드만 대상으로 하며 LogDock이 재마스킹하지 않는다. 저장 초기 포함과 공유 링크/export 후속 구분은 Q01 합의로 유지한다. Q11의 상대/고정 시간 지원·선택 방식 유지 합의와 수정·삭제·수명의 Q11-01~03 합의를 따르며 향후 계정 분리 시 기존 저장 조건의 귀속/이전·공용 유지 정책을 별도로 정한다. 후속 반출 세부는 재검토 시 정한다.

## 7 F08 알림에서 조사로 연결

2026-11-02 Q12 세부 협의를 정리했다. 조사 링크는 불투명 사건 ID를 쓰고, 열 때 사건의 조건과 평가 구간을 수신 시각 기준으로 고정하며, 당시 건수와 현재 건수의 차이와 사유를 표시한다. 상세는 [Q12 기획안 5절](../planning/q12-plan-v0.1.md#5-상태와-전달-계약)을 따른다. 알림 이력은 로그 보관 기간과 같다.

**출시 구분: 오류 알림은 Q01에서 초기 포함, Q12에서 건수 기준·이메일·중앙 수신 시각 집계·기본 검색 필터·규칙별 시간 구간/임계 건수·수신 목록·요약/조사 링크·제한된 메일 재시도·기준 미만 일정 기간 후 해소와 지속 중 최초 한 번·해소 후 재발 시 새 발송을 합의했다. 규칙마다 시간 구간과 임계 건수를 설정할 수 있다. 평소 대비 급증은 후속이다. 회복 메일 생략과 규칙별 한 개 이상의 수신 주소 지정을 합의했다. 메일의 요약·로그인 후 조사 이동 링크와 원문 로그 본문 제외도 Q12 합의다. 구체 문구/링크와 UI/API는 후속 설계다. F07 내부 공유 객체를 첫 출시에 추가하는 합의가 아니다.**

Q12 알림 집계 대상에도 서비스/서버·레벨·본문·정상 해석 필드의 값 일치/존재/숫자 범위를 사용한다. 본문 대소문자 정책은 Q08을 따르고 필드 값 비교에 자동 적용하지 않는다. 집계는 중앙 수신 시각이며 구체 타입/문법·누락/해석 불가·조건 조합·평가 예산은 설계/검증이다.

Q12 해소는 정상 평가 건수가 임계 미만인 상태를 정한 기간 유지한 뒤 확정한다. 대기 중 다시 기준 이상이면 같은 지속 상황으로 유지하고 해소 확정 후 재발하면 새 오류 메일을 보낸다. 회복 메일은 생략하며 실제 대기 시간/평가 주기·미관측/실패·상태 기록/복원은 후속이다.

Q12 메일 전송 실패 수신자는 간격을 두고 횟수/총 대기 시간 상한 안에서 재시도하며 성공 확인 주소는 제외하고 상한 후 최종 실패를 표시한다. 해소 후 대기 메일은 계속 전송하고 해소 사실을 표시하며(Q12-11), 전송 여부 불명은 같은 Message-ID로 재시도한다(2026-11-02 Q12 합의). 실제 한도/간격·중복 제어 세부는 설계다.

Q12 합의에 따라 메일에는 규칙명·오류 건수·집계 시간 구간 등 요약과 로그인 후 여는 조사 이동 링크를 담는다. 원문 로그 본문은 메일 본문/첨부에 포함하지 않는다. 규칙별 수신 목록·현재 접근 범위·표시할 추가 요약 항목과 메시지 길이/출력 처리는 D14 설계에서 검증한다.

알림에서 탐색을 열 때 알림 조건과 평가에 사용한 **중앙 수신 시각 기준·절대 시간 범위**를 유지한다. 조건 수정 뒤 원래 평가 조건을 찾는 방식·링크 식별·현재 로그인/권한/보존 처리의 구체 계약은 후속 설계다. 수신 시각으로 평가한 알림을 발생 시각 검색으로 바꿔 열지 않는다. 일반 검색의 기본은 Q08에서 발생 시각으로 합의했으며 알림 집계는 Q12에서 중앙 수신 시각으로 합의했다. 알림에서 이동하는 조회는 중앙 수신 시각과 평가한 절대 기간을 유지하도록 설계하며 구체 UI/API·현재 권한/보존 적용은 별도 계약이다. 현재 조회 권한·보존·late event 때문에 현재 결과가 평가 당시와 달라질 수 있음을 표시한다. 평가 결과를 재현 가능한 snapshot으로 보장하려면 별도 보존 계약이 필요하다. 상세 상태 전이와 전달은 [관리·운영 명세](platform-operations-v0.1.md)를 따른다.

## 8 공통 사용성과 접근성

- 필터·목록·상세·pause·오류 안내는 키보드로 접근하고 상세 종료 시 원래 행으로 초점을 돌린다.
- 심각도와 실패를 색상만으로 구분하지 않는다. 상태명·아이콘의 의미를 함께 제공한다.
- 실시간 유입은 포커스·선택 행을 빼앗지 않고 보조기기에 모든 행을 고빈도로 읽히지 않게 한다.
- 긴 JSON·stack trace·넓은 필드에서 접기·복사·줄바꿈과 최대 표시량을 명시한다. 화면의 표시 생략과 D03의 이벤트 전체 거부를 구분하며 저장 본문 잘림을 전제하지 않는다.
- 시간대·고정/상대시간·실제 적용 범위는 검색/공유/export에서 함께 확인할 수 있게 한다.
- 첫 출시 지원 브라우저는 Q15-01에 따라 데스크톱 Chrome이다. 화면 크기·국제화·접근성 평가 수준은 D16의 지원표와 연결한다. 한국어 UI 우선과 영어 확장 가능 구조를 검토안으로 둔다.

## 11 확정할 입력

D12에서는 기본 발생 시각·본문 대소문자 옵션·필드 세 연산의 초기 지원 합의를 유지한다. 본문 일치·추가 연산·수신 시각·미래 시각·시간대·텍스트 인식·분포는 [Q08 결정표](../planning/q08-search-plan-v0.1.md#3-사용자-결정-일괄-요청) 8개 합의를 따르고, 타입·정렬·페이지 일관성은 SD로 설계 확정했다. 라이브 복구 수준은 후속 검토에 남는다. D14에서 F07/F08 단계와 반출 범위를 정한다. D16에서 page/시간/scan/timeout/동시성·문맥·화면 버퍼·export·지원 브라우저 수치를 채운다. D17에서 이를 만족하는 API와 엔진 capability를 증명한다. 값이 없거나 지원 근거가 없는 기능은 출시 가능으로 판정하지 않는다.

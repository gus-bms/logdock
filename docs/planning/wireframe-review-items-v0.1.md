# 와이어프레임 검토 항목 정리표 v0.1

작성일: 2026-11-05. **상태: 검토 항목 91건의 처리를 정했다. 사용자 합의 2건, 문서로 정리 12건, 설계로 넘김 77건.** 설계로 넘긴 항목의 기본안은 화면·API 설계에서 확정하며 사용자 합의가 아니다. 화면 구현·실행 검증은 하지 않았다.

[와이어프레임](../wireframes/index.html)을 그리며 문서에 답이 없어 남긴 `검토 항목`을 정리했다. 기준은 [화면 흐름 명세](../specs/screen-flows-v0.1.md)와 [결정 기록](../decisions.md)이다. 와이어프레임 주석은 같은 번호(WQ-nn)로 이 표를 가리킨다.

## 1 처리 기준

| 처리 | 뜻 | 건수 |
| --- | --- | --- |
| 사용자 합의 | A안·B안으로 사용자 답을 받아 결정 기록에 반영했다 | 2 |
| 문서로 정리 | 기존 합의·설계 확정에 답이 있거나 명세끼리 어긋난 점이다. 명세와 와이어프레임을 고쳤다 | 12 |
| 설계로 넘김 | 사용자 정책이 아니라 화면·API 설계에서 정할 점이다. 기본안을 적고 설계에서 확정한다 | 77 |

처음 사용자 판단 후보로 본 주제 3개(서비스 이름·운영 수신 주소 변경, 보관할 때 남은 대기, 서비스 재활성)는 기존 합의를 적용하면 답이 나와 `설계로 넘김`에 넣고 결과에 `기존 합의 적용`이라고 적었다(WQ-52·53·55·81·88).

`정하는 곳`은 2026-11-05 API 계약 초안과 디자인 시스템을 병행하기로 하면서 나눴다. `API` 46건은 서버가 판정·기록·상태 전이·권한을 정하는 항목으로 api-contract-draft에서 확정하고, `화면` 31건은 서버가 준 값을 어떻게 보이고 안내할지 정하는 항목으로 design-system에서 확정한다. 다른 쪽 항목을 바꿀 이유가 생기면 자기 작업 파일에 적고 사용자에게 알린다.

## 3 반영과 남은 일

- **명세:** `문서로 정리` 항목을 [화면 흐름 명세](../specs/screen-flows-v0.1.md) UI-02·UI-04·UI-06·UI-07·UI-08·UI-12·UI-14에 반영했다.
- **와이어프레임:** UI-02 상태 18, UI-04 상태 5, UI-12 상태 4를 고치고 UI-06 상태 8, UI-08 상태 7, UI-14 상태 7·8을 더했다. 주석의 `검토 항목:`을 WQ 번호와 처리 결과로 바꿨다.
- **그림과 다른 기본안:** WQ-10, WQ-31, WQ-37, WQ-42, WQ-61, WQ-73, WQ-76, WQ-82, WQ-83, WQ-87은 지금 그림과 다르거나 그림에 없다. 화면 설계에서 기본안을 확정할 때 그림도 고친다.
- **확인 범위:** 정적 문서 대조와 로컬 브라우저 렌더링만 했다. 구현·API·실행 검증은 하지 않았다.

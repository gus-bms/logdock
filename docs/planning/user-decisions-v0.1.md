# LogDock 기획 리뷰와 사용자 협의 목록 v0.1

최종 갱신: 2026-11-02. 상태: 재검토·상세 초안 통합 후 협의 목록. 합의된 상태는 아래에서 구분하며, 나머지 선택지·검토안은 사용자 결정 전이다. 문서 통합만으로 새 정책 채택·구현·운영 검증을 뜻하지 않는다.

## 1 읽는 방법과 검토 자료

이 문서는 진행된 기획을 대조하고, 이미 합의한 사항을 제외한 **사용자 판단이 필요한 선택**을 추린 것이다. Q01~Q16은 협의 묶음이며 한 번에 승인받는 체크리스트가 아니다. 각 묶음 안에서도 선택·축소·유예할 수 있다.

**Q01 첫 출시의 최소 기능 범위와 완료 기준은 합의 완료(2026-11-01)**다. 검색 조건 저장과 오류 알림은 첫 출시에 포함하고, 실시간 조회·내부 공유 링크·파일 내보내기·요청 ID 기반 연관 조회는 후속으로 두기로 합의했다. 검색 저장은 공용 1계정의 단일 목록을 함께 쓰고 향후 계정 분리 확장을 고려하기로 합의했다. 첫 알림은 건수 기준, 평소 대비 급증은 후속으로 합의했다. 초기 수신 채널은 이메일로 합의했다. Q08에서 기본 검색은 로그의 발생 시각 기준으로 합의했다. 사용자 요청에 따라 기존 시각 대체 설계안과 합의 상태는 유지하고 같은 질문을 반복하지 않는다. 본문 검색은 기본 대소문자 미구분·선택적 구분 옵션으로 합의했다. 필드 검색은 값 일치·항목 존재·숫자 범위를 초기 지원으로 합의했다. 새 로그는 기존 고정 검색 재실행으로 확인하며 Q09 주변 조회의 레벨/본문 조건 해제·원래 검색 유지도 합의했다. Q11 상대/고정 시간 모두 지원·선택 방식 유지도 합의했다. 메일 세부 협의는 보류하고 남은 사용자 선택·설계 항목을 일괄 보고한다. 검색 연산·보존일·저장/알림 설정 등은 해당 Q의 상세 협의로 이어간다. 수집·설치 쪽은 Q02-01 에이전트 설치 대상 Linux를 확인했다. ## 2 다시 협의하지 않을 기존 합의

| 범위 | 유지할 합의 |
| --- | --- |
| 제품과 초기 대상 | 범용 Apache 2.0 프로젝트. 기존 기획의 D09 합의 기록은 한 운영팀용 자체 설치형이다. 중앙 SaaS·과금·여러 조직 격리는 초기 대상에 포함하지 않는다. 실제 설치 패키지·규모·인증 방식은 별도다. |
| 서비스 구분 | 서비스 지정·수집 등록 확정 후 키 발급. 중앙은 키와 등록정보로 서비스를 판별해 서비스별/통합 조회. 서비스 없는 등록의 키 발급·미분류 보관/재분류는 제외. tenant/권한 경계가 아니며 키 범위/개수는 Q10-07 합의, 실제 등록/입력 묶음·UI/schema·이름/수명은 후속 설계/검토. |
| 기존 서비스 보호·D01 | 기존 버퍼 보존, 추가 읽기 일시정지, 자원 예산 안에서 복구. 앱의 동기 요청 경로에 중앙 전송 대기를 추가하지 않음. 원본 rotation·삭제의 손실 경계 표시. |
| D02 최초 연결 | 신규 로그부터 시작. 파일별 시작 위치 확정이 기준이며 연결 당시 쓰던 이벤트는 제외. 한 줄은 줄바꿈, 여러 줄은 수집원별 새 이벤트 시작 규칙 사용. 판별 불가 시 해당 파일은 설정 확인 필요 대기. |
| D02 파일 발견·복구 | 신규 생성 확인 파일은 처음부터, 생성 시점 불확실한 미등록 파일은 발견 시 끝 위치부터. 기존 추적 파일의 기록 유실에는 이 규칙을 재적용하지 않음. 안전한 위치·동일 이벤트 식별을 복원할 수 있으면 재개하고 근거가 없으면 해당 파일 자동 읽기 보류. |
| 과거 가져오기 | 최초 수집 경계 이전 로그를 별도로 가져오는 기능은 구현 범위에서 제외. 정상 장애 후 밀린 로그 재개와 구분. |
| D03 큰 이벤트 | 상한 초과 이벤트 전체 본문 거부. 거부 사유·관측 시각·수집원·확인된 건수·적용 상한을 본문 없이 확인 가능하게 함. 분할·잘림은 채택하지 않음. 1MB는 설명용 예시이며 상한 미정. |
| D04 민감정보 | 각 앱이 출력 전에 처리. LogDock은 앱 출력 본문을 민감정보 판별·마스킹·내용에 따른 제외 없이 중앙화. 제거 실패 차단·원문 격리 저장은 범위에서 제외. |
| D05 기본·사용 불가 처리 | 전송 대기는 제한된 디스크 버퍼가 기본. 사용 불가 시 자동 메모리 전환 없이 영향받는 수집 대기/오류와 사용자 가시성 제공. 기존 버퍼 보존, 필수 상태 기록 불가 시 해당 전송도 안전 정지, 정상 확인 후 제한 재개. 전체 예산·D01/D06 유지. 수치·지원 수단·기록 확정/복구 범위는 후속 설계다. |
| D06 중복 방지 | 재전송된 동일 이벤트는 중앙 저장·검색·집계 한 건. 같은 본문의 실제 별도 발생은 각각 유지. 식별 방식·유지 기간·보장 범위는 후속 설계. |
| 에이전트와 중앙의 책임 | 에이전트는 수집·대기·중앙 전송까지. 중앙 수신 이후 저장·색인·검색·보존은 중앙 책임. 에이전트가 중앙 저장소나 검색 완료를 직접 검사하지 않음. 전송 완료/버퍼 정리 인터페이스는 후속 설계. |
| Q04 전송·중앙 보호 범위 | 중앙 프로그램 재시작 후 수신 완료 로그 보존, 이를 충족하는 기록 확정 뒤 완료 응답. 응답 전에도 한도 안에서 후속 전송, 미확인 로그 버퍼 유지·같은 식별 재시도. 중앙 서버/디스크 고장 대비 별도 복제·자동 장애조치·로그 백업/복구 보장 제외. 검색 지연 목표·수치/구현은 후속 설계. |
| Q05 키 문제와 보관 위치 | 못 보낸 로그는 에이전트 서버 디스크의 별도 전용 폴더/대기 파일에 유지. 키 사용 불가 시 전송 보류, 원래 수집원에 대한 새 키의 유효 전송 권한 확인 후 재개. 가득 차면 D01 추가 읽기 pause, 앱은 원본 기록 지속. 구체 폴더/형식/용량·기록/정리 순서는 후속 설계. |
| Q06 복원 불가 시 재개 | 자동 읽기 보류를 유지하되 누락 안내 후 사용자가 ‘지금부터 다시 수집’을 선택 가능. 적용 시 끝 위치 뒤 새 이벤트 재개·기존 유효 대기 데이터 보존. 파일/경계/필수 기록 확인 불가 시 보류 유지. 상세 UI/권한·정합성·검증은 후속 설계. |
| Q01 첫 출시 범위·완료 기준 | 연결/수집·기본 검색/발생량·상세/주변 로그·수집 상태·키/관리 이력·기본 보존/용량과 제품 완료 기준 합의. 검색 조건 저장·오류 알림도 첫 출시 포함. 실시간 조회·내부 공유 링크·파일 내보내기·요청 ID 기반 연관 조회는 후속. 검색 저장은 공용 1계정의 목록 공동 사용으로 합의했다. 알림은 건수 기준으로 시작하고 급증은 후속이다. 초기 수신 채널은 이메일이다. 조건 수치·메일 연결 설정·수신 주소 검증/한도 등 세부와 후속 기능의 구체 단계는 미정. |
| Q08 기본 검색 시각 | 로그에 기록된 발생 시각을 기본 검색 기준으로 사용. 검색 화면에서 수신 시각도 선택 가능(Q08-04). 미래 시각은 원본 보존·검색 기준만 관측 시각으로 대체(Q08-05). 시간대 없는 시각은 연결의 선택 입력값, 미입력 시 에이전트 서버 시간대로 해석(Q08-06). 알림은 Q12 중앙 수신 시각, 보존은 Q13 최초 중앙 수신 기준. |
| Q08 본문 검색 | 글자 그대로 부분 일치(Q08-01). 기본은 대소문자를 구분하지 않고 필요할 때 구분 옵션 사용. 본문 검색에 적용하며 구조화 필드·ID 값 비교는 별도. |
| Q08 필드 검색·연산 | 정상 해석한 필드의 값 일치·항목 존재·숫자 범위 초기 지원. 본문 제외·값 다름·항목 없음도 검색과 알림에 포함(Q08-02). 정규식·직접 쿼리는 후속(Q08-03). |
| Q08 일반 텍스트 인식·분포 | 흔한 형식은 내장 패턴으로 시각·레벨을 읽고 안 맞는 연결만 추출 규칙을 선택 입력(Q08-07). 시간별 발생량과 서비스·서버·레벨별 건수 제공(Q08-08). |

### 협의 제시 방식

2026-11-02 사용자 요청에 따라 사용자 판단이 필요한 안건은 A안·B안으로 제시해 문자로 바로 답할 수 있게 한다. 각 안에 실제 동작·감수할 영향·쉬운 예시를 적고 추천안을 표시한다. 안이 더 필요하면 C안처럼 문자를 이어 붙이고 한 문자에 한 가지 동작만 둔다. 기준은 [AGENTS.md](../../AGENTS.md)를 따른다.

### 잔여 협의 집계 기준

2026-11-02 사용자 요청에 따라 **합의를 반영할 때마다 완료 내용과 잔여 협의 수를 함께 보고한다. 현재 잔여는 1개 범위**다. 단위는 중복을 제거한 최상위 Q ID이며 세부 질문 수나 개발 작업 수가 아니다. 부분 합의가 생겨도 해당 Q에 다른 사용자 판단이 남으면 수는 유지한다. Q05/Q07/Q10 전용 표의 하위 선택 수와 이 집계를 합산하지 않는다.

Q08·Q09·Q11·Q12·Q13 사용자 협의 정리를 반영해 전체 잔여는 **1개 범위(Q15)**다. 공유 문서의 최신 합의를 대조해 재집계한다.

| Q ID | 현재 남은 사용자 협의 범위 | 상태 |
| --- | --- | --- |
| Q15 | Q15-01~03 합의. 지연·용량 수치는 로그량 측정 뒤 제안. | 유보 |

Q01·Q05·Q07·Q08·Q09·Q10·Q11·Q12·Q13·Q14는 명시한 사용자 범위를 정리했고, Q02·Q03·Q04·Q06·Q16은 독립 기본 정책/환경 합의를 정리해 설계/검증으로 넘긴 범위라 잔여 수에서 제외한다. 이는 상세 설계·기술 선정·구현/실행 검증 완료 선언이 아니다. 공유 정책은 원래 Q에서 한 번만 관리하고 수치/권한·기록/정리/실패/복구·신선도/정합성은 개발팀 후속이다. 초기 범위 안의 미정/유보 사용자 협의는 포함하고 유예 기능·개발팀 구현/실측/시험은 제외한다.

공유 문서의 최신 상태를 읽어 매번 재집계한다. 새 사용자 영향 정책이 발견되거나 범위가 바뀌면 해당 Q를 다시 포함하고 이유를 보고한다. 이미 합의한 내용을 수를 줄이기 위해 재승인받지 않는다.

Q01의 범위 협의는 완료했다. 아래 남은 상세 정책·수치·검증은 각 Q/설계에서 이어간다. 범위 문서 완료와 실제 제품의 출시 가능 상태는 구분하며 구현·실행 검증을 완료했다고 보고하지 않는다.

- **후속 협의:** 기본 검색의 발생 시각 기준은 Q08에서 합의했고 시각 대체 질문은 사용자 요청으로 반복하지 않고 본문 검색은 기본 대소문자 미구분·선택적 구분 옵션으로 합의했다. 필드 검색은 값 일치·항목 존재·숫자 범위를 초기 지원으로 합의했다. 새 로그는 기존 고정 검색 재실행으로 확인하며 Q09 주변 조회의 레벨/본문 조건 해제·원래 검색 유지도 합의했다. Q11 상대/고정 시간 모두 지원·선택 방식 유지도 합의했다. 메일 세부 협의는 보류하고 남은 사용자 선택·설계 항목을 일괄 보고한다. 지원/형식은 Q02, 서비스/객체 수명은 Q07, 검색/상세는 Q08/Q09, 인증/키/감사 세부는 Q10, 저장 수명/시간 의미는 Q11, 메일 발송/수신자·조건 수치·해소 판정은 Q12, 보존·진단은 Q13/Q14, 수치/운영 목표는 Q15/Q16으로 연결한다. 기술/API는 설계에서 구체화한다.
- **유예 영향:** 첫 버전에는 자동으로 로그가 올라오는 live, 동료에게 전달할 내부 공유 링크, 결과 파일 다운로드, 여러 서비스의 같은 요청을 모으는 전용 조회가 없다. 유예 세부 정책은 첫 출시 필수 협의에서 분리하며 후속 단계·일정은 아직 정하지 않았다.
- **재검토 조건 제안:** 배포 중 지속 관찰은 live, 공동 조사는 내부 링크, 보고/외부 분석은 export, 여러 서비스의 한 요청 추적은 연관 조회를 다시 검토할 계기다. 이 조건은 검토 제안이며 후속 출시 약속이 아니다.
- **연결:** F01~F10, D10~D18, P02 및 각 상세 P/Q. R1 최소 범위·제품 완료 기준과 후속 기능 구분은 합의했고 R2/R3 세부 순서·일정·인력·기술은 미정이다.

### Q02 처음 지원할 로그와 실행 환경은 무엇인가

**상태: 중앙 경로 입력·단일 파일/파일명 규칙 지정 지원 합의, 에이전트 설치 대상 Linux 확인(2026-11-01). 일반 파일/journald 초기 지원 합의. 일반 텍스트·JSON·여러 줄 초기 형식도 합의. UTF-8 초기 지원도 합의. 세부 지원 조합/인코딩 오류·형식 처리·패턴/journal 설정·한도는 미정.**

합의한 지정 방식은 app.log 같은 단일 파일과 app-*.log 같은 파일명 규칙이다. Q02-06에서 지정한 폴더 안에서만 탐색하고 필요한 하위 폴더는 별도로 지정하기로 합의했다. 최초/발견/재시작 파일의 읽기 시작은 기존 D02, 탐색/파일/자원 한도는 기존 보호 원칙을 적용한다. 구체 패턴 문법·경로/파일 종류 지원과 규칙 겹침·탐색 주기·상한은 설계/검증하며 과거 가져오기·전체 디렉터리 자동 탐색을 추가하지 않는다.

- **확인한 환경:** Q02-01 에이전트 Linux와 후속 Q16-01 중앙 Linux를 확인했다. 양쪽 배포판/버전·아키텍처·파일시스템·설치/실행 제약과 지원 검증은 남아 있다. 모든 Linux 조합이나 특정 실행 방식을 채택한 것은 아니다.
- **입력 합의 Q02-02:** 일반 로그 파일과 journald를 모두 초기 수집 대상으로 지원한다. 기존 파일과 journal에 기록된 컨테이너/실행 서비스 출력을 읽는 범위이며 모든 Docker driver·호스트 전체 journal·원격 journal·syslog/앱 SDK를 자동 포함하지 않는다. Docker json-file 드라이버 파일은 첫 출시에서 직접 읽지 않고 컨테이너 로그는 journald로 읽는다(2026-11-03, [결정 기록](../decisions.md)). 서비스/수집 등록 선행과 신규 로그·대기 보존·복구/중복 방지·자원 보호를 유지한다. journal 대상 지정/경계/진행 위치·권한·설정/운영 검증은 [수집 명세](../specs/collection-agent-v0.1.md#journald-입력-q02-02)에 남긴다.
- **형식 합의 Q02-03:** 일반 텍스트·JSON·여러 줄 로그를 모두 초기 지원한다. 여러 줄은 이미 합의한 수집원별 새 이벤트 시작 규칙과 D02의 쓰던 이벤트 제외/판별 불가 시 대기를 유지한다. 본문 지원 채택이며 내장 parser/규칙·필드 추출·JSON 구조/여러 줄 JSON 처리·조립 한도나 실제 구현/검증 완료를 뜻하지 않는다.
- **인코딩 합의 Q02-04:** 초기에는 UTF-8을 지원하고 EUC-KR/CP949 등 다른 인코딩은 실제 필요 확인 시 추가 지원을 구체화한다. BOM/줄 구분·부분/잘못된 문자·지원 외 인코딩의 오류/표시 계약은 설계/검증 과제로 남긴다. 자동 감지/변환·문자 치환·본문 폐기를 이번에 채택하지 않았다.
- **일반 파싱 실패 합의 Q02-05:** 지원 조건/이벤트 경계가 유효하나 항목 해석만 실패하면 본문을 그대로 중앙 전송하고 형식 해석 실패를 표시한다. 확인 불가 항목은 미확인으로 남기고 다음 로그도 계속 수집한다. 기존 D01/D05·전송/복구/중복 방지를 유지하고 인코딩 오류·D02 경계 불명·D03 크기 초과와 구분한다. 세부 계약/미실행 검증은 [수집 명세](../specs/collection-agent-v0.1.md#일반-파싱-실패-q02-05)를 따른다.
- **탐색 범위 합의 Q02-06:** 지정 폴더 안의 파일만 탐색하고 필요한 하위 폴더는 별도로 지정한다. 문법/경로·symlink·중복 일치·오류·탐색/자원 한도와 실제 검증은 [수집 명세](../specs/collection-agent-v0.1.md#파일-탐색-범위-q02-06)의 후속 과제로 남긴다.
- **후속 입력/설계 Q02-07~08:** 실제 교체/원본 보관·driver/권한은 후속 환경 입력으로, 오류별 의존 범위·조치 안내/진단은 기존 D02/D05 적용표와 미실행 검증으로 구체화한다. 기존 합의를 새 정책 선택으로 재질문하지 않는다. 두 앱의 대표 설정은 [Q02-07 정적 조사 메모](q02-q16-handoff-v0.1.md#q02-07-대표-설정-정적-조사)에 남겼다. 레벨 임계로 겹치는 기본 출력의 대표 흐름 선택은 해당 사례의 설치/등록 때 참고할 미합의 추천이며 전체 서비스에 강제할 제품 규칙이 아니다. 이 선택을 범용 기획의 선행 조건으로 삼지 않고 서비스별 입력 위치/형식 등록 구조를 유지한다. 사용자가 확인한 컨테이너의 Docker driver는 journald다(2026-11-02). 2026-11-03 실측에서 같은 서버의 웹·워커는 json-file이었고, 운영 쪽에서 journald로 통일하기로 했다. 그 밖의 대상과 호스트 보관은 미확인으로 후속 설치 입력/검증에 연결한다. Q02-08은 기존 D02/D05 적용/설계 검증으로 정리해 재승인받지 않고 중앙 별도 서버 배치는 합의했고 중앙 OS도 Linux로 확인했고 중앙 Docker 사용 가능도 확인했고 에이전트 Docker 혼합 환경도 확인했고 읽기/전용 대기 쓰기 권한 설정 가능도 확인했고 재부팅 후 에이전트 자동 시작도 합의했고 비정상 종료의 제한된 자동 재시작도 합의했고 에이전트 수동 업데이트도 합의했고 호환 이전 버전 수동 되돌림도 합의했고 중앙 자동 시작/제한된 재시작도 합의했고 Q16-04에서 모든 대상의 private 상호 연결 가능을 확인했고 HTTPS 인증서 기존 관리도 확인했고 Q16-05 설정 적용/재시작의 일시 수집 중단도 합의했고 중앙 업데이트는 개발팀 담당으로 정리했고 다양한 Linux 환경/사양 지원을 요구하고 세부 호환 확인은 개발팀 검증으로 넘겼으며 초기 서비스 2개·로그 서버 총 4대 입력을 확보했고 서비스/서버 증가를 전제로 Q15 운영 기대와 로그량/증가 workload를 확인하고 구체 성능/용량은 측정 후 제안한다. 단일 파일/이름 규칙과 오류 가시성 자체는 다시 묻지 않는다.
- **검토안:** 채택한 일반 파일/journald·일반 텍스트/JSON/여러 줄·UTF-8의 세부 처리/지원 조합·구현은 설계/검증한다. BOM/줄 구분·부분/잘못된 문자·지원 외 인코딩 오류 계약은 아직 미정이다. 일반 파싱 실패의 기본 처리는 위 합의를 유지하고 schema/일부 필드·표시/검색/집계·진단과 실제 검증을 설계한다. 다른 OS·network syslog·앱 SDK는 별도 필요성이 있을 때 검토하는 안이다.
- **영향과 입력:** 지원 범위를 늘리면 설치·권한·rotation·자원 한도·복구 검증 조합이 늘어난다. 실제 필요한 OS/실행 방식과 합성 로그 형식 예시가 필요하다. 운영 로그 원문·주소·자격증명 제출을 요구하지 않는다.
- **연결:** D07, F02, P04. 여러 줄 경계 처리 원칙은 이미 합의했으며 구체 규칙과 지원표만 남아 있다. 과거 가져오기는 선택지에 넣지 않는다.

### Q03 전송 대기 로그를 디스크에도 보관할 것인가

**상태: 기본·사용 불가 처리 원칙 합의(2026-11-01). 수치·지원 수단·보장 계약은 후속 설계/검증.**

- **합의한 것:** 전송 대기 로그의 기본 저장 방식은 크기가 제한된 디스크 버퍼다. 디스크 용량·읽기/쓰기 속도·공유 volume 여유와 전체 CPU/메모리를 관리하며 포화/복구에도 D01/D06을 유지한다.
- **추가 합의:** 공간 부족·권한 부족·쓰기 오류로 디스크를 사용할 수 없으면 자동 메모리 대체 없이 해당 수집을 대기/오류로 처리하고 사유·영향·중단 여부를 사용자에게 표시한다. 기존 버퍼를 보존하며 전송 완료/위치 기록도 안전하게 남길 수 없으면 해당 전송도 멈춘다. 원인 해결과 상태 정상 확인 후 기존 위치부터 제한 재개한다.
- **영향과 후속 설계:** 디스크를 요구하므로 환경이 준비되지 않으면 수집이 대기할 수 있다. 진단 경로까지 영향을 받으면 중앙에서 미관측을 표시하고 마지막 상태를 현재 정상으로 간주하지 않는다. 실제 크기·여유 공간·쓰기 속도·보고 신선도·확정/복구 조건·재개 검증 수단은 설계와 측정 후 정한다. 디스크 자체 손상·기록 확정 이전 데이터까지 무손실을 보장하지 않는다.
- **연결:** D05, P05. D04 앱 출력 본문과 본문 없는 진단을 유지한다. 중앙 전달 완료 뒤의 보존 수준은 Q04에서 별도로 협의하며 수집기 제품·기본 용량은 아직 선택하지 않았다.

### Q04 중앙이 전달 완료라고 답한 로그를 어느 장애까지 지킬 것인가

**상태: 전송·보존 원칙과 장애 보호 범위 합의(2026-11-01). 검색 지연 목표·실제 한도·구현 계약은 후속 설계/검증.**

**책임 구분:** 에이전트는 수집·대기·중앙 전송까지, 수신 이후 저장·색인·검색·보존은 중앙 책임이다. 에이전트는 중앙의 전송 응답만 확인하며 중앙 저장소/검색 결과를 직접 검사하지 않는다.

- **합의한 보존:** 중앙은 프로그램 종료·재시작 후에도 로그를 유지할 기록 확정 뒤 수신 완료 응답한다. 메모리 수신만으로 완료 응답하지 않는다. 완료 응답과 검색 가능 상태는 구분한다.
- **합의한 전송:** 앞선 응답 전에도 정해진 한도 안에서 다음 로그를 보낸다. 미확인 로그는 버퍼에 유지하고 같은 이벤트 식별로 재시도한다. 미확인 전송 한도에서는 새 전송을 기다리고, 디스크 버퍼 포화에서는 D01 추가 읽기 pause를 적용한다. 승인·명시적 거부·재시도를 구분하는 구체 계약은 후속 설계다.
- **합의한 제외:** 중앙 서버/디스크 고장에 대비한 별도 복제·자동 장애조치·로그 백업/복구 보장은 구현하지 않는다. 그 상황에서 이미 수신 완료한 로그가 유실될 수 있으며 에이전트에 재해 복구용 재수집 책임을 추가하지 않는다. 앞선 백업 복구 추천은 채택하지 않는다.
- **유지할 동작:** 저장 장치가 정상인 중앙 프로그램 재시작 보존, 중앙 미응답 시 미확인 버퍼 유지·제한 재시도와 D01/D05의 포화·디스크 사용 불가·오류 가시성. 하드웨어 보호 제외를 쓰기 실패 상태에서 성공 응답하는 허용으로 해석하지 않는다.

### Q06 복구 근거가 없어 보류한 파일을 어떻게 다시 시작할 것인가

**상태: 누락 가능성 확인 후 ‘지금부터 다시 수집’ 선택 제공 원칙 합의(2026-11-01). 상세 구현·권한·기록 정합성과 검증은 후속 설계.**

### Q07 서비스와 수집원을 어떤 방식으로 등록·변경할 것인가

**상태: 서비스/수집 등록 후 키 발급·중앙 등록정보 기반 분류 유지. Q07-01 등록 화면의 기존 서비스 선택/새 이름 등록 합의(2026-11-01). 이름/수명 등 나머지는 미정. 미분류 보관/재분류 제외.**

2026-11-01 [전용 기획안 Q07-01~08](q05-q07-q10-plan-v0.1.md#q07)에 명시 등록·이름 중복/변경·서비스/입력 교체·중복 등록·보관/재활성/삭제·메타데이터의 선택지를 조사했다. Q07-01은 등록 화면의 기존 서비스 선택/새 이름 등록으로 합의했고 Q07-02는 이름이 별칭이고 실제 연결 식별이 중요하다는 사용자 취지에 따라 설계로 인계했다. 이름 중복 허용/금지는 미확정이다. Q07 사용자 항목은 정리했고 실제 식별/수명/참조·schema와 구현/검증은 남아 있다. 새 등록으로 전환하는 추천안의 D02 누락 가능성, 과거/대기/키/저장 조건/알림의 독립 수명을 함께 설명한다. 키당 등록 범위는 Q10-07과 같은 선택으로 관리한다.

- **보관/재활성화·완전 삭제 Q07-07:** 보관/재활성화는 초기 제공하고 연결 등록의 완전 삭제는 후속으로 합의했다. 사용하지 않음은 운영자의 명시적 보관 선택을 뜻하며 무로그·agent 단절/미보고·키/네트워크 오류로 자동 보관하지 않는 기준으로 구체화한다. 중앙 새 수신 차단·과거 로그의 보존 정책 유지·로컬 중단 별도 적용, 재활성 시 원래 서버/입력·현재 자격/설정·위치 확인을 따른다. 대기/원본 자동 삭제·옛 키 부활 없음. 잔여/효력·권한/동시 조작은 후속 설계다.
- **서버/실제 입력 교체 Q07-05:** 다른 서버나 전혀 다른 로그로 교체하면 새 연결로 등록해 기존 대상/이력과 구분한다. 별칭 수정·같은 입력의 정상 rotation·재시작은 기존 연결과 D02 복구를 유지한다. 기존 대기는 원래 연결/식별로 유지하고 새 등록은 D02 시작 기준을 따른다. 동일 입력 판정·설정 변경·잔여/제거 절차·agent 관계/키 교체 정합성과 실제 검증은 후속이며 키 범위/개수는 Q10-07 합의를 따른다.
- **다른 서비스 분류로 직접 이동 Q07-04:** 후속으로 유예. 초기에는 기존 연결 종료/잔여 처리 뒤 새 분류의 새 연결로 등록하고 기존 로그/대기는 원래 분류·연결/식별로 유지한다. 새 D02 시작 경계까지 수집 공백 가능성을 표시하며 종료/새 등록·중복 차단·미확인 정합성은 후속 설계다. 직접 전환 기능/검증을 첫 출시 필수로 넣지 않는다.
- **별칭 변경 Q07-03:** 나중에 서비스 이름을 수정할 수 있고 실제 서버/agent/수집 연결과 기존 로그·출처는 유지한다. 화면의 서비스 표시를 현재 이름으로 바꾼다. 원문 재작성·읽기/대기 초기화나 다른 서비스 분류로 이동하는 기능은 추가하지 않는다. 이름 규칙·이력/이전 이름·동시 수정과 저장 조건/알림 참조는 후속 설계다.
- **확인된 중복 Q07-06:** 같은 서버의 같은 로그를 수집하는 연결이 이미 등록돼 있다고 확인되면 기존 연결을 안내하고 새 등록을 막는다. 별칭이 다른 같은 입력과 같은 서버의 다른 입력을 구분한다. 실제 판정/검사 시점·불확실한 겹침·동시 등록·복제와 실행 검증은 후속 설계다.
- **오류:** 키나 수집 등록정보로 서비스를 확인할 수 없는 요청은 수신 완료로 처리하지 않고 연결/등록 오류를 알린다. 미확인 대기 로그는 D01/D05/D08에 따라 보존한다. 서비스명을 추측하거나 실제 서비스를 자동 생성·임의 변경하지 않는다. 영구 거부/재시도 오류 분류와 구체 응답은 후속 설계다.
- **기존 안건 정리:** 앞선 미분류 보관/표시 합의는 서비스 분류 정보를 키/등록과 별개로 받는 가정에서 나왔다. 사용자의 키 발급 전 서비스 확정 전제로 대체하며 미분류 보관·화면/필터와 기존 미분류 재분류 기능을 구현 후보에서 제거한다.
- **남은 선택/설계:** 중앙의 단일 파일/파일명 규칙 입력·주소/키/경로 설정 제공·사용자 복사 적용은 합의했다. Linux 세부 지원·중앙 Linux 세부 환경·입력/형식·패턴 문법/탐색 한도·설정/UI/인증/프로토콜·등록/입력 묶음 모델과 서비스 이름/수명·ID/DB 관계·등록정보/키 정합성은 후속 검토/설계다. 본문/전송/자원 원칙을 유지한다.
- **연결:** F01/F03, P03/P14/P18, D11. 이 정정은 서비스별 tenant/권한이나 HTTPS 등 특정 전송 방식 채택을 뜻하지 않는다.

### Q08 검색의 기본 동작과 시간 기준은 무엇인가

**상태: 기본 발생 시각과 본문 검색의 기본 대소문자 미구분·선택적 구분 옵션 합의(2026-11-01). 필드 검색의 값 일치·항목 존재·숫자 범위 초기 지원도 합의했다. 2026-11-02 [Q08 기획안](q08-search-plan-v0.1.md)으로 전수 조사와 설계 인계를 정리했고 사용자 결정 8개(Q08-01~08)를 모두 A안으로 합의해 사용자 협의를 정리했다. 수치와 구현·실행 검증은 후속이다.**

**진행:** 사용자는 시각 대체가 기존에 정의된 내용임을 지적하고 다음 안건으로 이동하도록 요청했다. 기존 관측 시각 대체/표시 설계안과 합의 상태를 유지하며 이를 사용자 확정으로 바꾸거나 같은 질문을 반복하지 않는다.

**본문 검색 합의:** 기본은 대소문자를 구분하지 않고 필요할 때 구분 옵션을 켠다. 예를 들어 기본 error 검색은 error/ERROR/Error를 함께 찾고 구분 옵션을 켜면 입력한 표기를 구분한다. 구조화 필드의 같음 비교·ID 검색에는 자동 적용하지 않는다. Unicode·정규화·엔진 지원과 비용은 후속 설계/검증이다.

**필드 검색 합의:** 정상적으로 해석한 필드의 값 일치·항목 존재·숫자 범위를 초기 지원한다. 예시는 status=500, request_id 항목 있음, duration_ms가 1000 이상이다. 항목명/수치는 설명용이다. 타입·문자열 비교·누락/해석 불가·중첩/배열·추가 연산은 후속 세부 설계/검토이며 파싱 실패를 항목 없음으로 단정하지 않는다.

**후속 조회 설계:** 새 로그 확인은 실시간 후속·고정 검색 재실행이라는 기존 흐름을 유지한다. 같은 검색의 조회 세대/페이지 기준과 지연 유입 반영·만료·권한/보존 변경·엔진 capability는 기존 상세 초안을 바탕으로 설계/검증한다. 문서만으로 snapshot 보장이나 장기 결과 저장을 확정하지 않으며 요구를 충족하지 못하면 사용자 영향을 설명한다. 주변 조회의 레벨/본문 조건 해제는 Q09에서 합의했고 Q11 상대/고정 시간 지원·선택 방식 유지도 합의했다. 메일 세부 협의는 보류하고 남은 사용자 선택·설계 항목을 일괄 보고한다.

- **합의한 것:** 유효한 발생 시각이 10:00이고 중앙에 10:05에 도착한 로그는 기본 검색의 10:00 범위에 속한다. 발생·관측·수신 시각은 구분한다. 이 선택만으로 지연 도착 로그를 진행 중 결과에 끼워 넣는 계약이나 알림/보존 기준까지 정하지 않는다.

- **사용자 결정 합의(2026-11-02):** 사용자가 [결정표](q08-search-plan-v0.1.md#3-사용자-결정-일괄-요청) 8개를 `전부 추천`으로 답했다. 다시 승인받지 않는다.
  - Q08-01: 본문은 글자 그대로 부분 일치한다. 긴 기간 검색은 느려 부분 결과가 나올 수 있다.
  - Q08-02: 본문 제외·값 다름·항목 없음을 첫 출시에 넣고 검색과 알림에 함께 쓴다.
  - Q08-03: 정규식과 직접 쿼리 입력은 후속이다.
  - Q08-04: 검색 화면에서 발생 시각(기본)과 수신 시각을 고르고 저장 검색에도 저장한다.
  - Q08-05: 미래 시각은 원본을 보존하고 검색 기준만 관측 시각으로 대체해 `시각 의심`을 표시한다. 과거 시각은 보정하지 않으며 로그는 버리지 않는다. 허용 오차는 측정 후 제안한다.
  - Q08-06: 수집 연결에 `로그 시간대` 선택 입력을 두고 미입력이면 에이전트 서버 시간대로 해석해 `시간대 추정`을 표시한다.
  - Q08-07: 일반 텍스트의 흔한 형식은 내장 패턴으로 시각·레벨을 읽고 안 맞는 연결만 추출 규칙을 선택 입력한다. 검색 정규식과 별개이며 규칙 변경은 이후 로그에만 적용한다.
  - Q08-08: 시간별 발생량과 서비스·서버·레벨별 건수를 제공한다. 임의 필드별 건수는 제공하지 않는다.
- **설계 인계:** 기존 관측 시각 대체 설계안은 그대로 두고 발생 시각은 미확인, 검색 기준 시각만 대체로 구체화했다(SD-01, SD-02). 재질문하지 않으며 사용자 확정으로 바꾸지 않는다. 지연 유입·페이지 기준은 실행 시 수신 기준 시점 고정과 재실행 반영으로 정리했다(SD-28). 타입·문자열 비교·판정 불가는 SD-20~SD-22로 정리했다. 일반 검색의 요청 ID 범위는 SD-23으로 닫았다.
- **영향과 입력:** ‘언제 발생했나’와 ‘언제 들어왔나’가 서로 다른 결과를 만든다. 결과에 적용한 시간 기준과 수신 기준 시점을 표시한다. 일반 텍스트 로그의 시각·레벨을 읽지 못하면 레벨 필터와 레벨 기준 알림이 동작하지 않는다.
- **연결:** F03, P07/P08, 초안 D12. 서비스별 구분과 통합 조회 요구를 다시 묻는 항목이 아니다. 안정적인 정렬·페이지 토큰·부분 결과 표시와 엔진의 일관성 충족 여부는 설계·검증 과제다.

### Q09 상세·주변 로그·실시간에서 어떤 조사 흐름을 제공할 것인가

**출시 구분: Q01에서 상세·같은 로그 흐름의 주변 조회는 초기 포함, 실시간 조회와 요청 ID 기반 여러 서비스 연관 조회는 후속으로 합의했다. 아래 후속 기능 상세안은 재검토 자료다.**

**주변 조회 필터 합의(2026-11-01):** 주변 조회에서만 레벨·본문 조건을 해제해 같은 로그 흐름의 앞뒤 INFO/WARN 등 다른 레벨 로그도 보여준다. 원래 검색 조건·선택 이벤트·로그 흐름·현재 접근 권한을 유지하고 해제한 조건을 표시한다. 원래 검색으로 돌아오면 기존 조건/선택을 이어간다. 전후 건수/시간 상한·순서·수명/권한 변경은 후속 설계/검증이다.

**상태: 사용자 협의 정리(2026-11-02).**

- **Q09-01 조건 해제:** 주변 조회에서 레벨·본문뿐 아니라 필드·시간 조건도 풀어 앞뒤 로그를 그대로 보여주고 해제한 조건을 표시한다. 연결·서비스·서버 경계와 현재 권한은 유지한다.
- **Q09-02 회전 경계:** 정상 로그 회전 경계를 넘어 이어 보여주고 경계를 표시한다. 파일 순서를 확인할 수 있을 때만 이어 붙인다.
- **Q09-03 같은 서버 전환:** 같은 서비스·서버의 다른 파일 로그를 시간순으로 함께 보는 전환을 제공하고 원본 순서가 아니라고 표시한다.
- **Q09-04 한 건 복사:** 상세에서 로그 한 건의 본문과 필드를 복사하는 버튼을 제공한다. 여러 건 내보내기를 뜻하지 않는다.
- **후속 설계/검토:** 같은 로그 흐름의 식별/원본 순서·전후 건수/시간 상한·추가 로딩·보존 만료/권한 변경과 표시/복귀 정합성을 구체화한다. 후속 live/요청 연관 계약은 해당 재검토 시 다룬다.
- **유지할 범위:** 같은 흐름의 주변 조회·필터 원칙은 합의했고 request/trace ID 연관 모드와 live는 후속이다. ID가 없으면 만들어 상관관계를 꾸미지 않는다. 실시간은 별도 화면 버퍼와 누락 가능 구간 표시를 두고, 재연결 범위를 넘으면 고정 검색으로 연결하는 안이다.
- **영향과 입력:** 발생 시각 순으로 나열했다고 원본 인접 행이라고 보장할 수는 없다. 화면 일시정지는 에이전트 수집 정지와 다르다. 전후 범위와 누락/만료·순서 의미를 설계/검증하며 후속 live의 복구 경험은 재검토 시 협의한다.
- **연결:** F04/F05, P09/P10, 초안 D12. 건수·시간·화면 버퍼 상한 수치는 Q15의 목표와 측정 후 정한다. 중복 저장 방지 합의를 실시간 전체 구간의 무손실 보장으로 확대하지 않는다.

### Q10 로그인·권한·수집 키·감사를 어느 수준으로 제공할 것인가

**상태: Q10-01~14 기본 사용자 협의 정리(2026-11-02).** 공용 계정/향후 분리·인증/자격/세션/키·감사 범위에 더해 감사 90일 목표/강제 한도 우선 정리, 감사 저장 단독 실패의 정상 운영 계속·일반 민감 변경 보류·확정 가능한 긴급 차단/인증된 로컬 복구 예외와 공백 표시까지 합의했다. MFA는 후속이고 실제 저장 예산·기록/정리/실패/복구·기술/구현/실행 검증은 개발팀 후속이다.

2026-11-01 [전용 기획안 Q10-01~14](q05-q07-q10-plan-v0.1.md#q10)에 인증/접속·복구/MFA·허용 작업·세션·키 단위/표시/만료/교체/폐기·감사 범위/보존/장애를 조사했다. 이후 사용자 답변으로 위 상태와 아래 항목의 범위를 합의했다. **명시한 합의 밖의 추천안/수치는 미승인**이며 실제 구현/실측도 아니다. 공용 계정과 개인 SSO/감사의 의미, 오프라인 수집 중단의 한계, 감사 실패 시 사고 차단이 막히는 위험을 구분한다. [공식 근거](../research/q05-q07-q10-evidence-2026-11-01.md)와 T04~T07·미실행 검증에 연결한다.

- **합의한 것:** 팀 전체가 같은 계정으로 로그인한다. 초기 사용자별 계정·역할 관리 기능은 추가하지 않고 검색 조건도 이 계정의 단일 목록을 함께 사용한다. 자체 로그인 선호에 따라 초기 로컬 공용 로그인 방향으로 진행하고 웹은 사내망·VPN 전용이며 웹과 에이전트 전송은 HTTPS를 기본으로 사용한다. MFA는 후속이며 첫 출시는 공용 비밀번호 로그인이다. 웹 계정 수와 서비스/수집 등록의 전송 키 단위는 별개로 유지한다.

### Q11 검색 저장·내부 공유·파일 내보내기를 제공할 것인가

**저장 시간 합의(2026-11-01):** 상대/고정 시간 모두 지원하고 저장 시 선택 방식을 유지한다. 최근 30분은 열 때 현재 기준 최근 30분, 특정 날짜 10:00~10:30은 그 날짜/시간 범위로 실행한다. 현재 권한·보존 범위에서 다시 검색하며 결과 snapshot 장기 저장을 추가하지 않는다. 시각·기간은 예시이며 초기 기본값을 정한 것이 아니다.

**출시 구분: 검색 조건 저장은 첫 출시 포함, 내부 공유 링크·결과 파일 내보내기는 후속이다. Q10/Q11에서 공용 계정 하나의 저장 목록을 함께 쓰기로 합의했다.**

- **합의한 것:** 첫 버전은 같은 공용 계정의 검색 저장 목록을 함께 쓰며 개인용과 팀용 목록을 따로 만들지 않는다. 조건 저장은 내부 공유 링크·결과 snapshot 저장과 구분한다. 필요 시 계정을 나눌 수 있도록 귀속·권한 검사 확장을 고려한다.
- **Q11-01 수정:** 저장 검색의 이름·조건·시간을 수정할 수 있다. 공용 목록이라 다른 팀원의 저장 검색도 바뀔 수 있다.
- **Q11-02 삭제:** 확인 후 즉시 삭제하고 복구는 두지 않는다.
- **Q11-03 수명:** 오래 쓰지 않아도 자동 삭제하지 않는다. 개수 상한에 닿으면 저장을 막고 안내한다.
- **설계 기본값:** 저장 이름 중복 금지, 동시 수정 덮어쓰기 전 경고, 보관된 연결 참조의 실행 전 경고. 개수 상한 수치는 측정 후 제안한다. 시간대·범위 경계는 Q08 SD-06/SD-07, 알림 규칙과의 관계는 Q12 복사 관계를 따른다.
- **남은 협의:** 향후 계정 분리 시 기존 목록의 복사/이전·귀속·공용 유지 여부는 그때 선택한다. 내부 링크·export의 상세 정책은 후속 재검토 시 정한다.
- **후속 검토:** 개인별/팀별 저장 방식과 소유자 이관은 계정 분리 필요가 생기면 검토한다. 파일 내보내기를 재검토할 때 사용 목적·형식(JSON Lines/CSV 등)·생성 파일 만료·다운로드 한도와 접근 범위를 정한다.
- **영향과 입력:** 조건 공유는 결과 복사와 다르며 저장된 조건이 로그 보존 기간을 늘리지는 않는다. 이미 다운로드한 파일의 회수는 보장할 수 없다. 저장 시 선택한 방식에 따라 상대 시간은 열 때 재계산하고 고정 시간은 저장한 날짜/시간 범위를 유지한다. 후속 내부 공유 링크의 시간 전달 세부는 재검토 시 정한다.
- **연결:** F07, P12, 초안 D14. D04에 따라 본문은 앱 출력 기준이며 ‘LogDock이 마스킹한 export’는 후보에서 제외한다. 익명 공개 공유·무제한 반출은 초기 대상에 자동 포함하지 않는다.

### Q12 알림을 언제, 어떤 조건과 채널로 제공할 것인가

**상태: 사용자 협의 정리(2026-11-02).** 사용자는 [Q12 기획안](q12-plan-v0.1.md#2-합의-결과)의 11개 안건에 답했다. 시간 구간·임계는 기본값 없이 직접 입력(1~1,440분, 1 이상). 해소 대기는 규칙별이며 비우면 시간 구간과 같은 길이. 조건 수정 시 상태 초기화. 대상 연결 전부가 끊겼을 때만 해소 계산 정지. 수집 끊김·평가 실패 10분 지속 시 설치 공통 운영 메일 1통. 크기 초과 거부는 화면 표시만. 전송 여부 불명은 같은 Message-ID로 재시도. 해소 뒤 대기 메일은 계속 전송하고 해소 사실 표시. 수신 주소는 규칙당 최대 10개, 형식 검사와 테스트 메일. 알림 이력은 로그 보관 기간과 동일. 기존에 쓰는 네이버 SMTP를 쓰고 메일 주소는 사용자가 입력한다. 평가 주기·재시도 상한·메일 표시 범위·메일 자격 위치는 설계값이다. 아래의 협의 보류·미결정 기록은 재개 전 내용이며 위 결과가 우선한다.

- **연결:** F06, P11, 초안 D11/D16. D03의 거부 사유·수집원·관측 시각·확인된 건수·적용 상한 확인은 다시 승인받지 않는다. 본문 없는 진단과 진단 자체 자원 상한도 유지한다.

- **시작/재시작 합의 Q16-07:** 에이전트와 중앙 LogDock 프로그램 모두 서버 부팅 시 자동 시작하고 비정상 종료 때 잠시 기다린 뒤 제한적으로 자동 재시작한다. 반복 실패하면 중단하고 사용자가 상태를 확인할 수 있게 한다. 각 호스트의 실행 관리 계층이 맡으며 agent 위치/식별·대기·파일 보류와 중앙의 프로그램 재시작 수신 보존/ACK를 유지한다. 실제 관리자/패키지·구성요소 의존/횟수/간격·상태/미관측·호스트 설정/검증은 후속이다.
- **업데이트/되돌림 합의 Q16-08:** 에이전트 버전 업데이트는 운영자가 시점을 정해 직접 실행한다. 업데이트 후 문제가 생기면 기존 대기/진행 기록을 유지할 수 있는 호환 이전 버전으로 운영자가 직접 되돌리는 절차를 제공한다. 부팅/오류 재시작과 새 버전 교체를 구분하고 위치/동일 식별·유효 대기·파일 보류를 유지한다. 모든 과거 버전/자동 되돌림을 약속하지 않으며 실제 지원 버전/절차·패키지·호환/중단·검증은 후속이다.
- **중앙 업데이트 담당 Q16-08:** 중앙 LogDock 프로그램 업데이트는 개발팀 담당이다. 운영자 직접/자동 업데이트를 고르는 사용자 질문은 종료하고 실제 배포·호환/중단·복원 절차는 개발팀 설계로 넘긴다. 자동 업데이트나 특정 배포/되돌림 기능을 승인한 답변으로 확대하지 않으며 에이전트 업데이트 합의는 유지한다.
- **남은 운영 입력/선택:** Q13 기본 보관은 모든 서비스 공통으로 각 로그 최초 중앙 유효 수신부터 6개월로 합의했다. 같은 이벤트 재전송/agent 재연결로 기존 기준을 갱신하지 않고 검색 발생 시각은 유지한다. 공간 부족·기간 변경·삭제·늦은 도착 정책도 합의해 잔여는 Q15의 1개 Q 범위다. 기존 Q10/Q14·감사/진단/원본/대기·성장/지연 수치 유보를 유지하며 실제 기록/정리/만료/공간 회수·설치/정합성/시험은 개발팀 후속이다.
- **유지할 범위:** Q04 중앙 서버/디스크 고장용 복제·자동 장애조치·로그 백업 복구는 제외한다. 설정 전달 합의가 원격 자동 설치/명령 실행/설정 변경 기능을 뜻하지 않는다. 재시작/업데이트에서도 현재 권한/보존과 기존 queue를 유지하도록 설계한다.
- **연결:** Q02/Q10/Q15, P04/P14/P18, D18. 실제 키 발급·서버 접속·설치/배포·DB 변경 실행은 이번 문서 합의 요청에 포함되지 않는다.

## 9 협의 결과를 반영하는 방법과 이번 확인 범위

각 Q는 미합의·부분 합의·합의·유예로 구분한다. 결정할 때 실제 선택과 감수할 영향, 남은 수치/설계/검증, 관련 D/F/P를 남긴다. [결정 기록](../decisions.md), 관련 명세, [handoff](../HANDOFF.md)에 같은 내용을 반영한다. 유예한 기능의 세부 정책은 초기 필수 협의로 남겨두지 않는다.

초기 재검토 작업은 두 작업 공간의 Markdown과 Git 변경 상태를 대조하고 최신 합의를 기준으로 협의 대상을 추린 것이다. 별도 작업 공간의 원본 초안을 수정하거나 전체 통합하지 않았고, 목록 작성만으로 새 정책을 채택하지 않았다.

2026-11-01 이후 사용자 응답으로 Q03의 제한된 디스크 버퍼 기본 방식과 사용 불가 시 자동 메모리 대체 없는 대기·오류/사용자 가시성, 기존 버퍼 보존·필수 상태 기록 불가 시 전송 정지·정상 확인 후 제한 재개를 합의해 갱신했다. 수치·지원 수단·기록 확정/복구 범위는 남아 있으며 다음 협의는 Q04다. 제품 코드·DB·운영 환경·의존성·PDF 변경, 수집/부하/복구 시험·commit/push는 실행하지 않았다. AT/IT/OT 시나리오는 여전히 정의 단계다.

후속 사용자 지시로 에이전트/중앙 책임 구분을 Q04에 반영하고 문서와 handoff를 commit `4398e9c`로 원본 저장소 main에 반영했다. 그 commit은 별도 stash와 미추적 상세 초안을 제외했다.

이후 사용자가 상세 초안의 유효 내용을 통합하고 중복 stash를 정리하도록 요청했다. 이에 상세 문서 3개·기술 평가 절차·기능 연결표·D10~D18 추적표를 최신 합의와 맞춰 연결했다. 과거 가져오기·내부 마스킹/격리·큰 이벤트 분할/잘림의 옛 제안은 제거했다. 이 통합 자체로 새 정책을 채택하지 않았고, 추가 commit/push·구현·DB/운영 작업·실행 검증도 하지 않았다.

Q02-05 일반 파싱 실패의 기본 처리도 합의했다. Q02-06 폴더별 탐색도 합의했다.

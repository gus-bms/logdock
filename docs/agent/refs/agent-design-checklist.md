# 수집 에이전트 설계 점검

에이전트와 수신 서버를 설계·구현할 때 놓치기 쉬운 점이다. 정책 자체는 [결정 기록](../../decisions.md)과 [수집·에이전트 명세](../../specs/collection-agent-v0.1.md)가 기준이다.

- 버퍼뿐 아니라 파일별 읽기, 여러 줄 조립, 파서, 압축·TLS, 상태 기록, 자체 로그, 진단, 열린 파일 수를 전체 자원 예산에 넣는다.
- 삭제된 원본 파일을 열어 둔 채 두면 디스크 공간이 반환되지 않는다. 보유·해제 한도와 아직 읽지 않은 부분의 유실을 함께 검증한다.
- 새 대기 추가 중단과 필수 확인 응답·읽기 위치 확정·안전한 대기 정리를 구분한다. 필수 상태 기록이 실패하면 읽기 위치를 확정하지 않는다.
- 원본 읽기 복구 위치, 중앙 전달 완료 위치, 내구성 있는 대기, 검색 가능 상태를 구분한다.
- 최초 연결 당시 파일, 이후 생성·발견된 파일, 재시작 때의 파일에 같은 끝 위치 규칙을 적용하지 않는다(D02).
- 재시도 기한이나 대기 보관 기한이 D01 보존 정책을 우회해 자동 폐기를 만들지 않는지 확인한다.
- 키 폐기나 등록 권한 변경 뒤 과거 대기가 현재 인증·권한을 우회해 전송되지 않게 한다. LogDock의 마스킹이나 기존 대기 본문 재마스킹은 D04에 따라 하지 않는다.
- 확인된 유실, 누락 가능 구간, 측정 불가를 구분하고 모르는 값을 0으로 보고하지 않는다.

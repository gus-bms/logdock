## 목표와 완료 조건

기획 종료 기준의 "구현 가능한 계약 초안(API/schema/상태 전이)"을 채운다. 와이어프레임과 동시에 진행하며, 화면 흐름 명세의 필드·상태 이름과 다르게 정하면 명세도 함께 고친다.

- 에이전트와 수신 서버 사이의 전송 규약: 연결별 키와 순번, 묶음 저장 뒤 응답, 부분 거부와 재시도.
- ClickHouse 로그 테이블과 PostgreSQL 관리 테이블(서비스, 수집 연결, 키, 저장 검색, 알림 규칙과 사건, 감사).
- 조회·관리 API와 오류 사유 코드.
- 수집 연결, 키, 알림 규칙의 상태 전이.

## 병행 규칙 (design-system과 함께 지킨다)

- 2026-11-05 사용자 결정(A안)으로 디자인 시스템 초안(design-system)을 다른 세션에서 병행한다([결정 기록](../../decisions.md)).
- 상태 이름, 오류 사유 코드, 필드 이름은 이 작업에서 정한다. 화면 흐름 명세의 이름을 바꾸면 명세와 와이어프레임을 함께 고치고 진행 기록에 남겨 디자인 쪽이 따라갈 수 있게 한다.
- 정리표의 `정하는 곳`을 따른다. `화면` 항목은 고치지 않는다. 바꿀 이유가 생기면 이 파일 진행 기록에 적고 사용자에게 알린다.
- 화면 흐름 명세와 와이어프레임은 한 번에 한 세션만 고친다. 고치기 전에 `git status`와 design-system 작업 파일의 진행 기록을 확인한다.
- 두 세션이 같은 작업 공간(Git worktree)을 쓴다. 커밋은 사용자가 요청할 때만 하고 자기 파일만 경로를 지정해 올린다. `git add -A`, `git commit -a`, `git stash`는 쓰지 않는다.

## 진행 기록

- 2026-11-04 작업 파일을 만들었다.
- 2026-11-05 사용자가 디자인 시스템과 병행하는 A안을 골라 기존 세션이 이 작업을 잡았다. 정리표의 설계 넘김 77건을 `API` 46건과 `화면` 31건으로 나눴다.
- 2026-11-05 [계약 초안](../../specs/api-contract-v0.1.md) 2절에 전송 규약을 썼다. 연결 키 인증과 에이전트 인스턴스 ID, 연결·세대·순번 묶음, 저장 뒤 `acked_through` 응답과 오류 코드별 에이전트 동작, 전송 창, Q06 세대, 연결별 상태 보고, 연결마다 파일 하나인 에이전트 설정이다. 정리표 WQ-53·58·61을 반영했다. 화면 쪽 참고: `rejected`·`boundary` 기록이 순번 자리를 차지하므로 WQ-25(거부 이벤트 자리)는 관측 시각 대신 순번으로 정확히 짚을 수 있다. 화면 항목이라 고치지 않았다. 수치는 모두 `N`이고 실행 검증은 하지 않았다.
- 2026-11-05 계약 초안 3절에 저장 구조를 썼다. ClickHouse `logs` 테이블 DDL 초안(수신일 파티션, 6개월 TTL, 연결·세대·순번 식별, 거부·경계 기록 포함), 보관·조기 삭제·구간 삭제·검색 가능 시점, PostgreSQL 관리 테이블 목록이다. 정리표 WQ-13·18·69·71·72·73·85·86·87·89·90을 반영했다. 화면 쪽 참고: 서버 표시명을 이름 목록 하나로 묶었으므로 `서버 이름 바꾸기`와 `이 연결의 서버 바꾸기`를 구분해야 한다(WQ-63은 5절에서 정함). DDL은 실행하지 않았다.
- 2026-11-05 계약 초안 4절에 조회·관리 API를 썼다. 공통 규칙(세션·CSRF, 조건을 주소에 넣지 않음, 재확인 `reauth_required`, 감사 장애 `held_audit_unavailable`, `version_conflict`), 검색 실행 기준(`run_id`·검색 가능 확정 수신 시점·커서), 관리 요청 표와 재확인·보류 여부, 운영 표시 계산, 오류 형식과 사유 코드를 정했다. 정리표 WQ-01·02·27·31·32·33·37·41·42·49·50·76·77·79·82를 반영했다. 화면 쪽 참고: 오류 문구는 디자인 쪽이 `code`와 `params`로 만든다. WQ-76은 CM-01 배너 종류를 더해야 해서 화면 쪽과 함께 명세에 반영해야 한다.
- 2026-11-05 계약 초안 5절에 상태 전이를 썼다. 수집 연결 관리 상태 다섯 개의 전이와 상태별 허용 동작, 키 상태와 발급·교체 구분, 서비스 보관·재활성과 이름 규칙, 알림 규칙 상태·사건을 닫는 이유·감시 품질, 메일 작업 상태, 감사에 남기는 동작이다. 정리표 WQ-40·45·51·52·54·55·56·57·59·60·62·63·66·67·68·81·88을 반영해 `API` 46건을 모두 첫 초안에 넣었다. 설계 판단: `종료 진행`은 에이전트가 정상 중지를 마지막 보고에 실었을 때 들어가고 다시 보고하면 `사용`으로 돌아간다. 화면 쪽 참고: 사건을 닫는 이유에 `조건 수정`이 새로 생겼다(UI-08 사건 이력).
- 2026-11-05 사용자 요청으로 DDL보다 시나리오 대조를 먼저 했다. AT 18·OT 10·PT 23·IT 26건, 모두 77건의 합격 기준을 계약과 문서로 대조해 7절에 남겼다. 충족 40, 보완 24, 계약 밖 13이다. 빈 곳 18군데를 고쳤다: null 키 존재(`field_paths`), 거부 건수 기준, 상태 보고 사유와 CM-05 대응, 경계 종류, 한 연결 한 인스턴스(`instance_conflict`), 읽은 설정 버전으로 해석, 기록 단위 오류, 6개월 달력 계산, 관리 DB 실패 때 응답, 키 발급 직렬 처리, 폐기 효력 순서, 자동 요청과 세션, 감사 폭주, 시각 확인 계산, 바인딩 파라미터, 큰 정수 전달, 조건 연산, 비밀번호 오류 사유. 실행 검증은 아니며 시나리오는 모두 미실행이다. 화면 쪽 참고: 상태 보고 사유표(2.7절)가 CM-05 관측 상태를 정하는 기준이고 비밀번호 오류 사유 코드(4.5절)가 UI-16 상태 2 문구의 근거다.
- 2026-11-05 사용자 요청으로 누락 조사를 했다. 계약을 결정 기록, 화면 흐름 명세 UI-01~16·CM-01~08, T01~T08, Q08 설계 확정, Q12 TD·사건·메일·F-01~24, 수집 명세 OB·SC·journald, 운영 명세 11절과 다시 대조해 빠진 계약 34건과 어긋남 6건을 고치고 계약 초안 9절에 남겼다. 8절(중앙 서버 설정, 중앙·에이전트 로컬 명령)을 새로 썼다. 공개 API 제공 여부는 운영 명세 11절이 D17에서 고른다고 했지만 고르지 않아 사용자 판단으로 남겼다(9.3절). 정적 대조이며 실행 검증은 아니다. 화면 쪽 참고(화면 항목이라 고치지 않음): UI-01은 `login_throttled`의 남은 시간으로 `대기 N분`을 그린다. UI-11 6단계와 키 발급은 재응답에 `secret_unavailable`이 오면 원문을 보일 수 없어 폐기 뒤 새로 받기를 안내한다. UI-07은 `no_filter_needs_confirm`이면 경고 후 확인받고 같은 이름 규칙은 경고만 한다. CM-01 배너 종류는 4.4절 표 8개이며 `storage_unmeasurable`은 WQ-76과 함께 명세에 더해야 한다. UI-05는 `references_archived`로 실행 전 경고를 띄운다. UI-11 7단계는 등록 단계별 처음 확인 시각을 받는다. UI-12 복구 보류 안내는 8.3절 명령을 보인다. UI-04는 방향별로 끝난 이유 5종을 받는다. UI-02 알림 조사는 `rule_status`로 `현재 규칙과 다름`을 보인다. UI-10 `조치 필요`에 오래 이어진 `연결 대기`가 들어가고 거부는 확인 처리 없이 시간이 지나면 빠진다. 파일과 journald 양쪽 등록의 겹침 안내 문구는 화면 쪽에서 정한다.
- 2026-11-05 사용자가 공개 API 안건에 A안으로 답했다([결정 기록](../../decisions.md)). 계약 초안 4.1·9.3절과 운영 명세 11절의 현재 상태 문장을 고쳤다.
- 2026-11-05 계약 초안 3.4절에 PostgreSQL DDL 초안을 썼다. 테이블 31개, 도메인 2개, 저장 값과 화면 이름 대응표, 설계 메모, DB 역할별 권한이다. 개요 표를 DDL에 맞췄고(`closed_at`, 등록 단계 `first_read_at`, `mail_status`·`ops_recipient_list`·`ops_mail_batches` 추가) 같은 키로 다른 요청이 오는 경우의 `idempotency_key_reused`를 4.5절에 더했다. DB에 실행하지 않았고 문법 검사 도구도 없어 정적 점검(괄호 짝, 끝 쉼표, 외래 키 순서, 색인 열 이름)만 했다. 완료 조건 네 가지가 모두 첫 초안을 갖췄다. 디자인 세션이 화면 쪽 참고를 읽고 있어 작업 파일은 사용자 검토 전까지 progress에 둔다. 화면 쪽 참고: 상태 값은 영어 코드로 저장하고 API도 같은 코드를 쓰며, 화면 이름은 3.4절 대응표를 따른다.
- 2026-11-05 version-pinning이 계약 초안의 버전 문장(상태 줄, 3.2·3.4·3.6·9.4절)을 고정 버전에 맞췄고, 3.2절에 text 색인 후보와 projection이 있으면 경량 삭제가 막히는 제약을 더했다. 같은 날 사용자 요청으로 개발용 PostgreSQL 18.6을 이 PC에 설치했다. 서버 시작과 DDL 적용은 사용자가 한다.

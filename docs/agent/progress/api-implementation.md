## 목표와 완료 조건

[API 계약 초안](../../specs/api-contract-v0.1.md) 4·5절의 조회·관리 API를 NestJS(`apps/api`)로 구현한다. 범위와 순서는 [결정 기록](../../decisions.md)의 2026-11-06 구현 시작 합의를 따른다.

- 이 작업: PostgreSQL만 쓰는 부분. 인증·세션·감사 → 서비스·서버·수집 연결·키 → 저장 검색 → 알림 규칙·사건 → 메일 설정 순서로 만든다. 키 형식과 수집 연결 테이블은 수신 서버도 쓰므로 계약 2.2절과 3.4절을 기준으로 한다.
- 다음 작업으로 나눌 것: ClickHouse를 쓰는 검색·발생량·이벤트 상세·주변 로그·필드 제안·알림 미리보기·저장 공간·구간 삭제. 중앙 서버가 준비되면 시작하고, 측정 M5의 조회 API로 쓴다.
- 시험: 이 PC의 임시 PostgreSQL(소켓만, 끝나면 폴더째 삭제)에 DDL을 적용해 돌린다. 사용자가 만든 `logdock_dev`에는 접속하지 않는다.
- 한도 값은 코드에 박지 않고 설정값으로 둔다. 측정·Q15 결과로 바뀔 수 있다.
- 의존성은 적게 두고 버전을 정확히 고정한다(`.npmrc`의 `save-exact`). 설치는 사용자가 실행한다.
- 코드가 생기면 [아키텍처](../../architecture.md)의 현재 구현 표, [개발 환경](../refs/dev-environment.md)의 현재 코드 표, [잔여 기획](../../planning/remaining-plan-v0.1.md) 9절의 현재 코드 문장을 고친다.
- 완료: 위 PostgreSQL 부분의 엔드포인트가 계약대로 동작하고 임시 PostgreSQL 시험이 통과한다. 실행 검증 시나리오(IT·OT)는 별도로 구분해 적는다.

## 진행 기록

- 2026-11-06 사용자 A안으로 작업을 만들고 시작했다. 첫 의존성은 PostgreSQL 드라이버 `pg`와 그 타입, 요청 검증용 `zod`로 정했다. ORM은 두지 않는다. DDL이 기준이고 부분 유일 색인·행 잠금 같은 동시성 규칙을 SQL로 드러내기 위해서다. 비밀번호 해시는 Node 내장 crypto를 쓰고, 시험은 Node 내장 시험 도구로 컴파일한 코드를 돌린다. 이 작업 공간에는 `node_modules`가 없어 설치 명령을 사용자에게 넘겼다.
- 2026-11-06 의존성이 필요 없는 단계를 먼저 했다. 계약 초안 3.4절의 DDL 블록 넷을 그대로 `db/postgres/migrations/0001_initial.sql`로 옮기고 계약에서는 지웠다(2026-11-05 결정 기록의 "구현 때 마이그레이션 파일로 옮긴다"). 수신 서버(Go)도 같은 스키마를 쓰므로 앱 폴더가 아닌 저장소 루트에 두었다. `db/postgres/ephemeral.mjs`는 외부 패키지 없이 initdb·pg_ctl·psql로 임시 PostgreSQL을 띄운다. 이 PC의 임시 폴더에만 만들고 TCP 포트를 열지 않으며(소켓만), 끝나면 폴더째 지우고, PG로 시작하는 환경 변수를 넘기지 않아 다른 DB로 접속하지 않는다. DB는 builtin `C.UTF-8`로 만든다. `schema.test.mjs`의 시험 17건(소켓 전용 확인, 테이블·도메인 수, 로캘, 이름 규칙, 대소문자 무시 유일성, 수집 대상 규칙, 같은 대상 중복, 유효 키 둘, 열린 사건·회차, 알림 규칙, 메일 작업, 세션 폐기 사유, 한 행 테이블, 운영 일·배너, 저장 검색, 감사 동작 이름)이 PostgreSQL 18.6에서 통과했다(`npm run test:db`, 임시 폴더·프로세스 남지 않음 확인). 시험 중 DDL에서 고칠 곳은 나오지 않았다. 마이그레이션 적용 기록과 적용 도구는 계약 3.6절 스키마 변경 절차와 함께 정한다.
- 2026-11-06 인증의 남은 설계(T04, "구현 때 당시 공식 보안 자료로 정한다")를 Node 24 crypto 문서와 OWASP 비밀번호 저장·CSRF 방지 지침으로 정해 계약 4.1절 `비밀 저장`에 적었다. 비밀번호는 Node 내장 Argon2id(OWASP 최소 설정 19456KiB·2회·병렬 1, PHC 문자열), 세션 ID와 수집 키 비밀 값은 SHA-256, CSRF는 세션마다 무작위 32바이트를 두는 synchronizer token이다. 이 PC에서 Argon2id 한 번은 약 15ms였다. 세션 테이블에 토큰 열이 없어 `0002_session_csrf.sql`을 더했고(적용한 0001은 고치지 않음) 시험 18건이 통과했다. `logdock_dev`에는 API를 붙이기 전에 사용자가 0002를 적용해야 한다.
- 2026-11-06 사용자가 의존성을 설치해(`pg` 8.23.1, `zod` 4.6.7, `@types/pg` 8.23.1) 진행으로 되돌리고 인증·세션을 만들었다. `POST /api/v1/auth/login`·`/logout`·`/reauth`, `GET /api/v1/auth/session`, `POST /api/v1/account/sessions/terminate-all`이다. 모든 경로를 한 검사 지점(전역 가드)에서 세션과 CSRF 토큰으로 확인하고, 세션 없이 부르는 경로만 `@Public`으로 연다. 세션 유효 판단은 DB 시각으로 하고, 화면의 자동 요청(`X-LogDock-Background`)은 활동으로 세지 않는다. 시도 제한은 좁은 열쇠(계정+주소)와 넓은 열쇠(계정)로 세고, 감사는 같은 트랜잭션에 쓰되 로그인·로그아웃·전체 종료는 감사 실패 때 공백과 배너를 남기고 진행한다. 오류는 계약 4.5절 형식이다. 구현에서 정한 세부(시도 제한 수치·쿠키 이름·세션 확인 응답·재확인 15분)는 계약 4.3절 `인증 구현 설계`에 적었다. 시험은 `node:test`로 컴파일한 코드를 돌리고(`npm run test:api`), 시험마다 임시 PostgreSQL에 마이그레이션을 적용해 앱을 루프백 주소에 띄워 HTTP로 확인한다. 16건이 3번 반복 통과했고 타입 검사와 `nest build`도 통과했다. 비밀번호 변경은 흔한·유출 비밀번호 목록(Q10-03)이 필요해 다음으로 미뤘다. 계정을 만드는 명령이 아직 없어 개발 DB로는 로그인할 수 없다.
- 2026-11-07 비밀번호 변경(`POST /api/v1/account/password`)과 계정 설정 로컬 명령(`admin set-password`·`reset-password`, 빌드한 `dist/cli.js`)을 만들었다. 비밀번호 규칙은 NIST SP 800-63B-4로 정했다: NFC 코드 포인트로 15자 이상이고, 비밀번호 전체를 차단 목록과 비교하며, 서비스·계정 이름 변형과 되풀이·연속 값도 막는다. 차단 목록은 HIBP Pwned Passwords에서 나온 NCSC 상위 10만 개(SecLists 사본, MIT, 커밋 고정)에서 비교 형태가 10자 이상인 9,123개를 `common-passwords.ts`로 만들어 넣었다. 공개 저장소라 메일 주소 모양은 뺐다. 감사를 쓸 수 없으면 웹 변경은 보류하고(409), 로컬 재설정은 진행하며 공백을 남긴다. 바뀌는 중에 들어온 로그인이 옛 비밀번호로 세션을 만들지 않게 로그인·재확인이 계정 행을 `FOR SHARE`로 읽는다. 세부는 계약 4.3·4.5·5.6·8.2절에 적었다. 시험 34건(규칙 7, 변경 6, 로컬 명령 5를 더함)이 3번 반복 통과했고 타입 검사와 `nest build`도 통과했다. 터미널에서 숨겨 입력받는 경로는 자동 시험하지 않았다. 이제 개발 DB에도 사용자가 `set-password`로 계정을 만들면 로그인할 수 있다(0002 적용 뒤). NIST 3.2.2절의 연속 실패 100회 상한과 지금 속도 제한의 차이는 사용자 판단으로 올렸다.
- 2026-11-07 사용자가 연속 실패 잠금 B안을 골라([결정 기록](../../decisions.md)) 바로 구현했다. 마이그레이션 `0003_login_lockout.sql`이 `login_throttle`에 연속 실패 수와 잠긴 시각을 더한다. 계정 이름 열쇠로 세어 없는 계정 이름도 똑같이 잠기고, 잠기면 `423 login_locked`이며 로컬 재설정만 푼다. 잠긴 순간은 감사(`auth.login_locked`)와 자체 로그 경고에 남긴다. 잠금 시험 5건과 스키마 시험 1건을 더해 API 39건·DB 19건이 통과했다(API 3번 반복). 사용자가 `logdock_dev`에 0002·0003을 적용해야 하고, 화면의 잠김 상태는 ui01-locked-state로 넘겼다. 시도 제한 기록 정리 작업은 아직 없으며 만들 때 잠긴 행을 남긴다.
- 2026-11-07 사용자가 `logdock_dev`에 0002·0003을 적용하고 터미널에서 `admin set-password`로 공용 계정을 만들었다(숨김 입력에 문제 보고 없음). 에이전트는 이 DB에 접속하지 않았다.
- 2026-11-07 서비스·서버 목록과 이름 변경(`GET·PATCH /api/v1/services`, `GET·PATCH /api/v1/servers`)을 만들었다. 이름 규칙은 공통 검사(`common/names.ts`, 상한 100자는 설정값)로 모았고, 감사가 남아야 적용하는 변경은 `AuditService.writeOrHold`가 던지는 오류를 오류 필터가 `409 held_audit_unavailable`로 바꾸게 정리했다(비밀번호 변경도 같은 방식으로 바꿈). 감사에 바뀐 항목 이름(`changed_fields`)을 남기기 시작했다. 세부는 계약 4.3절 `서비스·서버 구현 설계`에 적었다. 시험 11건을 더해 API 50건이 3번 반복 통과했고 타입 검사와 `nest build`도 통과했다. 서비스 보관·재활성은 하위 수집 연결과 키를 함께 바꾸므로 수집 연결과 같이 만든다.
- 2026-11-07 사용자 요청으로 그때까지의 작업을 주제별로 커밋했다(에이전트, 관리 DB, API, 문서 점검 스크립트, 문서). 다른 세션의 측정 작업은 넣지 않았고 푸시는 하지 않았다.
- 2026-11-07 수집 연결 사전 검사(`POST /api/v1/connections/validate`)를 만들었다. 새 이벤트 시작 규칙은 Go(RE2) 문법이라 JavaScript 정규식으로는 같게 검사할 수 없어, 에이전트의 수집 대상·형식 검사를 `agent/internal/rules`로 꺼내고 WebAssembly(`agent/cmd/logdock-rules`, 약 5MB, 불러오기 수십 ms)로 빌드해 API가 그대로 부르게 했다. 에이전트 설정 검사도 같은 함수를 쓴다. 시간대만 Node의 IANA 자료로 본다. 수집 연결 외부 ID는 내부 ID를 곱셈으로 섞은 36진수로 정했다. 세부는 계약 2.8·3.1·4.3·4.5절에 적었다. 에이전트 시험이 모두 통과했고, API 시험은 사전 검사 6건과 외부 ID 2건을 더해 58건이 3번 반복 통과했으며 빌드도 통과했다. 이제 API 빌드·시험에 Go가 필요하다.
- 2026-11-07 수집 연결 등록 확정(`POST /api/v1/connections`)과 설정 내려받기(`GET .../{id}/config`)를 만들었다. 민감 작업의 최근 재확인을 검사 지점에서 보는 `@RequireReauth`와, 키 행을 작업 트랜잭션 처음에 넣는 `Idempotency-Key` 처리(`common/idempotency.ts`)를 처음 썼다. 수집 키는 16진수 키 ID와 base64url 비밀 값이며 DB에는 SHA-256만 둔다. 설정 파일은 에이전트가 읽는 TOML 일부로 만들고, `agent/internal/config/testdata`의 기준 파일을 API 시험과 에이전트 시험이 함께 써서 두 쪽이 어긋나지 않게 했다. API 서버는 이제 수신 서버 주소 `LOGDOCK_INGEST_URL`이 있어야 시작한다. 세부는 계약 2.2·4.3·8.1절에 적었다. API 시험 10건을 더해 68건이 3번 반복 통과했고, 에이전트 시험과 빌드도 통과했다.
- 2026-11-07 수집 키 발급·교체·폐기를 만들었다. 같은 경로가 유효 키 수에 따라 발급·교체를 고르고 5.1절 상태별 동작을 따른다. 연결 행 잠금으로 동시에 눌러도 유효 키가 둘을 넘지 않는다. 폐기는 `폐기 요청`까지 하고 확정·관측은 수신 서버가 기록한다. 그래서 수신 서버 전에는 `폐기 요청`에 머물고 `전송 차단` 전이도 일어나지 않는다. 감사에 진행 단계(`stage`)를 남기기 시작했다. 세부는 계약 4.3절 `수집 키 구현`에 적었다. API 시험 10건을 더해 78건이 3번 반복 통과했고 빌드도 통과했다.
- 2026-11-07 사용자 요청으로 사전 검사·등록·키 작업을 주제별로 커밋했다(에이전트 규칙 패키지, API, 점검 스크립트, 문서). 측정 세션의 문서·`bench/`는 넣지 않았다.
- 2026-11-07 수집 연결 목록·상세·조치 필요 수(`GET /api/v1/connections`·`/summary`·`/{id}`)를 만들었다.

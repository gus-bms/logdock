## 목표와 완료 조건

첫 출시 화면에 쓸 디자인 시스템 초안을 문서와 정적 HTML 시안으로 만든다. 2026-11-05 사용자 결정(A안)으로 api-contract-draft와 다른 세션에서 병행한다([결정 기록](../../decisions.md)). React 같은 코드 컴포넌트는 만들지 않는다. 화면 구현은 기획 완료와 와이어프레임 뒤라는 2026-11-02·11-04 합의를 따른다.

- 사용자 결정 두 가지를 A안·B안으로 받아 결정 기록에 남겼다.
  - 부품 방식: 직접 만들기, 또는 Apache-2.0과 함께 쓸 수 있는 오픈소스 UI 라이브러리. 라이브러리 후보는 라이선스와 유지 상태를 공식 자료로 확인해 제시한다.
  - 시각 방향: 참고 제품, 밝은 테마·어두운 테마 지원 범위.
- 기준값을 정했다: 색, 글꼴, 글자 크기, 간격, 모서리, 그림자, 초점 표시. 글꼴은 라이선스를 공식 자료로 확인했다.
- 부품의 모양과 상태(기본·마우스 올림·초점·비활성·오류)를 정했다. 범위는 와이어프레임 공통 요소 CM-01~CM-08과 화면에 쓰인 버튼, 입력, 선택, 표, 배지, 배너, 토스트, 확인 창, 패널, 단계 표시다.
- 화면 규칙을 지킨다: 상태는 색만으로 구분하지 않고 글자를 함께 쓴다(화면 흐름 명세 1절, 조사 명세 8절). 데스크톱 Chrome 기준이다(Q15-01). 작업 결과 알림은 CM-08 토스트다.
- 대표 화면 2~3개(예: UI-02 로그 탐색, UI-12 수집 연결 상세)에 적용한 정적 시안을 만들었다.
- [와이어프레임 검토 항목 정리표](../../planning/wireframe-review-items-v0.1.md)에서 `정하는 곳`이 `화면`인 31건을 확정하거나, 바꿀 안을 사용자에게 올렸다.
- 산출물은 `docs/design/`에 두고 [문서 안내](../../README.md)에 등록했다. 예시는 합성 데이터만 쓴다(AGENTS.md 공개 자료와 검증).

## 병행 규칙 (api-contract-draft와 함께 지킨다)

- 상태 이름, 오류 사유 코드, 필드 이름은 API 쪽이 정한다. 디자인은 화면 흐름 명세의 이름을 쓰고, 바뀌면 글자만 고친다.
- 정리표의 `정하는 곳`을 따른다. `API` 항목은 고치지 않는다. 바꿀 이유가 생기면 이 파일 진행 기록에 적고 사용자에게 알린다.
- 화면 흐름 명세와 와이어프레임은 한 번에 한 세션만 고친다. 고치기 전에 `git status`와 api-contract-draft 작업 파일의 진행 기록을 확인하고, 상대가 고치는 중이면 기다린다.
- 두 세션이 같은 작업 공간(Git worktree)을 쓴다. 커밋은 사용자가 요청할 때만 하고 자기 파일만 경로를 지정해 올린다. `git add -A`, `git commit -a`, `git stash`는 쓰지 않는다.

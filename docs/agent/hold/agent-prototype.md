## 진행 기록

- 2026-11-04 작업 파일을 만들었다.
- 2026-11-05 version-pinning에서 Go를 1.27 계열로 고정했고(D17 공식 자료 조사 8절) 같은 날 사용자 요청으로 이 PC에 1.27.3을 설치했다. 남은 조건은 구현 시작 요청이다.
- 2026-11-05 사용자가 A안으로 구현 시작을 요청했다. 합의한 첫 범위: 저장소 `agent/` 폴더의 Go 모듈, 로그 파일 하나와 파일명 규칙 읽기, 회전 추적(이름 바꾸기·copytruncate·읽기 전 삭제), 디스크 대기와 순번, 계약 2절대로 묶음 보내기·재시도·상태 보고, 받는 쪽은 시험용 가짜 수신 서버. journald·systemd 설치·자원 강제 제한은 다음 범위다. 이 PC(macOS)에서 개발하고 Linux 전용 동작과 M7 측정은 Linux에서 다시 확인한다. 단계: 1 파일 따라 읽기(회전 추적), 2 이벤트 조립(한 줄·여러 줄·크기 상한·D02 시작 경계), 3 디스크 대기와 순번·읽기 위치 확정, 4 묶음 보내기와 가짜 수신 서버, 5 파일명 규칙·상태 보고·설정 파일. 외부 라이브러리 없이 표준 라이브러리만 쓴다(설정 파일 TOML은 5단계에서 다시 본다).
- 2026-11-05 1·2단계를 만들었다. `agent/internal/tail`은 stat 확인으로 경로 하나를 따라 읽고 장치·inode로 파일을 구분한다. 이름 바꾸기 회전은 옛 파일이 조용해질 때까지 마저 읽고 넘어가며 다음 파일은 미리 열어 둬 연속 회전에도 놓치지 않는다. copytruncate는 크기와 파일 앞부분 내용으로 알아보고, 지워진 파일은 보유 시간이 지나면 남은 바이트를 잃은 것으로 보고하며 닫는다. 재시작 뒤에는 같은 폴더에서 inode로 옛 파일을 찾아 이어 읽는다. `agent/internal/assemble`은 한 줄·JSON·여러 줄 형식으로 이벤트를 묶고 D02 시작 경계, D03 상한(본문 없는 거부 하나), 파일이 바뀌면 이벤트를 끊는 규칙(AG-08), 재시작용 체크포인트를 지킨다. 시험 26개가 macOS에서 `-race`로 통과했다(실행 검증은 이 시험까지다). 알려진 한계: 단일 파일 연결에서 멈춘 사이 회전이 두 번 이상 일어나면 중간 파일을 알 수 없어 순서 미확인으로만 표시한다. 줄바꿈 없이 멈춘 마지막 줄은 파일이 바뀔 때까지 붙잡는다. 회전 유예 동안 앱이 옛 파일에 계속 쓰면 새 파일 읽기가 그만큼 늦어진다.
- 2026-11-05 3단계를 만들었다. `queue`는 연결·세대마다 세그먼트 파일에 순번과 길이·CRC를 붙여 쓰고 디스크에 확정한다. 열 때 쓰다 멈춘 끝은 잘라 내고, 수신 확인된 순번까지 지우되 마지막 세그먼트는 남긴다. 형식 버전이 다르거나 이미 확인된 기록이 사라졌으면(다시 읽으면 새 순번으로 중복 저장되므로) 지우지 않고 멈춘다. `record`는 대기 기록과 수신 서버로 보낼 기록(계약 2.3절)의 형식이다. `collect`는 읽기 위치를 따로 두지 않고 기록마다 "이 기록 다음 위치"를 함께 대기에 확정한다. 그래서 묶음을 쓰다 멈춰도 마지막으로 온전히 확정된 기록 다음부터 원본을 다시 읽어 중복도 유실도 없다. 대기가 한도에 닿으면 읽기만 멈추고 90% 아래로 내려가면 재개하며(D01), 디스크에 쓰지 못하면 기록을 들고 더 읽지 않고(D05), 재시작 위치를 잃었으면 처음부터 시작하지 않고 복구 보류로 둔다(D02). 시험 49개가 macOS에서 `-race`로 통과했다. 만들면서 찾은 계약의 빈 곳 두 가지(재설치 뒤 세대 번호, 원본 읽기 입출력 오류 사유)를 계약 초안 2.9절 남은 것에 적었다. 세대 번호는 4단계에서 정한다.
- 2026-11-05 4단계를 만들었다. `ship`은 대기의 기록을 gzip JSON 묶음으로 HTTPS 수신 서버에 보내고, 저장 끝 응답(`acked_through`)까지만 대기에서 지운다. 계약 2.4절 표대로 재시도(지수 백오프와 지터, `Retry-After`), 보류(키·보관·중복 대상·인스턴스 충돌·규약 불일치), 413 묶음 나누기를 한다. 키 보류 중 키 파일이 바뀌면 같은 순번부터 바로 다시 보낸다(Q10-11). 설정 버전이 바뀌는 곳에서 묶음을 끊는다(AT-09). 수신 서버가 이미 지운 순번을 다시 달라고 하면 보류한다. 3단계에서 찾은 세대 번호 문제는 수신 서버가 번호를 정해 주는 `POST /ingest/v1/generations`로 메우고 계약 초안 2.6절에 넣었다. `ingesttest`는 시험용 가짜 수신 서버(TLS)다. 원본 파일 → 대기 → 가짜 수신 서버를 잇는 시험 9개를 더해 모두 58개가 macOS에서 `-race`로 5번 반복 통과했다. 시제품은 전송 창을 1(응답을 받은 뒤 다음 묶음)로 두었고, 계약에 없는 보고 사유 `read_error`·`queue_corrupt`와 함께 계약 초안 2.9절 남은 것에 적었다.
- 2026-11-05 단계를 다시 나눴다. 파일명 규칙은 파일마다 재시작 위치가 필요해 "기록마다 그 파일의 다음 위치"만으로는 부족하므로(조용한 파일의 위치가 든 기록이 수신 확인 뒤 지워질 수 있음) 스냅샷과 기록을 함께 쓰는 재시작 상태로 6단계에서 따로 만든다. 5단계는 설정 파일·상태 보고·실행 파일이다.
- 2026-11-05 5단계를 만들었다. `config`는 에이전트 전체 설정과 연결 설정(TOML)을 읽고 계약 2.8절 입력 규칙을 검사한다. 외부 라이브러리를 들이지 않으려고 쓰는 TOML 문법(주석, 한 단계 표, 문자열·정수·참거짓)만 엄격히 읽고 그 밖의 문법과 모르는 키는 오류로 알린다. https만 받고 인증서 검증을 끄는 설정은 없으며, 키 파일을 다른 계정이 읽을 수 있으면 그 연결을 시작하지 않는다(SC-03). `status`는 계약 2.7절 상태 보고를 정기적으로, 상태가 바뀌면 빈도 제한 안에서 바로 보내고 모르는 값은 null로 보낸다. 누락 구간은 읽지 못한 내용의 시각을 알 수 없어 파일 위치·잃은 바이트·알아챈 시각으로 보내도록 계약 2.7절을 고쳤다. `agent`는 연결마다 읽기·보내기·상태 보고를 따로 돌리고, 잘못된 연결은 건너뛰며, 중지 신호에는 마지막 보고에 중지를 싣되 1초 넘게 기다리지 않고 멈춘다(Q05-02). `cmd/logdock-agent`는 `run`·`check`·`status`·`version`이다. 설정 예시(합성 값)를 `agent/examples`에 두고 시험으로 유효성을 지킨다. 시험 78개가 macOS에서 `-race`로 3번 반복 통과했고 Linux amd64·arm64용 빌드와 vet도 통과했다. Linux에서 시험을 실제로 돌리는 것과 M7 측정은 아직이다.
- 2026-11-06 6단계 파일명 규칙을 만들었고, 이것으로 처음 합의한 범위를 마쳤다. `tail.Watcher`는 폴더 하나를 1초마다 훑어 규칙에 맞는 일반 파일을 장치·inode로 구분해 따라 읽는다. 규칙 안에서 이름이 바뀐 파일은 같은 파일로 이어 읽고, 규칙 밖으로 나갔거나 지워진 파일은 마저 읽은 뒤 놓는다. 하위 폴더와 심볼릭 링크는 따라가지 않는다. 다 읽고 1분 조용한 파일은 닫아 두었다가 크기나 수정 시각이 바뀌면 다시 열고 앞부분으로 같은 파일인지 확인한다(동시에 여는 파일 32개, 따라가는 파일 1,024개, 넘으면 `file_limit`). 처음 보는 파일의 시작은 D02대로 가른다. 최초 연결 때 있던 파일은 끝, 연결 뒤 새로 나타난 파일은 처음부터 읽는다. 규칙을 바꿨거나 한도·열기 오류로 따라가지 못했던 파일은 언제 생겼는지 모르므로 끝에서 시작하고 건너뛴 크기를 누락으로 알린다(`new_file_tail`). 같은 규칙으로 다시 시작하면 상태에 없는 파일은 마지막으로 폴더를 본 뒤 생긴 것으로 보고 처음부터 읽는다. 정상 재시작에 끝 위치 규칙을 다시 쓰지 않는다는 D02 원칙에 맞춘 설계이며 계약 초안 2.3절에 적었다. `collect.PatternReader`는 파일마다 이벤트를 따로 묶는다. 조용한 파일의 위치가 든 기록은 수신 확인 뒤 지워질 수 있으므로, 모든 파일의 위치를 대기 폴더에 스냅샷으로 1초마다 확정한다. 대기는 스냅샷 뒤 기록을 지우지 않고, 재시작하면 스냅샷과 그 뒤 기록으로 위치를 되살린다. 스냅샷을 쓰지 못하면 더 읽지 않는다(D05). `check`는 규칙에 맞는 파일 수와 압축 파일이 섞였는지 알리고, 수집 대상 폴더가 상태 폴더 안이면 막는다. 입력 규칙의 설계(`[`·`]`·`\` 불가, 링크 미추종)는 계약 초안 2.8절에, 새 보고 사유 `file_limit`은 2.9절 남은 것에 적었다. 시험 109개가 macOS에서 `-race`로 5번 반복 통과했고 Linux amd64·arm64 빌드와 vet도 통과했다. Linux에서 시험을 실제로 돌리는 것과 M7 측정은 아직이다. 알려진 한계는 `agent/README.md`에 모았다.
- 2026-11-06 다음 범위(journald 입력, Q06 다시 수집 명령, systemd 자원 제한)는 처음 합의 때 다음 범위로 남겼으므로 사용자 확인을 기다리며 보류로 옮겼다.
- 2026-11-06 사용자가 다음 범위로 journald 입력을 골라([결정 기록](../../decisions.md)) 진행으로 되돌렸다. 7단계로 만든다. 설계와 합성 데이터 시험은 이 PC에서, 실제 journal 확인은 Linux 환경에서 한다.
- 2026-11-06 7단계 journald 입력을 만들었다. 공식 자료(journalctl·export 형식·커서·journal 필드·journald.conf, systemd 소스의 속도 제한 알림, Docker 문서와 Moby 드라이버 소스)를 확인하고 설계를 [수집 명세](../../specs/collection-agent-v0.1.md) journald 절의 `시제품 설계`와 계약 초안 2.3·2.7·2.8·2.9절에 적었다. `journal`은 `journalctl --output=export`를 하위 프로세스로 읽고, 나뉜 줄의 조각을 잇고, 형식대로 이벤트로 묶는다. 커서 문자열은 같은 항목도 다를 수 있어 비교하지 않고 항목 식별값으로 재시작 위치를 확인하며, 없으면 복구 보류다. 조각 사이에 다른 줄이 끼면 그 줄을 먼저 내고 처리한 항목을 위치와 함께 기억해 재시작에도 중복·유실이 없게 했다. 속도 제한 알림은 `source_dropped` 경계로 낸다. `collect.JournalReader`는 읽기 권한을 journal 파일로 확인하고, 대기가 차면 journalctl을 끝냈다가 확정한 위치에서 다시 띄운다. 설정은 `[target]`의 `kind`·`name`, `check`는 journalctl·권한·메모리 보관을 알린다. 만들면서 대기와 D01의 맞물림 문제를 찾아 고쳤다. 한 번에 쓴 기록이 한도의 대부분을 차지한 세그먼트는 수신 확인돼도 재시작 위치 때문에 마지막 세그먼트로 남아 읽기가 다시 시작되지 않았다. 멈춤·재개 판단을 수신 확인되지 않은 바이트(`queue.Unacked`)로 바꾸고 journald는 한 번에 쓰는 양을 1MiB로 묶었다. 시험 141개가 macOS에서 `-race`로 3번 반복 통과했고 Linux amd64·arm64 빌드와 vet도 통과했다. 실제 journal에서의 실행은 아직이다.
- 2026-11-06 실제 journal 확인은 사용자가 B안(중앙 서버가 준비되면)을 골라([결정 기록](../../decisions.md)) 이 PC에는 VM을 두지 않는다. 확인할 것은 수집 명세 journald 절 `시제품 설계`의 남은 것이다. 보류로 옮겼다.

# Q15 수치 제안

- 담당: 없음
- 우선순위: 1
- 선행: measurement-m1-m8(M7)
- 다음 할 일: M7(에이전트 자원 측정) 결과로 에이전트가 서비스 서버에서 쓸 CPU·메모리·디스크 I/O 상한을 A안·B안으로 제시한다
- 막힌 이유: 에이전트 시제품의 자원 사용을 아직 재지 않았다(M7)
- 풀리는 조건: measurement-m1-m8의 M7 완료
- 마지막 갱신: 2026-11-07

## 목표와 완료 조건

남은 사용자 협의인 Q15의 지연·용량 수치를 측정 근거로 제안하고 합의를 받는다. 답을 받으면 `plan-apply`로 반영한다. 사용량이 더 많은 서비스의 하루 로그량(사용자 실측)은 중앙 디스크와 에이전트 대기 크기를 제안할 때 입력으로 쓴다.

## 진행 기록

- 2026-11-04 작업 파일을 만들었다.
- 2026-11-07 M1~M4 측정과 첫 수집 대상 로그량으로 세 안건을 제시했고 사용자가 1A(검색 가능 지연 95% 10초 안), 2A(본문 검색 한 번에 7일 이하, 기본 기간 24시간, 서비스 먼저 선택), 3A(에이전트 대기 서버마다 500MB)를 골랐다([결정 기록](../../decisions.md)). M5~M8을 기다리지 않고 측정한 범위로 제안했다. 잔여 사용자 협의 Q는 0개다.
- 2026-11-07 사용자 요청으로 이날 결정을 다시 검토했다. 본문 검색 7일 제한은 기존 설계 SD-31과 구현된 검색 API(요청당 10초 예산, 부분 결과와 이어 보기)를 빼고 설명한 탓이라 다시 제시해 C안(SD-31 유지)으로 바뀌었다. 에이전트 자원 상한을 정하지 않은 채 닫은 것을 확인해 Q15를 유보로 다시 열고 이 파일을 보류로 되돌렸다([결정 기록](../../decisions.md)).

# LogDock 디자인 시스템 초안 v0.1

작성일: 2026-11-05. **상태: 설계 초안이다.** 사용자가 정한 것은 [결정 기록](../decisions.md) 2026-11-05 "웹 프런트 기반과 디자인 시스템 방향"의 다섯 가지(React 유지, Base UI와 직접 스타일, 정보 밀도가 높은 운영 도구형, 첫 출시 밝은 테마만, CSS 변수와 CSS Modules)와, 같은 날 채택한 시각 기준(7.1절 v0.2 모양과 로그 탐색 시안의 배치, 결정 기록 "디자인 시스템 시각 기준 채택")이다. 이 문서의 세부 값과 상태 대응은 그 합의 안에서 정한 설계 기본안이며 화면 구현 승인이 아니다.

## 1 기준과 범위

- **입력:** [화면 흐름 명세](../specs/screen-flows-v0.1.md) 1·4절, [검색·조사 상세](../specs/investigation-workflows-v0.1.md) 8절, [와이어프레임](../wireframes/index.html).
- **환경:** 데스크톱 Chrome 한 화면, 가로 1280px 기준(Q15-01, 와이어프레임 기준).
- **접근성 목표:** WCAG 2.2 AA의 색 대비(1.4.3 글자 4.5:1, 1.4.11 비글자 3:1), 초점 표시(2.4.7), 최소 누름 크기(2.5.8 24px). 평가 수준의 최종 확정은 D16 지원표를 따른다.
- **상태 표시:** 색만으로 구분하지 않는다. 모든 상태 배지와 배너는 상태 이름 글자를 함께 쓴다(화면 흐름 명세 1절).
- **이름:** 상태 이름은 화면 흐름 명세의 것을 쓴다. API 계약 초안에서 이름이 바뀌면 이 문서의 글자만 고치고 색 대응은 유지한다.

## 2 토큰 구조

두 단계로 나눈다.

1. **팔레트**(`--palette-*`): 색과 밝기만 뜻한다. 예: `--palette-red-700`.
2. **용도**(`--color-*`, `--text-*`, `--space-*` 등): 화면이 쓰는 이름이다. 예: `--color-danger-fg`.

화면 코드와 정적 시안은 용도 토큰만 쓴다. 어두운 테마를 더할 때는 용도 토큰을 다시 정의하는 블록 하나만 추가하고 화면 코드는 고치지 않는다(합의 3A). CSS Modules 안에서도 값을 직접 쓰지 않고 `var(--…)`로 부른다(합의 4A).

## 3 색

### 3.1 바탕·글자·선

| 용도 | 토큰 | 쓰는 곳 |
| --- | --- | --- |
| 화면 바탕 | `--color-bg-page` | 본문 뒤 |
| 표면 | `--color-bg-surface` | 패널, 표, 입력 칸 |
| 옅은 바탕 | `--color-bg-subtle` | 표 머리, 코드·로그 원문 상자 |
| 올림 | `--color-bg-hover` | 행·메뉴에 마우스를 올렸을 때 |
| 고름 | `--color-bg-selected`, `-strong` | 고른 행, 고른 값, 현재 메뉴 |
| 흐림 | `--color-bg-dim` | 지금 조건의 결과가 아닌 영역(와이어프레임 `.wf-dim`) |
| 글자 | `--color-text`, `-secondary`, `-tertiary`, `-disabled` | 본문 / 시각·출처·설명 / 표 머리·항목 이름(흰 표면·화면 바탕에서만) / 비활성 |
| 선 | `--color-border`, `-strong`, `-control` | 장식 구분선 / 표 머리 아래 / 입력·체크 상자 |

입력 칸과 체크 상자 테두리(`--color-border-control`)는 바탕과 3:1 이상이다. 패널 구분선은 장식이라 대비 기준을 적용하지 않고 옅게 둔다. 밀도가 높은 화면에서 선이 글자보다 눈에 띄지 않게 하기 위해서다.

### 3.2 주 동작과 초점

- **주 동작**(`--color-accent`, 인디고 `#4f46e5`): 주 버튼, 체크 상자, 고른 행의 왼쪽 막대. 옅은 강조 바탕(`--color-accent-subtle`)과 강조 글자(`--color-accent-fg`)는 현재 메뉴와 분할 버튼 선택에 쓴다. 강조색은 이 자리에만 쓰고 장식에 퍼뜨리지 않는다.
- **고름**(`--color-bg-selected`, 옅은 인디고), **검색어 일치**(`--color-match-bg`, 인디고 16%), **링크**(`--color-text-link`, 진한 인디고).
- **초점**(`--color-focus`, 강조색): 고른 행의 옅은 인디고 위에서도 3:1 이상이다.
- 상태 색을 주 동작이나 고름에 쓰지 않는다. `성공`과 `고름`을 섞어 읽지 않게 하기 위해서다. 같은 이유로 상태 `info`는 강조색과 다른 하늘색 계열이다.
- 경과: 첫 미리보기의 청록은 투박하다는 의견으로 무채색(거의 검정)으로 바꿨고, v0.2의 검정 주 동작은 칙칙하다는 의견으로 2026-11-05 인디고로 바꿨다(7.4절).

### 3.3 상태 색

상태는 여섯 가지 색 묶음으로만 나타낸다. 묶음마다 글자(`-fg`), 바탕(`-bg`), 표시점·막대(`-border`)가 있다.

- **배지:** 테두리 없는 옅은 바탕의 알약 모양에 상태 글자와 앞의 작은 표시점을 쓴다. `미확인`만 점선 테두리다.
- **로그 레벨:** 표 안에서는 배지 대신 작은 네모와 굵은 색 글자(Pretendard 12px 600)로 쓰고, `ERROR` 행은 옅은 빨강 바탕을 깐다.
- **배너·토스트:** 배너는 상태 바탕에 상태 이름 배지를 함께 둔다. 토스트는 반전 색 바탕에 종류 글자와 점을 쓴다.

| 묶음 | 뜻 | 모양 |
| --- | --- | --- |
| `success` | 기대한 대로 진행·완료 | 초록 |
| `info` | 진행 중이거나 기다리는 중, 알릴 것 | 하늘색(강조색 인디고와 구분) |
| `warning` | 확인이 필요하지만 멈추지 않음, 일부만 됨 | 주황 |
| `danger` | 실패, 막힘, 지금 고쳐야 함 | 빨강 |
| `unknown` | 모른다(`미확인`). 정상으로도 오류로도 보이지 않게 함 | 회색 + **점선 테두리** |
| `neutral` | 문제도 성공도 아님(보관, 취소, 실행 전) | 회색 실선 |

`미확인`을 0이나 정상으로 채우지 않는다는 운영 명세 4절을 따라 `unknown`을 `neutral`과 다른 모양(점선)으로 둔다.

### 3.5 차트 색

발생량 그래프는 상태 색과 따로 `--color-chart-level-*` 세 가지를 쓴다. 막대 면적은 배지 글자보다 채도가 높아야 구분되기 때문이다.

- `ERROR`(빨강 `#d92d48`), `WARN`(주황 `#e5a00d`), `INFO·미확인`(옅은 인디고 `#7c82f4`) 순서로 아래에서 위로 쌓는다. 미확인은 그래프에서 INFO와 합치고 왼쪽 항목별 건수에서 따로 센다. 기타 막대는 강조색보다 한 단계 옅게 둬 그래프가 화면을 덮지 않게 한다.
- 2026-11-05 v0.2b 채택 때 dataviz 검증 스크립트로 밝기 범위, 채도, 색각 이상 구분(모든 쌍 최소 ΔE 18.3), 일반 시각 구분을 통과했다. `WARN` 색은 바탕 대비 2.18:1이라 범례, 마우스 툴팁, 결과 표로 같은 값을 함께 보여 준다. 처음 v0.2 값(`#c02a3c`·`#d8940f`·`#5b82d6`)은 채도가 낮아 탁해 보였다.
- 쌓인 조각 사이에 2px 바탕 틈을 두고 맨 위 끝만 둥글게 한다. 격자는 옅게 세 줄만 둔다.

## 5 글자 크기

기본 본문은 14px, 로그 표 칸은 13px다. 처음에는 밀도를 우선해 기본 13px로 뒀으나 2026-11-05 v0.2b 채택으로 올렸다(7.4절). 밀도는 행 높이와 표 칸 크기로 지킨다(합의 2A).

| 토큰 | 크기 / 줄 높이 | 쓰는 곳 |
| --- | --- | --- |
| `--text-sm` | 12 / 16px | 배지, 보조 정보, 단위, 표 머리 |
| `--text-table` | 13 / 20px | 로그 표 칸, 항목별 건수 이름. 한 줄 안의 칸은 같은 크기(6.1절) |
| `--text-md` | 14 / 20px | 기본 본문 |
| `--text-base` | 14 / 20px | 입력 칸, 버튼, 폼 라벨 |
| `--text-lg` | 16 / 24px | 패널·절 제목 |
| `--text-xl` | 20 / 28px | 화면 제목 |

12px보다 작은 글자는 쓰지 않는다(상단 메뉴의 건수 숫자 11px만 예외). 굵기는 400(본문), 500(배지·버튼·표 머리), 600(제목) 세 가지다.

## 6 간격과 크기

- 간격은 4px 단위다(`--space-1` 4px ~ `--space-10` 40px). 2px(`--space-0-5`)는 배지 안쪽처럼 좁은 곳에만 쓴다.
- 입력·버튼 높이는 32px, 표 안의 작은 버튼과 칩은 24px다. 24px는 WCAG 2.5.8 최소 누름 크기다.
- 로그 결과 표는 한 줄 32px, 관리 목록 표는 36px다. 로그 결과는 훑어보는 표라 더 촘촘하게, 관리 목록은 행마다 동작 버튼이 있어 조금 넉넉하게 둔다. 로그 표는 처음 28px였고, 글자를 키우면서 행이 좁아 보인다는 의견으로 2026-11-05 32px로 올렸다. 800px 높이에서 보이는 줄은 28줄에서 25줄로 준다.
- 상단 메뉴는 44px다. 화면 최소 폭은 와이어프레임과 같은 1280px이다.

### 6.1 정렬 규칙 (2026-11-05 채택)

사용자가 시안의 상자 안 글자 중앙이 맞지 않고 검색 막대와 아래 그래프의 왼쪽 선이 다르다고 지적했다. 이런 어긋남은 화면마다 손보는 것이 아니라 규칙으로 막는다. tokens.css·components.css와 로그 탐색 시안에 반영했다. 화면을 구현할 때 화면마다 이 규칙에 맞는지 확인한다.

1. **같은 열 기준선.** 위아래로 이어지는 줄(도구 줄, 작업 영역)은 같은 바깥 여백(`--layout-pad-x` 16px), 같은 왼쪽 열 폭(`--layout-side` 240px), 같은 열 사이 간격(`--layout-gutter` 12px)을 쓴다. 예: 시간 선택 칸 폭이 왼쪽 항목별 건수 폭과 같아서, 검색 막대와 그래프의 왼쪽 선이 일치한다. 상자 안 첫 아이콘도 아래 체크 상자와 같은 세로선에 둔다.
2. **상자 안 글자는 글자 높이로 가운데.** 높이가 정해진 상자(버튼·칩·배지·메뉴·분할 버튼·숫자 배지)는 flex·grid로 가운데 정렬하고, 글자는 `text-box: trim-both cap alphabetic`로 글꼴의 위아래 여백을 잘라 대문자 높이~기준선을 기준으로 맞춘다. 줄 높이(`line-height`)로 가운데를 맞추지 않는다. `text-box`는 Chrome 133부터 지원하며 첫 출시는 데스크톱 Chrome 한정이다(Q15-01).
3. **표 칸은 기준선을 맞춘다.** 표 칸은 칸마다 따로 세로 가운데에 맞춰지므로, 한 줄 안의 칸 글자 크기를 하나로 둔다(로그 표 13px, 고정폭 본문 12.5px도 같은 기준선에 온다). 레벨처럼 앞에 표시점이 붙는 글자는 인라인 글자로 두어 칸의 줄 상자를 바꾸지 않는다.
4. **손 보정 금지.** `top: -1.5px` 같은 px 보정을 쓰지 않는다. 어긋나면 원인(글꼴 여백, 표시점이 기준선이 되는 문제, 섞인 글자 크기)을 고친다.

확인 방법: 브라우저에서 각 칸에 크기 0인 인라인 상자를 넣어 기준선 위치를 비교하고(로그 표 다섯 칸이 같은 값), 왼쪽·오른쪽 끝 좌표를 비교한다. 2026-11-05 Orca 탭에서 이 방법과 확대 캡처로 확인했다.

## 7 모서리와 그림자

- 모서리는 4px(배지 안 네모·칩 단추), 6px(입력·버튼), 8px(검색 막대·팝오버·토스트), 12px(카드·상세 패널·확인 창)다. 상태 배지는 알약 모양이다.
- 카드와 버튼은 회색 테두리 대신 아주 옅은 고리 그림자(`--shadow-card`)로 바탕에서 띄운다. 테두리 선이 겹쳐 보이지 않아 화면이 가볍다.
- 진한 그림자는 떠 있는 요소에만 쓴다: 팝오버, 토스트, 상세 패널, 확인 창.

### 7.1 v0.2 모양 (2026-11-05)

사용자가 첫 다듬기 뒤에도 "트렌디하지 않다"고 해, 배치는 그대로 두고 요즘 개발 도구(Linear, Vercel, Axiom, Better Stack)에서 흔한 처리를 들였다. 모양은 각 제품을 베끼지 않았다.

- 도구 막대와 항목별 건수는 흰 띠 없이 화면 바탕 위에 두고, 검색 막대·그래프·결과만 카드로 띄운다.
- 상세 패널은 화면 끝에 붙이지 않고 8px 띄운 둥근 시트로 연다.
- 토스트는 반전 색(밝은 테마에서 검정 바탕)으로 띄워 화면 내용과 구분한다. 종류 글자(`성공`·`실패`·`보류`·`안내`)와 점을 함께 쓴다.
- 체크 상자, 단축키 표시(`↵`), 결과 건수 글자 위계를 다듬었다.

사용자가 v0.2를 채택한 직후 "너무 AI틱하다"고 해, 장식을 걷어낸 v0.3을 만들었다. 사용자는 v0.3을 보고 v0.2가 더 낫다며 v0.2로 되돌리는 A안을 골랐다. **현재 기준은 v0.2다.** v0.3은 [components-v03.css](components-v03.css)와 [v0.3 시안](sample-ui02-log-search-v03.html)으로 비교용으로만 남긴다. 아래는 v0.3을 만들 때 쓴 진단과 원칙이며 채택한 기준이 아니다.

진단은 흔한 생성 UI 기본 미감, 장식 반복, 옅은 색 상자 남용, 색 원칙 위반(그래프의 INFO 파랑), 가짜 티가 나는 데이터, 설명 문장, 평평한 위계, 카드에 갇힌 표였다.

1. **로그가 주인공이다.** 표를 카드에 넣지 않고 화면 폭을 다 쓴다. 상세 패널은 떠 있는 시트 대신 오른쪽에 붙고, 열리면 왼쪽 항목별 건수를 접어 표 폭을 지킨다.
2. **색은 문제에만.** 발생량 그래프는 전체를 회색(`--color-chart-volume`)으로 두고 `ERROR`·`WARN`만 칠한다. dataviz 지침의 "하나를 강조하고 나머지는 회색" 형식이며, 회색은 범주 색 검증 대상이 아니고 범례 대신 툴팁·항목별 건수·결과 표로 값을 보인다. 옅은 색 바탕은 전역 배너와 수집 문제 구간에만 쓴다.
3. **장식 반복 금지.** 배지 점, 알약, 고리 그림자, 체크 상자 장식, 단축키 표시를 뺐다. 조건은 칩 상자 대신 `service:billing` 같은 고정폭 글자이고 지울 때만 ×가 보인다.
4. **강조는 하나.** 결과 건수만 20px 600으로 크게 쓰고 나머지는 회색 위계로 물러난다. 버튼은 `실행` 하나만 검정이고 나머지는 글자 버튼이다.
5. **문구는 짧게.** 설명 문장을 값과 이동할 곳으로 바꿨다. 예: `app-02 수집 멈춤 13:40–13:52 — 이 구간 결과가 빠졌을 수 있음 · 수집 연결`.
6. **데이터는 실제처럼.** 합성 로그를 nginx 접근 로그, JSON, 스택 첫 줄(`+4줄`), 한글 배치 로그, 레벨 없는 줄로 섞었다. 실제 조직·서버 값은 쓰지 않았다.
7. **정체성은 하나만.** 로고를 길이가 다른 세 로그 줄과 빨간 짧은 줄로 그렸다. 다른 곳에는 브랜드 장식을 두지 않는다.

v0.3은 7.1절의 고리 그림자 카드·반투명 상단 메뉴·알약 메뉴·떠 있는 상세 시트를 뺐고 반전 토스트와 글꼴은 유지했다. 사용자는 이 결과를 후퇴로 봤다. 위 진단 가운데 데이터·문구·그래프 색 같은 모양과 무관한 개선은 사용자가 원할 때 v0.2에 따로 적용할 수 있다.

### 7.4 v0.2b 색·글자·정렬 (2026-11-05 채택)

사용자가 v0.2를 칙칙하다고 해 [조사 문서](../research/central-log-ui-design-research-2026-11-05.md)의 Sentry·Datadog·Axiom 캡처와 비교했다. 원인은 강조색이 검정이라 색이 상태에만 있는 것, 베이지·분홍·겨자 같은 따뜻하고 탁한 색의 조합, 작은 회색 고정폭 글자였다. 사용자가 고른 1A·2A와 이어진 표 행 A안·정렬 A안을 비교안으로 만들어 보인 뒤, 사용자가 채택했다. 값은 tokens.css·components.css로 옮기고 비교용 파일은 지웠다. 부품 모양과 배치는 v0.2 그대로다.

- 강조색 인디고(`#4f46e5`): 주 버튼, 체크 상자, 현재 메뉴, 분할 버튼 선택, 고른 행, 검색어 일치 바탕. 상태 `info`는 겹치지 않게 하늘색 계열로 옮겼다.
- 차트: 기타 `#7c82f4`, WARN `#e5a00d`, ERROR `#d92d48`. dataviz 검증 모든 쌍 통과, WARN은 바탕 대비 3:1 미만이라 범례·툴팁·결과 표를 함께 둔다.
- 글자: 기본 14px, 표 머리 12px, 로그 표 칸 13px. 시각·서버·레벨은 Pretendard 고정폭 숫자, JetBrains Mono는 본문·필드 이름·원문 상자에만.
- 로그 표 행 28→32px. 800px 높이에서 보이는 줄이 28줄에서 25줄로 준다.
- 6.1절 정렬 규칙.

- 고른 행 바탕이 옅은 인디고로 바뀌며 `success` 글자가 4.43:1로 미달해 한 단계 진한 초록(`#166534`)으로 바꿨다.
- 어두운 테마 검토용 파일도 같은 날 인디고 강조·하늘색 info·차트 기타 색으로 맞췄다(7.2절).

### 7.2 어두운 테마 검토용 미리보기

[tokens-dark-preview.css](tokens-dark-preview.css)는 사용자가 어두운 테마를 비교해 볼 수 있게 만든 **검토용**이다. 2026-11-05 합의(3A)대로 첫 출시는 밝은 테마만이고, 이 파일은 채택이 아니다. 시안 오른쪽 위 `어두운 테마 보기` 단추나 주소 끝 `?theme=dark`로 연다. 용도 토큰만 다시 정의해 화면 코드는 그대로 두는 구조가 동작하는 것을 보여 준다. 글자·상태 색 대비는 정적 계산으로 4.5:1, 입력 테두리·표시점·초점은 3:1 이상이고, 차트 색은 dataviz 검증 스크립트(어두운 표면)를 통과했다. 이 파일은 check-contrast.mjs의 계산 대상이 아니다.

## 8 초점 표시

- 키보드 초점(`:focus-visible`)에만 2px 실선 `--color-focus`를 그린다. 마우스로 누를 때는 그리지 않는다.
- 버튼·입력은 바깥 2px 띄우고(`--focus-ring-offset`), 표 행·셀처럼 바깥 공간이 없는 곳은 안쪽으로 그린다(`--focus-ring-offset-inset`).
- 초점 색은 모든 바탕(표면, 화면 바탕, 옅은 바탕, 올림, 고름)과 3:1 이상이다.
- 상세를 닫으면 원래 행으로 초점을 돌린다(조사 명세 8절). 실시간 유입은 초점·고른 행을 빼앗지 않는다. 토스트도 초점을 빼앗지 않는다(CM-08). 이 동작은 부품 단계에서 Base UI 동작과 함께 정한다.

## 9 움직임과 겹침

- 움직임은 120ms(올림·펼침)와 200ms(토스트 등장)만 쓴다. 운영체제의 "동작 줄이기" 설정이 켜지면 0으로 바꾼다.
- 겹침 순서는 표 머리·상단 메뉴 < 팝오버 < 확인 창 < 토스트다. 토스트가 확인 창 위에 보이는 것은 확인 창의 실행 결과를 바로 알리기 위해서다.

API가 돌려주는 다른 값의 표시:

- **UI-04 끝난 이유:** `stream_start` 흐름의 처음입니다, `order_unknown` 파일 회전 순서를 확인할 수 없어 더 가지 않습니다, `retention` 보관 기간이 지나 앞의 로그가 없습니다, `limit` 조회 한도에 닿았습니다(더 불러오기), `unobserved` 이 연결을 지금 관측할 수 없습니다. 목록 끝의 `.callout`으로 쓴다.
- **UI-08 사건을 닫는 이유:** `해소`·`조건 수정`·`규칙 꺼짐`·`규칙 삭제` 네 가지다(API 3.4절 저장 값과 화면 이름). `조건 수정`은 API에서 새로 생겼다.
- **UI-10 `조치 필요`:** API 4.4절 계산을 그대로 쓴다. 오래 이어진 `등록·연결 대기`에는 `설정을 적용하지 않았을 수 있음`을 붙이고, 거부는 따로 확인하지 않고 시간이 지나면 빠진다.
- **UI-11 7단계:** 단계마다 처음 확인 시각을 받아 `.steps`의 시각 칸에 쓴다.
- **UI-12 복구 보류:** API 8.3절의 `logdock-agent resume-from-now` 명령과 대상 파일을 `.secret-box`와 같은 고정폭 상자에 복사 버튼과 함께 보인다(시안 `?state=hold`).
- **UI-12 서버 표시명:** `서버 이름 바꾸기`(이름 목록의 이름을 고침, 같은 서버의 모든 연결에 보임)와 `이 연결의 서버 바꾸기`(이 연결을 다른 서버 이름에 붙임)를 다른 버튼과 문구로 둔다(WQ-63).

- **묶음 2 다시 점검(2026-11-06):** 사용자 요청으로 정리표 WQ-30~49, API 계약 5.4~5.6절, 이 문서 11·12절과 시안을 다시 대조해 고쳤다. 목록 행의 최종 실패 미확인에서 사건으로 바로 가기(WQ-32), `전송 여부 불명`을 상태 배지로, 사건의 `일부 구간만 평가`(TD-13), 메일 설정이 없을 때 꺼진 채 저장(WQ-38), `받았음`을 저장과 함께 반영(API 5.6절 감사 대상), 이름 100자(TD-01), 재시도 횟수·시각을 Q12-09 일정에 맞추고 수신자마다 마지막 시도 시각, 목록에서 누른 규칙의 상세·사건 열기, 상세에서 끄면 `규칙 꺼짐`으로 닫힘, 조건 요약 둘째 줄의 임계, 평가 중단 표시 줄이기, 편집 떠나기 확인, 사건 이력 더 보기를 반영했다. 감시 품질 필터는 WQ-37대로 두지 않았다. 30개 시안 상태를 모두 그려 스크립트 오류가 없음을 확인했고, 화면 사이 흐름 6개를 클릭으로 따라갔고, 목록 평가 중단·최종 실패, 상세 꺼짐·평가 실패(어두운 화면), 편집 메일 설정 없음, 사건 재시도 중·최종 실패(어두운 화면)를 스크린샷으로 봤다. 콘솔 오류는 없었다.

- **묶음 4 화면 확인(2026-11-06):** 검색 보조 시안의 29개 상태를 모두 그려 스크립트 오류가 없음을 확인했다. 로그인 알림 링크, 알림 조사 당시와 현재 다름·조기 삭제 0건, 주변 로그 빈 자리 표시·시간순, 저장 검색 수정 창·보관 참조 실행(어두운 화면), 로그 탐색 시안의 규칙 상한 상태를 스크린샷으로 봤다. 알림 링크 로그인 뒤 알림 조사로 이동, 조사 중 세션 만료 뒤 다시 로그인해 돌아오기, 정렬만 바꾸면 모드 유지, 칩을 지우면 모드 벗어남, 판정 불가 보기·원래 결과로, 저장 검색 이름 중복·덮어쓰기·수정 중 삭제 뒤 새 항목으로 저장, 회전 순서 미확인에서 시간순으로 전환을 클릭으로 따라갔다. 콘솔 오류는 없었다. 시안끼리 메뉴(`저장 검색`·`알림`), 사건의 `조사 열기`, 이벤트 상세의 `주변 로그`, 로그 탐색의 규칙 만들기 버튼을 이었다.
- **시안 상태 보완(2026-11-06, 작업 mockup-states):** 와이어프레임 24개 파일의 상태 목록을 시안과 대조해, 대표 시안 2개와 공통 요소에서 빠진 상태를 세 묶음으로 그렸다. 묶음마다 만들기 → 스스로 리뷰 → 고치기 → 다시 리뷰 순서로 진행했다. 묶음 5는 로그 탐색 상태 21개, 묶음 6은 이벤트 상세 상태 17개, 묶음 7은 수집 연결 상세 상태 15개와 공통 요소(CM-01 배너 여러 개·조치 필요 미확인, CM-07 재인증 유효·비밀번호 오류·감사 장애 보류·긴급 키 폐기, CM-08 토스트 겹침)다. 리뷰에서 고친 것은 다음과 같다.
  - 숨김 속성이 부품의 `display`에 덮여 안내·더 보기·그래프 덮개가 남던 문제를 고쳤다.
  - 끝나지 않은 결과는 범례·항목 건수를 `—`로, 부분 결과는 완료 구간만 세도록 고쳤다.
  - 상세 패널을 고른 행의 내용으로 맞췄다.
  - 수집 연결 상세에서 상태마다 어긋나던 설정 버전을 맞췄다. 원래 있던 `수집 문제`·`미관측`·`복구 보류`도 함께 고쳤다.
  - 보류 토스트의 조사를 고쳤다.
  - 공통 부품을 고쳤다. 배너 링크는 줄바꿈하지 않고, 어두운 테마에서 배너 `확인` 단추가 보이게 했다.
  - 디자인 시스템 11절 WQ-21에 맞춰 상세 패널의 복사 아이콘을 `본문 복사`·`필드 복사` 두 버튼으로 바꿨다. 기본 장면도 바뀌었다.

  모든 상태를 그려 스크립트 오류가 없음을 확인했고, 주요 흐름(조건 저장, 필드로 조건 추가와 닫기, 재활성, 설정 수정, 감사 장애 보류)을 클릭으로 따라갔다. 어두운 화면에서는 검색 완료 0건과 배너 여러 개를 봤다. 콘솔 오류는 없었고 대비 60쌍은 모두 통과했다. 남긴 것: 로그 탐색 기본 장면은 필드 조건이 없는데 `판정 불가 37건 제외`를 보인다. 승인된 기본 장면이라 그대로 두었다.
- **판정 불가 표시 맞춤(2026-11-07):** 판정 불가는 필드·레벨 조건이 있을 때만 생긴다. 사용자 승인(A안)으로 로그 탐색 기본 장면에서 `판정 불가 37건 제외`를 뺐다. 필드 조건 없이 판정 불가를 보이던 `완료 0건`과 `판정 불가만 보기` 장면에는 필드 조건 `http.status ≥ 500`을 더했다. `보기`를 누르면 판정 불가만 보기로 가고, `원래 결과로`를 누르면 완료 0건으로 돌아간다. 목록만 바뀌므로 판정 불가만 보기에서도 그래프와 항목별 건수는 원래 결과인 0건을 보인다(WQ-06). 같은 확인에서 완료 0건의 수집 문제 표가 카드 오른쪽으로 12px 넘치던 문제도 고쳤다. 상태 21개를 모두 그려 콘솔 오류가 없음을 확인했고, 보기와 원래 결과로를 클릭으로 따라갔다.
- **실행하지 않은 것:** 실제 화면에서의 대비 측정, 화면 낭독기 확인, 글꼴 파일 렌더링 확인. 미리보기 HTML은 글꼴 파일을 넣지 않아 Pretendard·D2Coding이 설치되지 않은 PC에서는 시스템 글꼴로 보인다.

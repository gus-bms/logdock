UI-07 알림 규칙 편집

알림 규칙을 만들고 고친다. 알림 규칙 목록(UI-06)의 새 규칙, 규칙 상세(UI-08)의 수정, 로그 탐색(UI-02)의 현재 조건으로 알림 규칙 만들기로 연다. 알림 규칙 변경에는 비밀번호 재확인(CM-07)을 쓰지 않는다.

근거: Q12-01 Q12-03 Q12-04 Q12-12 TD-05 TD-17 SD-09 SD-30 · 기준: 화면 흐름 명세 5절 UI-07, 4절 CM-03, 7절

예상 동작

  • 평가할 때마다 중앙 수신 시각 기준 최근 15분 동안 조건에 맞는 로그를 셉니다. 20건 이상이 되면 처음 한 번 수신 주소 3곳에 메일을 보냅니다.
  • 계속 20건 이상이면 지속입니다. 오류가 계속된다는 뜻이며 메일을 다시 보내지 않습니다.
  • 20건 아래인 상태가 15분(해소 대기) 이어지면 해소됩니다. 오류가 멈춰도 구간에서 빠지기까지 최대 15분이 걸려, 해소까지 약 30분이 걸릴 수 있습니다.
  • 해소된 뒤 다시 20건 이상이면 새 메일을 보냅니다. 해소됐을 때는 따로 메일을 보내지 않습니다.
  • 레벨을 읽지 못한 로그(미확인)와 판정 불가 로그는 세지 않습니다.

  • 요소는 5절 UI-07을 따른다: 이름, 조건(CM-03), 시간 구간, 임계 건수, 해소 대기, 수신 주소, 최근 구간의 실제 건수 미리보기, 예상 동작 문구. 동작은 저장, 테스트 메일 발송(상태 8), 삭제(상태 9)다.
  • 조건 편집기는 CM-03 상태 2의 마크업 그대로다. 알림 규칙에서는 집계가 중앙 수신 시각 기준임을 편집기 위에 표시한다(5절 UI-07, CM-03 상태 7, Q12 1절). 늦게 도착한 로그도 수신 시점의 구간에서 센다(TD-14).
  • 시간 구간 1~1,440분, 1·5·15·60분 버튼, 임계 1 이상이며 둘 다 기본값이 없다(Q12-01, 7절). 비교는 항상 임계 이상이다(TD-01). 해소 대기는 1~1,440분이고 비우면 시간 구간과 같다(Q12-03).
  • 그림의 15분·20건은 사용자가 넣은 값의 합성 예시이며 기본값이나 추천값이 아니다.
  • 수신 주소는 1개 이상(Q12 1절), 최대 10개, 저장 때 형식만 검사하고 확인 안 됨으로 표시한다(Q12-12). 새 주소는 다음 사건부터, 지운 주소의 미전송 메일은 취소한다(Q12 5절 메일 작업).
  • 미리보기는 최근 구간의 실제 건수다(Q12-01, TD-05). 판정 불가 건수는 엔진이 저비용으로 줄 때 따로 보인다(TD-04). 입력을 바꾸면 다시 계산한다(와이어프레임 표기).
  • 예상 동작 문구는 처음 충족 때 1회 발송, 지속 중 반복 없음, 해소 뒤 재발 때 새 메일 합의(Q12 1절)와 Q12-03의 해소 시간 계산을 옮겼다. 평가 주기 숫자는 7절에 없어 쓰지 않는다. 회복 메일은 첫 출시 밖이라 그리지 않고, 해소 때 메일이 없다는 사실만 적는다(3절, Q12 1절).
  • 저장 검색·로그 탐색과 조건을 복사하는 관계라는 안내를 조건 아래에 둔다(SD-30, TD-05).
  • 이름 길이 상한은 7절에 없어 N으로 쓴다(TD-01). 서비스 이름이 바뀌면 칩에 현재 이름을 보이고 대상은 그대로다(TD-18).
  • 알림 규칙 변경은 재인증 없이 감사 대상이다(TD-17). 비밀번호 칸이나 CM-07 창을 두지 않는다.
  • 켬/끔은 이 화면이 아니라 UI-06·UI-08에서 한다(5절 UI-06·UI-08 동작).
  • WQ-38 설계로 넘김: 새 규칙을 저장하면 켜진 상태로 시작하는지 꺼진 상태로 시작하는지 문서에 없다. 기본안: 켠 상태로 저장한다. 저장 전 미리보기와 예상 동작 문구로 바로 메일이 갈 수 있음을 알린다. 메일 설정이 없으면 꺼진 상태로 저장한다(TD-08).

  • WQ-42 설계로 넘김: 테스트 메일이 메일 서버 수락이 된 뒤에도 확인 안 됨 표시를 그대로 두는지, 사람이 도착을 확인했다고 표시하는 방법이 있는지 문서에 없다. 그림은 그대로 둔 모습이다. 기본안: 사람이 받았음을 누르면 확인됨으로 바꾼다. 자동으로 판정하지 않는다(WQ-82와 같음).

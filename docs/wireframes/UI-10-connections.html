  • 연결은 서비스별로 묶고, 연결마다 수집 대상(파일, 파일명 규칙, journald), 서버 표시명, 환경 태그, 관리 상태, 관측 상태, 마지막 보고 시각, 대기량을 보여 준다(5절 UI-10).
  • 관리 상태와 관측 상태는 CM-05 표시를 따로 쓰고 하나의 정상 표시로 합치지 않는다(4절 CM-05, 운영 명세 4절). 행 마크업은 CM-05 상태 4의 조합 예를 따랐다.
  • 서버 표시명과 환경 태그는 선택 입력이라 비어 있으면 미입력으로 쓴다(Q07-08, SD-12).
  • 대기량을 모르면 0으로 쓰지 않고 미확인으로, 관측이 오래된 연결의 값에는 마지막 보고 기준을 붙인다. 에이전트가 0으로 보고한 값만 0MB로 쓴다(1절, 운영 명세 4절).
  • journald 대상의 입력·표기 형태는 API 설계에서 정한다(5절 UI-11 2단계). 그림은 입력 종류만 적고 대상 자리를 비워 두었다.
  • 열기는 UI-12, 새 연결 등록은 UI-11을 연다. 연결을 다른 서비스로 옮기거나 연결 등록을 완전히 삭제하는 동작은 두지 않는다(3절).
  • 상단 메뉴의 조치 필요 3은 CM-01 상태 1 마크업을 그대로 쓴 예시 값이다. 어떤 상태를 셀지는 상태 4의 검토 항목을 따른다.
  • 서비스 묶음 머리에 이름 변경과 서비스 보관을, 목록 위에 사용 중·보관됨 전환과 상태 필터를 둔다(와이어프레임 표기).
  • 서비스·서버·경로는 합성 예시다. 같은 서버의 같은 로그가 두 번 나오지 않게 서비스마다 폴더를 나눴다(Q07-06).

상태 2. 연결이 하나도 없음

화면 본문. 상단 메뉴는 상태 1과 같고, 조치가 필요한 연결이 없어 수를 표시하지 않는다

수집 연결

새 연결 등록

아직 수집 연결이 없습니다.

연결을 등록하면 서비스와 수집 대상을 정하고 키와 설정을 받습니다.
받은 설정을 로그 서버의 에이전트에 적용하면 수집을 시작합니다.

새 연결 등록
  • 연결이 없으면 등록 안내와 새 연결 등록만 보여 준다(5절 UI-10). 등록은 UI-11의 7단계로 진행한다.
  • 설정은 사용자가 로그 서버에 적용하고 중앙은 원격으로 적용하지 않는다(5절 UI-11 7단계). 안내 문구도 그 순서로 썼다.
  • 보관된 연결도 없는 경우라 사용 중·보관됨 전환과 상태 필터를 숨겼다. 보관된 연결만 있으면 보관됨 전환을 남긴다(와이어프레임 표기).
  • 조치가 필요한 연결이 없으면 상단 메뉴에 수를 표시하지 않는다(CM-01 상태 1 주석).

  • 관측 불가가 10분 지속되면 운영 수신 주소로 묶어서 운영 메일 1통을 보낸다(Q12-06, 7절). 10분은 관측 불가로 판정한 뒤의 유예라 판정 기준 N과 별개다(Q12 기획안).
  • 같은 서버의 연결이 함께 끊긴 모습은 합성 예시다. 서버나 에이전트 단위로 묶어 보여 주는 표시는 두지 않았다.

취소이름 변경
  • 서비스 이름은 사람이 알아보는 별칭이다. 바꿔도 연결, 기존 로그와 원래 출처, 저장 검색·알림 규칙의 대상은 그대로이고 화면의 서비스 이름만 지금 이름으로 보인다(Q07-03, 5절 UI-10).
  • 이름을 바꿔도 로그 본문이나 저장 검색의 본문 검색어는 바꾸지 않는다(Q05·Q07·Q10 기획안 3절).
  • WQ-51 설계로 넘김: 이름 규칙(길이·쓸 수 있는 글자)과 같은 이름을 허용할지는 설계로 넘겼고(Q07-02), 이전 이름 표시도 후속 설계다(Q07-03). 이름이 겹칠 때의 화면은 그리지 않았다. 기본안: 이미 Q07-02 설계 인계다. 이름이 겹칠 때의 화면은 그 설계와 함께 그린다.
  • WQ-52 설계로 넘김: 5절 UI-10은 보관·재활성만 CM-07로 적었다. 이름 변경에 비밀번호를 다시 받을지, 감사 기록 장애 때 보류할지(Q10-12의 주요 설정 변경에 드는지) 문서에 없다. 그림은 CM-07 없이 확인 창만 그렸다. 기본안: 기존 합의 적용: 알림 규칙 변경과 같다(TD-17). 재인증 없이 감사 기록을 남기고 감사 장애 때 보류한다.
  • 창에서 새 이름을 받는다(와이어프레임 표기).

  • 감사 기록 장애 중에는 보관을 적용 전에 보류한다. 긴급 차단 예외(키 폐기·전체 세션 종료)에 들지 않는다(Q10-14, CM-07 상태 5·6).

  • 감사 기록 장애 중에는 재활성도 적용 전에 보류한다(Q10-14, CM-07 상태 5).

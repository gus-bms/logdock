CM-07 민감 작업 확인

키·등록·보관·로그 삭제·비밀번호처럼 영향이 큰 작업 전에 대상과 영향을 보여 주고 비밀번호를 다시 받는 확인 창이다. 에이전트에 닿는 작업은 실행 뒤 요청 접수, 중앙 확정, 에이전트 관측을 나눠 보여 준다. 알림 규칙 변경에는 쓰지 않는다.

  3. 에이전트 관측미확인 · 마지막 보고 09:31:07
  • 중앙 폐기 요청·확정과 오프라인 에이전트의 읽기·관측은 별개다. 중앙 확정만으로 서버의 읽기가 멈췄다고 표시하지 않는다(Q10-11, 4절 CM-07).

상태 5. 감사 기록 장애로 보류

수집 연결 상세(UI-12)에서 설정을 고친 예다.

보류감사 기록을 저장할 수 없어 설정 변경을 적용하지 않았습니다. 기존 설정이 그대로 쓰입니다. 이 요청은 저장하지 않으니 감사 기록이 복구된 뒤 다시 실행하세요. 감사 이력 보기닫기 ×
  1. 요청 접수완료 10:40:12
  2. 보류감사 기록 장애로 적용하지 않음
  • 감사 기록 장애 중에는 새 키 발급, 일반 등록·설정 변경, 웹 비밀번호 변경 같은 일반 민감 변경을 적용 전에 보류한다(Q10-14). 알림 규칙 변경도 보류하지만 재인증은 요구하지 않으므로 이 창을 쓰지 않는다(TD-17).
  • 감사 기록이 복구돼도 보류한 작업을 자동으로 적용하지 않고 요청도 남기지 않는다. 사용자가 복구 뒤 다시 실행한다(2026-11-05 Q10-14 후속 합의).
  • 보류 결과는 CM-08 토스트로 알리고, 진행 단계는 화면에 남긴다.

상태 6. 감사 기록 장애 중 긴급 키 폐기

감사 기록 장애 중입니다. 키 폐기는 차단 상태를 확정할 수 있으면 진행하고, 이 작업은 감사 이력에 공백으로 남습니다.

  1. 요청 접수완료 10:41:30
  2. 중앙 확정완료 10:41:31 · 감사 기록 공백
  3. 에이전트 관측대기
  • 키 폐기와 전체 세션 종료는 실제 차단 상태를 확정 저장할 수 있을 때 허용하고, 감사 공백과 실제 결과를 나눠 보여 준다. 차단 상태를 확정하지 못하면 완료로 표시하지 않는다(Q10-14, 운영 명세 5절).

상태 7. 쓰는 작업과 보여 줄 영향

작업화면확인 창에 보여 줄 영향진행 단계
등록 확정과 키 발급UI-11 5단계서비스·대상·형식 요약. 키 원문은 다음 단계에서 한 번만 보여 준다.UI-11 7단계 증거 표시
키 교체UI-12새 키를 한 번만 보여 준다. 적용하고 정상 수신을 확인한 뒤 기존 키를 직접 폐기한다. 교체 중 키는 2개이고 자동 종료 기한은 없다.—
키 폐기UI-12중앙 폐기를 먼저 하고 로컬 읽기 중지는 서버 운영자가 한다. 대기 로그는 보존된다.요청 접수 · 중앙 확정 · 에이전트 관측
설정 변경UI-12새 설정을 다시 복사해 에이전트에 적용해야 하고 적용 중 수집이 잠시 멈춘다. 다른 서버나 다른 로그는 새 연결로 등록한다.—
보관UI-10(서비스), UI-12(연결)중앙 새 수신을 막고 과거 로그는 보관 기간까지 검색된다. 서비스는 하위 연결의 수신 차단, 남은 대기, 이 서비스를 쓰는 저장 검색과 알림 규칙을 보여 준다.요청 접수 · 중앙 확정 · 에이전트 관측
재활성UI-10(서비스), UI-12(연결)같은 등록으로 돌아가고 옛 키는 살아나지 않는다.—
구간 로그 삭제UI-12되돌릴 수 없다. 에이전트 대기와 원본 파일은 지우지 않는다. 실제 공간 회수까지 시간이 걸린다. 같은 구간이 다시 전송돼도 저장하지 않는다.—
비밀번호 변경UI-16바꾸면 현재 세션을 포함한 모든 세션이 끝나고 다시 로그인한다.—
  • 쓰는 작업은 키 발급·교체·폐기, 등록·설정 변경, 보관·재활성, 구간 로그 삭제, 비밀번호 변경이다. 알림 규칙 변경에는 쓰지 않는다(4절 CM-07, TD-17).
  • 영향 문구의 출처는 UI-10·UI-11·UI-12·UI-16 절이다. 진행 단계 —는 문서가 단계 표시를 요구하지 않은 작업이다.
  • 모든 작업은 감사 대상이다(Q10-12). 구간 로그 삭제는 Q13-03을 따른다.

취소 다음
  • 기존 서비스를 고르거나 새 서비스 이름을 입력한다. 서비스는 LogDock의 로그 분류 이름이고 수신한 로그로 자동으로 만들지 않는다(Q07-01).
  • 5단계에서 확정하기 전에는 서비스·연결·키를 만들지 않는다. 취소하면 UI-10으로 돌아간다(5절 UI-11).
  • 서비스 이름은 별칭이며 연결이나 인증을 판정하는 근거로 쓰지 않는다(Q07-02).
  • WQ-57 설계로 넘김: 새 서비스 이름의 규칙과 같은 이름 허용 여부는 설계로 넘겼다(Q07-02). 보관된 서비스를 이 목록에서 고를 수 있는지도 문서에 없다(UI-10 상태 9와 같은 항목). 그림의 목록에는 사용 중인 서비스만 넣었다. 기본안: WQ-51·WQ-54와 같다. 보관된 서비스는 목록에 넣지 않는다(그림대로).
  • 단계 표시줄을 화면 위에 두고 단계마다 취소·이전·다음을 둔다(와이어프레임 표기).

journald 대상 입력

컨테이너 로그는 journald로 읽습니다.

journald 접근과 대상 확인은 설정을 적용할 때 로그 서버의 에이전트가 합니다.

취소 이전 다음
  • 경로는 로그 서버 기준으로 파일 하나(app.log)나 파일명 규칙(app-*.log)을 넣는다. 지정한 폴더 안에서만 찾고 하위 폴더는 따로 등록한다(Q02-06, Q02·Q16 인계서 3절).
  • journald 대상을 고를 수 있고 컨테이너 로그는 journald로 읽는다(2026-11-03 컨테이너 로그 합의). journald 대상의 입력 형태는 API 설계에서 정하므로 빈 자리로 그렸다(5절 UI-11 2단계).
  • 파일 존재·읽기 권한·journald 접근은 로그 서버의 에이전트가 확인한다. 중앙은 원격으로 파일을 탐색하거나 권한을 바꾸지 않는다(운영 명세 2절). 그래서 이 단계에서 파일 검사 결과를 보여 주지 않는다.
  • 파일명 규칙의 문법·경로 해석과 오류 표시는 설계 과제다(수집 명세 Q02-06).
  • 입력 종류를 세그먼트로 고른다(와이어프레임 표기).

추출 규칙을 해석할 수 없습니다. 고치거나 비우세요.

취소 이전 다음
  • 형식은 일반 텍스트, JSON, 여러 줄 중 고르고, 여러 줄은 새 이벤트 시작 규칙이 필요하다. 인코딩은 UTF-8이다(Q02-03, Q02-04).
  • 로그 시간대는 선택 입력이다. 비우면 에이전트 서버 시간대로 해석해 시간대 추정을 표시한다(Q08-06, CM-06).
  • 추출 규칙은 내장 형식이 맞지 않을 때만 넣는 선택 입력이며 이후 로그에만 적용된다. 잘못된 규칙은 등록 때 오류로 알린다(Q08-07).
  • 시작 규칙과 추출 규칙의 문법·실행 위치는 후속 설계라 입력 칸만 그리고 예시 문법을 넣지 않았다(Q08-07, 수집 명세 D02). 시작 규칙 도움말의 예는 수집 명세 D02의 설명을 옮긴 것이다.
  • 등록 뒤 경계 규칙이 맞지 않아 이벤트 경계를 판별할 수 없으면 에이전트가 그 파일을 설정 확인 필요로 대기시킨다(D02).

이전확정(기존 연결 있음)

  • WQ-58 설계로 넘김: 등록 단계에서는 실제 서버를 식별할 근거가 없을 수 있다(서버 표시명은 판정 근거가 아님, Q07-08). 같은 서버·같은 로그를 언제 확인하는지(이 단계 또는 에이전트 적용 때)는 설계로 넘겼고(Q07-06), 적용 때 확인되면 7단계와 UI-12에서 어떻게 보일지와 확실하지 않은 겹침을 경고할지는 문서에 없다. 기본안: Q07-06 설계 인계다. 기본안은 확실한 겹침(같은 에이전트·같은 대상)만 막고 불확실한 겹침은 경고하며, 적용 때 확인되면 7단계와 UI-12에 보인다.
  • 확정 전에는 키를 발급하지 않는다(5절 UI-11).

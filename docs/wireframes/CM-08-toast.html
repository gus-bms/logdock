CM-08 토스트 알림

방금 한 작업의 결과(성공·실패·보류·안내)를 화면 오른쪽 위에 겹쳐 띄우는 알림이다. 모든 화면이 작업 결과를 이 방식 하나로 알리고 화면 안에 결과 상자를 넣지 않는다. 계속 이어지는 상태와 입력 칸 오류는 토스트로 띄우지 않는다(상태 6).

근거: 2026-11-05 사용자 요청(화면 안 알림을 토스트로 통일) · 기준: 화면 흐름 명세 1·4·7절, 조사 명세 8절

  1. 성공
  2. 실패
  3. 보류
  4. 안내
  5. 여러 개가 겹침

상태 1. 성공

화면 오른쪽 위, 상단 메뉴와 전역 배너 바로 아래
성공저장 검색 주문·결제 timeout 조사를 저장했습니다.닫기 ×
작업하던 화면은 그대로 남는다
  • 작업이 끝났음을 알린다. N초 뒤 저절로 사라지고 그 전에 닫기로 닫을 수 있다. 표시 시간은 정하지 않아 N으로 썼다(7절).
  • 화면 오른쪽 위, 상단 메뉴와 전역 배너(CM-01) 아래에 겹쳐 띄운다. 화면 내용을 밀어내지 않고 입력 칸의 초점을 빼앗지 않는다(조사 명세 8절).
  • 종류는 성공·실패·보류·안내 글자로 쓰고 색만으로 구분하지 않는다(1절 상태 표시). 화면 읽기 프로그램은 성공·안내를 하던 일을 끊지 않고 읽고, 실패·보류는 바로 읽는다(와이어프레임 표기).

상태 2. 실패

메일 상태(UI-14)에서 테스트 발송을 누른 뒤
실패테스트 메일을 보내지 못했습니다. 사유: 메일 서버 연결 시간 초과. 메일 서버 연결 상태와 서버 설정을 확인하세요.닫기 ×
ops@example.com테스트 발송
  • 작업을 하지 못했음을 알린다. 무엇을 하지 않았는지, 사유, 다음에 할 일을 함께 쓴다. 사용자가 닫을 때까지 남는다(와이어프레임 표기).
  • 입력한 내용은 화면에 그대로 둬서 고친 뒤 다시 할 수 있게 한다. 입력 칸 하나가 틀렸으면 토스트가 아니라 그 칸 옆에 오류를 보인다(상태 6).

상태 3. 보류

감사 기록 장애 중 수집 연결 설정을 고친 뒤(CM-07 상태 5)
보류감사 기록을 저장할 수 없어 설정 변경을 적용하지 않았습니다. 기존 설정이 그대로 쓰입니다. 이 요청은 저장하지 않으니 감사 기록이 복구된 뒤 다시 실행하세요. 감사 이력 보기닫기 ×
작업하던 화면은 그대로 남는다
  • 감사 기록 장애로 작업을 적용하지 않았음을 알린다(Q10-14). 보류한 작업은 복구돼도 자동으로 적용하지 않으므로 다시 실행하라고 쓴다(2026-11-05 Q10-14 후속 합의). 사용자가 닫을 때까지 남는다.
  • 장애가 이어지는 동안의 상태는 CM-01 전역 배너가 보인다. 토스트는 방금 누른 작업의 결과만 알린다.
  • 바로 가는 링크는 하나까지 둔다(와이어프레임 표기).

토스트로 띄우지 않는 것

표시두는 곳이유
입력 칸 오류그 칸 옆(CM-03 상태 5, UI-16 상태 2)토스트가 사라지면 어느 칸을 고칠지 알 수 없다
계속 이어지는 상태: 검색 결과 상태와 0건 사유, 수집 문제, 감시 불가, 측정 불가, 개수 상한 도달그 화면 안(CM-04, UI-08 상태 4, UI-13 상태 4, UI-06 상태 5)상태가 이어지는 동안 보여야 한다
설치 전체의 장애와 경고CM-01 전역 배너어느 화면에 있든 계속 보여야 한다
실행 전 대상과 영향 확인확인 창(CM-07)사용자가 고르기 전에 읽어야 한다
키 원문발급·교체 화면(UI-11 상태 7, UI-12 상태 5)한 번만 보여 주므로 사라지면 안 된다(Q10-08)
화면 설명(집계 기준, 복사 관계, 시간상 근접 이벤트 등)해당 칸 옆작업 결과가 아니라 화면을 읽는 데 필요한 설명이다
  • 사용자는 화면 요소 안에 알림을 넣지 말고 토스트로 통일하길 요청했다(2026-11-05). 적용 범위는 방금 한 작업의 결과로 정했다. 위 표의 표시는 사라지면 고칠 곳이나 이어지는 문제를 놓치므로 화면에 둔다(결정 기록 2026-11-05).
  • 위 표에 없는 저장·삭제·이름 변경도 결과를 알릴 때는 토스트를 쓴다(와이어프레임 표기).

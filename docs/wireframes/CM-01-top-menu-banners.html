CM-01 상단 메뉴와 전역 배너

모든 화면 맨 위에 두는 메뉴와 전역 배너다. 다른 화면 파일은 상태 1의 상단 메뉴 마크업을 그대로 가져다 쓰고, 현재 화면의 메뉴에 is-current를 붙인다.

근거: Q12 6절 Q10-14 Q13-01 운영 명세 4절 · 기준: 화면 흐름 명세 1·2·4절

화면 본문(각 화면 파일에서 그린다)
  • 메뉴는 2절 순서를 따른다: 로그 탐색(UI-02), 저장 검색(UI-05), 알림(UI-06), 수집 연결(UI-10), 시스템(UI-13~UI-15), 계정(UI-16).
  • 현재 화면은 굵은 글자와 밑줄로 표시한다. 색으로만 구분하지 않는다(1절).
  • 수집 연결 옆에 조치가 필요한 연결 수를 표시하고, 누르면 UI-10으로 간다(4절 CM-01). 조치가 필요한 연결이 없으면 숫자를 표시하지 않는다(와이어프레임 표기).
  • WQ-01 설계로 넘김: 어떤 관리·관측 상태를 조치 필요로 셀지 문서에 없다. 수집 연결 묶음(UI-10의 조치가 필요한 연결 상태)과 같은 기준을 써야 한다. 기본안: UI-10 상태 4의 후보 표에 있는 상태를 센다. 얼마나 이어지면 셀지는 관측 오래됨 기준(D16)과 함께 정한다. CM-01 메뉴 수와 UI-10이 같은 계산을 쓴다.
  • 로그아웃과 비밀번호 변경은 계정(UI-16)에서 한다.

  • 메일 최종 실패를 확인 처리하는 방식은 API 설계에서 정한다(4절 CM-01). 그래서 확인 버튼을 그리지 않았다.
  • WQ-02 설계로 넘김: 메일 최종 실패 배너가 어느 화면으로 가는지 문서에 없다. 규칙마다 마지막 전달 결과를 보여 주는 UI-06으로 그렸다. 기본안: 최종 실패 미확인 필터를 건 UI-06으로 간다. 확인 처리는 사건 단위로 UI-09에서 하고 API는 설계에서 정한다(WQ-31·32·37·49와 한 묶음).
  • WQ-03 화면 확정(2026-11-05 디자인 시스템 11절): 지나간 일을 알리는 배너(감사 기록 공백, 조기 삭제 발생)를 언제 내릴지 정했다. API 계약 초안 4.4절의 `확인`(ack)과 같다. 감사 기록 공백·조기 삭제 발생 배너는 확인을 누를 때까지 보이고 같은 일이 다시 생기면 다시 보인다. 기록은 UI-13·UI-15에 남는다.
  • 감사 기록 장애 중 보류되는 작업은 Q10-14의 일반 민감 변경과 TD-17의 알림 규칙 변경이다. 긴급 키 폐기와 전체 세션 종료는 차단 상태를 확정할 수 있으면 진행한다(CM-07 상태 6).
  • 디스크 경고 기준은 정하지 않았다(7절). 조회 가능 시작일은 보관·조기 삭제 기준인 수신 시각으로 쓴다(SD-33).
  • 시각은 배포 설정의 표시 시간대로 쓰고 시간대를 함께 적는다(1절, SD-07).

  • WQ-46 문서로 정리: 대상 연결이 모두 보관돼 대상이 0개가 되면 경고한다(TD-18, Q12 8절 F-18). 이 경고를 UI-06·UI-08 중 어디에 어떻게 그릴지 화면 흐름 명세에 없다. 정리: UI-08 상태 7과 UI-06 감시 품질의 대상 없음으로 보인다(TD-18, F-18). 명세 UI-06·UI-08에 더했다.

  • 평가 상태는 정상, 지속, 해소 대기다(Q12 5절). 지속은 오류가 계속된다는 뜻이라는 점을 상태 옆 문구에서 숨기지 않는다(Q12 6절).
  • 처음 충족하면 메일을 한 번 보내고 지속 중에는 반복하지 않으며, 해소 확인 뒤 재발하면 새 메일을 보낸다(Q12 1절).
  • 지속 칸의 지금 구간 건수는 마지막 성공 평가의 건수다. 이 줄은 해소 대기 진행 칸을 비워 두지 않으려고 둔 와이어프레임 표기다.

상태 3. 사건 없음

사건 이력

사건이 없습니다.

이 규칙이 아직 조건을 넘은 적이 없거나, 지난 사건이 알림 이력 보관 기간(로그 보관 기간과 같은 6개월)을 지났습니다.

  • 사건 이력은 로그 보관 기간과 같이 보관하므로, 오래된 사건은 기간이 지나면 목록에서 사라진다(Q12-14, 7절).
  • 사건이 없을 때도 위쪽의 평가 상태·감시 품질·해소 대기 진행·미평가 구간·일부 미관측 대상은 그대로 보인다.

해소 대기 진행

9분 / 15분 임계(20건) 아래 유지

평가하지 못한 회차는 세지 않고, 이미 쌓은 시간은 지우지 않습니다.

  • 평가 쿼리 실패·시간 초과는 평가 불가로 처리하고 상태를 유지한다. 평가 자체가 실패한 회차는 해소 계산에 넣지 않는다(Q12-05, Q12 8절 F-06, Q12 5절 상태 표).
  • 회차가 주기 안에 안 끝나면 다음 회차를 건너뛰고 기록한다. 재시작 뒤 놓친 회차를 다시 평가하지 않고, 미평가 구간을 이력에 표시한다(TD-12).
  • 쿼리가 일부만 끝나도 그 건수가 임계 이상이면 충족으로 판정하고, 임계 미만의 부분 결과는 평가 불가로 남긴다(TD-13).
  • 평가 실패가 10분 지속되면 묶어서 운영 메일 1통을 보낸다(Q12-06, 7절). 전체 평가가 멈추면 CM-01 알림 평가 중단 배너가 뜬다(UI-06 상태 3).
  • 사유 이름(평가 시간 초과, 회차 건너뜀, 평가 쿼리 실패)은 Q12 8절 F-06·F-07의 설명을 옮긴 것이다. 사유 코드는 API 설계에서 정한다(9절).
  • WQ-47 문서로 정리: 미평가 구간을 얼마 동안 보여 줄지 문서에 없다. 사건 이력처럼 로그 보관 기간과 같은지 정해야 한다. 정리: 알림 이력과 같이 로그 보관 기간 동안 보관한다(Q12 합의의 알림 이력 보관).

상태 7. 대상 없음

정상 감시 품질 대상 없음 마지막 성공 평가 2026-11-05 10:40:00 (UTC+09:00)

이 규칙이 셀 연결이 없습니다. 대상 연결이 모두 보관돼 건수를 0으로 평가하고 있어 오류가 나도 알림이 오지 않습니다. 조건을 고치거나 연결을 재활성하세요. 규칙 수정 · 수집 연결 보기

  • 보관된 연결은 규칙 대상에서 빠지고, 대상이 0개가 되면 경고하며 건수 0으로 평가한다(TD-18, Q12 8절 F-18). 수집 대상 조건(Q08-09)으로 보관된 연결만 고른 규칙도 같다.
  • UI-06의 감시 품질 칸에도 대상 없음을 보인다. 대상이 다시 생길 때까지 이어지는 상태라 토스트가 아니라 화면에 둔다(CM-08 상태 6).

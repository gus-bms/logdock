새 저장 검색은 로그 탐색에서 조건을 고른 뒤 조건 저장으로 추가합니다. 오래 쓰지 않은 저장 검색도 자동으로 지우지 않습니다. 고정 범위는 시작 포함·끝 제외입니다.

  • 공용 계정의 목록 하나만 둔다. 개인·팀 목록 구분은 없고 같은 계정으로 로그인한 사람이 함께 쓴다(Q11, 조사 명세 6절, 1절).
  • 열은 5절 UI-05의 요소(이름, 조건 요약, 시간 방식, 최근 수정 시각, 실행 전 경고)다. 조건 요약은 CM-03 요약 문구 형식을 쓴다. 시간 방식에는 시간 기준(발생·수신)도 함께 보인다. 저장 검색에는 시간 기준도 저장한다(Q08-04, CM-02 상태 5).
  • 상대 범위의 길이는 CM-02 마크업을 그대로 써서 N으로 둔다. 고정 범위의 날짜·시각과 저장 개수 4개는 합성 예시다. 저장 개수 상한은 정하지 않았다(7절).
  • 실행은 UI-02를 열고 저장한 조건·시간 방식으로 바로 실행한다. 조건은 URL에 평문으로 넣지 않는다(1절, SD-35). UI-02에서 조건을 고치는 것만으로 저장 검색이 바뀌지는 않는다(5절 UI-02 복사 관계). 고친 조건을 원래 저장 검색에 덮어 저장할 수 있는지는 UI-02 상태 12의 검토 항목이다.
  • 수정은 상태 4, 삭제는 상태 6이다. 오래 쓰지 않아도 자동으로 지우지 않는다(Q11-03).
  • 이 화면에는 새로 만드는 버튼이 없다. 5절 UI-05 동작에 생성이 없고, 추가는 UI-02 조건 저장으로 한다(5절 UI-02). 같은 목록에서 이름은 겹칠 수 없다(Q11 정리의 설계 기본값).
  • 저장 검색과 알림 규칙은 조건을 복사하는 관계라 한쪽을 고쳐도 다른 쪽은 바뀌지 않는다. 이 안내를 목록 위에 둔다(SD-30, TD-05).
  • 서비스 이름을 바꾸면 조건 요약에 현재 이름을 보여 주고 조건의 대상은 그대로다(5절 UI-10). 보관된 서비스는 CM-03 값 목록처럼 보관됨을 붙인다.
  • 목록은 최근 수정순으로 그렸다(와이어프레임 표기).

상태 7. 개수 상한 도달

저장 검색

상한 도달 공용 목록 · N개 저장 · 최대 N개

저장 검색이 상한(N개)에 닿아 로그 탐색에서 새 조건을 저장할 수 없습니다. 쓰지 않는 저장 검색을 지우면 다시 저장할 수 있습니다. 오래 쓰지 않은 저장 검색도 자동으로 지우지 않습니다.

저장 검색 목록(상태 1과 같음). 실행·수정·삭제는 그대로 쓸 수 있다.
  • 자동 삭제 없이, 개수 상한에 닿으면 저장을 막고 안내한다(Q11-03). 상한 값은 측정 뒤 정하므로 N으로 쓴다(7절). 상한에 닿았을 때는 현재 개수도 N이 되어 그렇게 쓴다.
  • 상한은 저장 개수에 걸리므로 실행·수정·삭제는 막지 않는다.
  • 실제로 저장을 막는 곳은 UI-02의 조건 저장이다(5절 UI-02). 그 창은 검색·조사 묶음이 UI-02 상태 14로 그렸고, 이 상태의 안내와 뜻이 같다.

  • UI-02 위에 패널로 열려 목록 위치를 잃지 않고, 뒤 목록에서 고른 행을 강조한다(5절 UI-03). 패널을 오른쪽에 두고 목록 일부를 덮는 배치와 너비는 와이어프레임 표기다. UI-04에서 행을 눌러도 같은 패널이 UI-04 위에 열린다.
  • 출처(서비스·서버·환경·수집 연결)는 수집 연결 등록 정보에서 온다. 본문 안의 service·host 값은 출처를 바꾸지 않는다(조사 명세 3절, SD-11). 수집 연결을 누르면 UI-12로 간다.
  • 시각 영역은 CM-06 상태 3이다. 발생·관측·수신 시각과 시각 출처를 함께 보여 준다(SD-34). 이 로그는 품질 표시가 없고, 표시가 붙은 모양은 상태 3이다.
  • 레벨은 원본 값과 정규화 값을 함께 보인다. 숫자 50은 Pino 계열 숫자로 읽어 ERROR가 됐다(SD-09, SD-10).
  • 본문은 중앙에 보관된 앱 출력 본문이며 글자로만 그린다. 실행 가능한 HTML로 해석하지 않고, 본문 속 링크를 누를 수 있게 만들지 않는다(조사 명세 1·2절, SD-36). 그림의 본문은 합성 예시다.
  • 필드는 점 경로 이름과 값을 글자로만 보여 준다(SD-19, SD-36). 필드를 눌러 조건에 더하는 동작은 상태 4, 복사는 상태 5다. 필드 행마다 조건에 추가를 둔 것은 와이어프레임 표기다.
  • 주변 로그는 UI-04를 연다. 요청 ID로 여러 서비스를 묶어 보는 전환은 첫 출시 밖이라 두지 않는다(3절, 조사 명세 4절). 요청 ID는 UI-02의 일반 검색으로 찾는다(SD-23).
  • 이벤트를 열 때와 더 불러올 때 서버가 현재 허용 범위를 다시 검사한다(조사 명세 4절). 패널은 키보드로 열고 닫을 수 있어야 하며 쓰는 키는 설계에서 정한다(조사 명세 8절).
  • WQ-18 설계로 넘김: stack trace로 따로 보여 줄 값을 무엇으로 정할지(JSON의 특정 필드, 여러 줄 이벤트의 이어진 줄) 문서에 없다. 그림은 err.stack 필드 값을 줄 단위로 보여 줬다. 기본안: 내장 필드 이름 목록(예: err.stack, stack)에 맞는 필드 값과 여러 줄 이벤트의 이어진 줄을 보인다. 목록은 Q08-07 내장 패턴과 함께 정한다.
  • WQ-19 설계로 넘김: UI-04에서 연 상세의 주변 로그가 그 행을 가운데에 두고 UI-04를 다시 여는지 문서에 없다. 기본안: 그 행을 가운데에 두고 UI-04를 새로 연다. 원래 검색으로 돌아가는 길은 유지한다.

색 코드는 화면에 그릴 때만 처리했습니다. 저장된 본문에는 그대로 있습니다.
  • 긴 행 접기·줄바꿈·JSON 펼침은 표시 동작이며 저장된 본문을 바꾸지 않는다(조사 명세 2절). 화면의 표시 생략과 D03의 이벤트 전체 거부를 구분하고 저장 본문이 잘렸다고 전제하지 않는다(조사 명세 8절). 검색은 저장 본문 전체를 비교한다(SD-14).
  • 긴 본문 표시량은 정하지 않았다(7절). 접기·줄바꿈·JSON 펼침 버튼의 모양과 위치는 와이어프레임 표기다.
  • ANSI 색 코드는 저장 본문에 그대로 두고 표시할 때만 처리한다. 단어 중간에 색 코드가 끼면 검색에서 찾지 못할 수 있다(SD-18). 그림은 색 없이 글자만 남긴 모양이다. 회색조라 색은 그리지 않는다(8절).

  • 상세에는 CM-06 표시를 글자로 붙이고 발생·관측·수신 시각과 시각 출처를 함께 보여 준다(4절 CM-06, SD-34). 발생 시각을 관측 시각으로 바꿔 쓰지 않고 미확인으로 둔다(SD-01).
  • 해석 실패 로그는 필드 조건이 있는 검색에서는 판정 불가로 빠지므로, 본문·출처 조건만 쓴 검색이나 UI-02의 판정 불가 보기에서 연다(SD-22). 필드가 없어 필드 복사는 쓸 수 없다고 적는다(와이어프레임 표기).
  • 시각 의심, 시간대 추정, 필드 일부 생략이 붙은 상세는 CM-06 상태 5·6·7과 같다.

  • 필드 값 비교는 화면에 보이는 값 기준이고 글자는 대소문자까지 같아야 한다(SD-20).
  • WQ-20 설계로 넘김: 필드를 눌렀을 때 어떤 연산으로 더할지(같음만인지, 다름·있음·없음도 고르게 할지) 문서에 없다. 그림은 같음으로 더했다. 기본안: 같음으로 더하고 연산은 조건 편집기에서 바꾼다(그림대로).

  • 세션이 끝난 뒤 행을 누르면 본문과 필드를 보여 주지 않고 CM-04 상태 9의 만료·접근 제한 문구로 다시 로그인을 안내한다(5절 UI-03). 다시 로그인은 UI-01 상태 4로 간다.
  • 세션은 비활동 1시간 또는 로그인 후 최대 24시간에 끝난다(Q10-06). 다시 로그인한 뒤 검색 조건까지 되살리는지는 UI-02 상태 9의 검토 항목과 같다.
  • WQ-23 설계로 넘김: 패널을 열어 둔 채 세션이 끝나면 이미 보이던 본문과 필드를 화면에서 지울지 문서에 없다. 기본안: 세션이 끝나면 보이던 본문과 필드를 화면에서 지우고 로그인 안내만 둔다.

저장
  • 요소는 5절 UI-14를 따른다: 메일 서버 연결 상태, 마지막 성공 전송, 테스트 발송, 운영 수신 주소 목록(최대 10개, 형식 검사, 확인 안 됨 표시, 테스트 메일).
  • 메일 서버 주소·계정·발신 주소·비밀번호는 서버 운영자가 서버 설정에 넣고, 웹에서는 연결 상태 확인과 테스트 발송만 한다. 비밀번호를 바꾸려면 서버 접속과 재시작이 필요하다(Q12-08, 3절). 비밀 값은 화면·로그·진단에 쓰지 않는다(TD-20).
  • 메일 서버와 계정은 이 설치의 서버 설정값이고 코어에 고정하지 않는다. 화면에 특정 메일 제공자 이름을 쓰지 않는다(Q12-15, TD-08).
  • 운영 수신 주소는 웹에서 관리하고 Q12-12 규칙(최대 10개, 형식 검사, 확인 안 됨, 테스트 메일)을 따른다(TD-21). 수집 끊김·알림 평가 실패가 10분 지속되면 묶어서 1통, 연결별로 지속 중 1회이고 회복 메일은 없다(Q12-06, 7절). 디스크 경고 기준은 정하지 않았다(7절).
  • 운영 수신 주소 변경은 CM-07 사용 목록에 없어 비밀번호를 다시 묻지 않는다(4절 CM-07).
  • WQ-77 설계로 넘김: 메일 서버 연결 상태의 정상 이름이 문서에 없다(연결 오류만 있다). 연결됨으로 그렸다. 연결 상태를 실제 발송 결과로 판정하는지 따로 확인하는지도 문서에 없어, 판정 근거가 없을 때 미확인을 쓸지(1절) 함께 정해야 한다. 기본안: 마지막 발송 시도 결과로 연결됨·연결 오류를 쓰고 시도가 없으면 미확인이다.
  • WQ-78 설계로 넘김: 테스트 발송을 받을 주소를 직접 넣는지, 운영 수신 주소로 보내는지 문서에 없다. 받을 주소를 넣는 칸으로 그렸다. 기본안: 주소를 직접 넣는다(그림대로). 운영 수신 주소 표에서는 행마다 보낸다.
  • WQ-79 설계로 넘김: 메일 서버 주소나 발신 주소를 읽기 전용으로 보여 줄지 문서에 없다. 5절 요소에 없어 그리지 않았다. 기본안: 비밀이 아닌 서버 주소·포트·발신 주소는 읽기 전용으로 보인다. 비밀번호는 보이지 않는다.
  • WQ-80 문서로 정리: 평문 사내 릴레이를 서버 설정에서 허용하면 화면에 경고한다(TD-08). 또 메일 설정이 없으면 규칙을 켤 수 없다(TD-08). 두 표시가 화면 흐름 명세 UI-14에 없다. 정리: 상태 7·8에 그렸고 명세 UI-14에 더했다(TD-08).
  • WQ-81 설계로 넘김: 운영 수신 주소 변경이 감사 대상인지, 감사 기록 장애 중 보류되는지 문서에 없다. 기본안: 기존 합의 적용: 알림 수신자 변경과 같다(TD-17). 감사 기록을 남기고 감사 장애 때 보류한다.

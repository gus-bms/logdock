# Q05·Q07·Q10 공식 자료 조사

확인일: 2026-11-01. 대상은 키 변경과 미전송 데이터(Q05), 서비스·수집원 수명(Q07), 인증·권한·키·감사(Q10)다. [기획안과 전체 선택표](../planning/q05-q07-q10-plan-v0.1.md)의 근거이며, 정책 채택·기술 선정·보안 적합성·실제 동작의 검증 결과가 아니다.

## 1 자료와 적용 범위

모든 자료는 공식 표준·프로젝트·보안 지침이다. 확인 당시 공개 문서를 읽었으며 후보 프로그램을 설치하거나 특정 버전의 지원을 시험하지 않았다. 아래 절 이름은 자료에서 확인한 범위다. 가격·유료 edition을 비교하거나 특정 공급자의 도입을 추천하는 조사가 아니다.

## 2 조사에서 도출한 판단

아래는 자료의 문장을 그대로 제품 규칙으로 옮긴 것이 아니라 LogDock의 기존 합의와 대조한 해석이다.

- **키 교체와 출처 보존:** 비밀 수명 관리(S02)와 요청별 권한 검사(S01)를 결합하면 새 키가 존재한다는 사실만으로 재개해서는 안 된다. 원래 등록에 대한 현재 권한을 확인하고 실제 전송에서도 검사하는 설계가 필요하다. 키 형식·인증 라이브러리는 아직 선택하지 않았다.
- **폐기와 완료 응답:** 오류 의미(S03)와 폐기 전파의 한계(S04)는 폐기 요청·중앙 효력 확정·agent 실제 관측을 구분하는 근거다. Q10-11에서 효력 전 유효하게 저장 완료한 로그/늦은 완료 응답 인정과 미완료 건의 폐기된 키로 완료 금지를 합의했다. 원래 연결의 유효 키/동일 식별로 대기를 재전송하며 실제 인증 상태/내구 기록·부분 응답·재시작/실패·효력/지연의 실현과 검증은 별도다. 이를 RFC 자체의 차단 시간 보장으로 해석하지 않는다.
- **이름과 출처 식별:** S05/S06은 서비스·실행·설명 정보의 구분 사례다. LogDock의 이름 유일성이나 보관 정책을 정하는 표준은 아니다. 이름 규칙은 Q07-02 설계 인계, 이름 변경/현재 별칭 표시와 보관/재활성은 Q07-03/07의 사용자 합의를 따르며 세부 경계는 기획안을 기준으로 한다.
- **공용 로그인과 SSO:** S11은 IdP의 개인 subject를 무시해도 개인 로그인이 공용 자격 하나와 같아지는 것은 아니라는 검토 근거다. 기존 공용 1계정 합의를 바꾸는 개인 로그인·역할 기능을 SSO 편의라는 이유로 추가하지 않는다.
- **수치의 근거:** 비밀번호 요건은 S07을 참고한 보안 설계 권고다. 키 90일 자동 만료안과 교체 중 24시간/7일 자동 종료는 초기 채택하지 않은 비교안이다. Q10-09/10에서 자동 기한 없이 새 키 수동 적용/수신 확인 후 기존 키 직접 폐기를 합의했다. 감사 90일은 사용자 채택 목표이며 강제 디스크 예산 우선/조기 정리로 실제 보관이 더 짧아질 수 있다. 표준 요구/실측 또는 최소 90일 보장으로 쓰지 않는다. 세션 비활동 1시간/최대 24시간은 Q10-06 사용자 채택 정책으로 AAL2 적합성이나 구현/실측 결과를 뜻하지 않는다.
- **수집 키 만료 후속 확인(2026-11-01):** S02의 2.7.2/2.7.4를 재확인했다. 키의 용도/보호 대상에 맞는 수명과 가능한 경우 제한된 만료를 권고하며 LogDock의 90일을 정하는 근거는 아니다. 90일 자동 만료와 만료 없는 명시 교체의 비교·수동 설정 적용/미교체 시 보류·포화/누락 영향은 Q10-09의 제품 선택이다. 웹 비밀번호의 정기 변경과 혼동하지 않는다. 사용자는 Q10-09에서 첫 출시 자동 만료 없음을 선택했다. 명시 교체/폐기와 현재 권한 확인을 유지하는 제품 선택이며 일반 지침을 준수한 보안 검증 결과로 취급하지 않는다.
- **감사 장애:** S10의 가용성 지침을 유지하면서 발급·권한 확대의 추적성을 우선할지, 모든 작업의 계속 실행을 우선할지 비교한다. 폐기·세션 무효화처럼 권한을 줄이는 작업까지 일괄 봉쇄하면 사고 대응이 막힌다. 인증 상태 쓰기까지 실패하면 차단 완료라고 표시할 수 없다.
- **대기 무기한 보존의 경계:** D01의 자동 폐기 금지와 유한한 디스크·원본 보존·중앙 중복 판정 기록을 함께 검토해야 한다(S14/S15). 대기가 남는다는 사실만으로 무기한 무손실·무중복을 보장할 수 없다. 판정 근거가 사라진 오래된 재전송은 D06에서 안전 보류/운영 해결 계약을 정해야 하며 임의 새 이벤트로 저장하면 안 된다. 2026-11-02 Q13-04 합의로 안전 보류 안은 대체했고, 판정 근거가 사라진 뒤 도착한 로그는 같은 식별로 저장한다.

## 3 남아 있는 증거와 입력

- 후속 답변으로 사용자가 계획한 웹의 사내망·VPN 전용과 자체 로그인 선호를 확인했고 초기 자체 공용 로그인 방향에 반영했다. 이어 웹/agent HTTPS 기본 사용과 MFA 후속을 합의했다. 실제 접근 통제/TLS 설정·런타임은 확인하지 않았다. ingest 네트워크, 기존 IdP 유무/공용 자격 정책, 인증서/사설 CA 배포, 로컬 복구 담당·키 교체 가능 주기는 미확인이다. 공용 MFA의 운영 조건은 후속 채택 때 확인하며 첫 출시 선행 입력으로 요구하지 않는다. 실제 이름·주소·키·운영 로그 없이 종류·제약만 받아도 된다.
- 특정 OIDC 제공자·MFA 방식·인증 라이브러리·수집기·저장 엔진·프로토콜의 버전/라이선스/호환성은 P17에서 선정할 때 당시 공식 자료로 확인한다. 이 조사가 기술 선정이나 공급자별 비용 검증을 대신하지 않는다.
- 등록 충돌 탐지, 키 폐기와 수신 확정의 순서, 원래 출처의 복원, 중복 판정 수명, 감사 실패 원자성은 문서 조사로 실행 가능성을 입증하지 못한다. [기획안의 검증 목록](../planning/q05-q07-q10-plan-v0.1.md#acceptance)에 남긴다.
- DB·운영 서버·비밀값에 접근하지 않았고 제품 코드·의존성·설정·배포를 변경하지 않았다. 정적 문서 확인과 공개 자료 열람만 수행했다.

2026-11-02 정책 반영: Q05-01에서 인증 오류 중 디스크/필수 상태가 정상이고 명시 중지가 없으면 로컬 대기 한도까지 새 로그를 읽는 안을 사용자가 채택했다. 포화/상태 실패 안전 정지·원래 등록/식별·명시 중지 우선은 유지한다. 이는 LogDock의 제품 선택이며 S14/S15 프로그램 채택/기본값이나 무손실·자원 검증 결과가 아니다. 자료 확인일은 2026-11-01이고 이번 날짜는 사용자 정책 합의일이다.
